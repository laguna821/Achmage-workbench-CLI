# 예약 작업과 실행 기록

예약은 기존 세션에서 이어서 실행하거나 같은 작업공간에 매번 새 대화를 만들 수 있습니다. 현재 세션에서 이어갈 때 진행 중인 응답·승인 대기는 그대로 두고 대기열에 요청을 넣습니다. 화면에 보이는 대화는 바꾸지 않습니다. 정기적인 상태 확인도 시간 간격 예약으로 만들며 기본으로 활성화하지 않습니다.

매일 예약은 저장한 시간대를 따릅니다. 한 번 예약과 종료 기한은 입력 화면의 현지 시각을 절대 시각으로 저장합니다. 일광절약시간 때문에 매일 지정 시각이 없는 날은 건너뛰고, 같은 시각이 두 번 오는 날에도 이미 지난 시각을 다시 예약하지 않습니다.

호스트가 꺼져 있었을 때는 기본적으로 지난 예약을 한 번 보냅니다. ‘1분 넘게 지난 예약 건너뛰기’를 고르면 늦은 요청은 전송하지 않고 기록만 남깁니다. 종료 기한과 최대 실행 횟수도 정할 수 있습니다. 횟수는 접수 시도 기준이며 결과를 잃었다고 자동으로 같은 요청을 다시 시작하지 않습니다.

예약 ID와 원래 예정 시각으로 고유 실행 ID를 만들고, 기존 로컬 SQLite의 transaction 안에서 접수 기록과 다음 예정 시각을 함께 저장합니다. 전송 후 응답을 잃거나 호스트가 재시작되면 ‘전달 결과 확인 필요’로 남습니다. 실행 기록의 **전달 상태 확인**은 같은 요청의 접수 결과를 조회합니다. **별도 새 요청 예약**은 사용자가 선택한 새 요청으로 접수합니다.

‘대화에 전달됨’은 AI 응답 완료를 뜻하지 않습니다. 실행 기록에서 해당 대화로 이동해 결과와 승인을 확인할 수 있습니다. UI가 없어도 백그라운드 호스트가 켜져 있으면 예약은 실행됩니다. 호스트 자체가 꺼져 있거나 기기가 잠든 동안 실행을 보장하지 않습니다.

변경 범위 확인은 기존 예약과 새 journal의 12개 동작으로 진행했습니다. SQLite 재시작 후 전송 결과 불명 상태의 중복 접수 방지, 겹친 tick, 기한·횟수·지난 예약, 시간대와 DST 경계를 포함합니다.
