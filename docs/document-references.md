# 문서를 요청에 붙이기

문서 옆 채팅과 일반 대화창의 `@`/문서 추가 메뉴는 열린 문서와 저장하지 않은 편집을 표시한다. 기본 선택은 **보낼 때 저장**이다. 같은 창에 열린 편집기의 저장을 기다린 뒤 문서 ID·판·SHA-256을 확정하며, 저장 실패나 남은 미저장 편집이 있으면 요청을 보내지 않는다. 다른 창이나 프로젝트 노트의 수동 편집은 해당 편집기에서 먼저 저장한다.

**저장된 판만**은 미저장 편집을 제외하고 현재 저장된 판을 명시적으로 고정한다. 칩에는 판 번호와 제외 사실을 표시한다. 선택 후 파일이 바뀌어도 이 참조는 고정된 판을 사용한다. **최신으로**를 누르면 다시 보내기 전 저장 확인을 따른다. 참조를 빼거나 요청이 성공하면 선택을 지운다.

참조 확인 API는 `POST /api/document-references`다. 입력은 문서 ID·요청 종류와 선택적인 판·선택 범위·저장된 판 선택을 받는다. 기본 경로에서는 미저장 상태를 거절하고 외부 디스크 변경을 기록한다. 명시한 판이 이미 바뀌었으면 선택 범위를 새 판에 몰래 옮기지 않고 요청을 보류한다.

엔진에 주는 읽기 사본은 문서 ID·판·내용 해시를 포함한 경로에 만든다. 같은 이름과 판 번호를 가진 다른 폴더의 파일도 분리한다. 작업 사본에는 요청 ID의 해시도 포함한다. 실제 판과 기존 읽기 사본의 내용이 기록된 해시와 다르면 전송을 거절한다. 기존 수정안의 저장 경로는 변경하지 않는다.

참조의 전체 해시와 저장된 판 선택 여부는 세션 요청 기록·프롬프트·Markdown 내보내기에 남긴다. 문서 패널과 일반 대화창은 같은 기존 세션을 사용한다. 읽기 참조의 원문은 AI 작업 사본으로 바꾸지 않는다.

검증 범위는 Markdown 두 문서와 대역 엔진을 사용한 실제 Linux 앱, 호스트의 같은 이름/긴 이름/요청 접두어 충돌·해시 검증·수정안과 복구 회귀다. PPTX·사용자 양식까지 이어지는 실제 엔진 흐름과 Windows/macOS는 후속 검증이다.

## 원본 Office 채팅의 참조

2026-10-31 Word/PPT/Sheets/HTML/한글/XMind/EPUB의 `@`와 문서 첨부 버튼을 연결했다. 같은 프로젝트의 열린/최근 문서를 선택하고, 선택 이후 사람의 편집은 보낼 때 저장한다. dirty 표시가 늦는 원본 Office도 쓰기 권한이 있는 편집기를 직접 확인한다. 요청별 판/해시를 고정하고 원본 파일 파서의 가림을 유지한다. 같은 창의 후속 요청은 다시 첨부하지 않아도 최신 판을 읽는다.

최종 실제 Linux **47/47**, 회귀 **63/63**. PPT 옆 칸에서 Markdown을 실제 편집한 흐름과7종 수신 편집기를 확인했으며 native 입력 참조는 Markdown이다. 로컬/이미지 첨부·재열기 후 첨부 복원·바이너리 입력 전체·Markdown/PDF 채팅의 첨부 확장·Windows/macOS는 후속이다. 근거 `office-document-references-native-06/verification.json`; 연구 판 `research:rr-e6e9abfeeec587137aae8e9d2f47aef0:a300e80dade495efb053fd3f867510fb4988576bcabae28ece610741303e5df5`.

## 로컬 첨부와 대화 복원

이어서 같은 7종의 파일 선택·드롭·이미지 붙여넣기와 재열기 복원을 연결했다. 파일 50MiB·이미지 5MiB까지 기존 해시 보관소에 저장한다. 로컬 경로는 부모 선택창에서 고르고, 브라우저 File은 바이트로 전달한다. 요청 동안 파일을 고정하고 다음 요청은 로컬 원본의 최신 내용을 읽는다. 첨부 이력은 같은 Workbench 대화에 보관하며 새 대화에는 이전 읽기 권한을 넘기지 않는다.
