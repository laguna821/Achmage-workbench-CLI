# 변경 구간별 스테이징

**Git 변경 검토**의 작업 파일·스테이징 비교에서 각 변경 구간을 선택할 수 있다. **이 구간 스테이징**으로 하나를 반영하거나 여러 구간을 체크한 뒤 **선택 구간 스테이징**을 실행한다. 스테이징된 변경 화면에서는 같은 방식으로 선택한 구간만 취소한다. 두 작업 모두 작업 파일의 바이트를 바꾸지 않는다.

**다음 변경** 또는 `F7`로 다음 구간, `Shift+F7`로 이전 구간에 이동한다. 새 diff를 불러오면 선택을 비운다. 줄 번호는 기준 쪽과 변경 쪽을 각각 표시하며, 기존 줄바꿈 보기와 이미지 비교를 계속 사용할 수 있다.

## 적용 범위와 보호

- 서버가 생성한 완전한 UTF-8 텍스트 diff에만 구간 ID를 제공한다. ID는 파일·staged/working 영역·검토 판·실제 patch 내용에 묶인다. 클라이언트가 작성한 patch는 받지 않는다.
- 요청 직전 실제 상태와 diff를 다시 읽는다. 같은 저장소의 작업을 직렬화하고 `git apply --cached --check` 후 검토 판을 다시 확인한 뒤 인덱스에만 적용한다. 스테이징 취소는 같은 patch를 역방향으로 적용한다. 작업 파일 적용, 3방향 우회, reject 파일이나 자동 공백 수정은 사용하지 않는다.
- 검토 후 파일이나 인덱스가 달라지면 새로고침을 요구한다. 이미 적용된 요청 ID를 다시 보내도 두 번 반영하지 않는다. 실패·출력·선택 파일/구간 수는 기존 Git 작업 기록에 남는다.
- 내용 일부만 표시한 큰 diff, 비 UTF-8·바이너리, 충돌·rename·모드·링크·서브모듈 변경에는 이유를 표시하고 기존 파일 전체 처리 또는 충돌 검토를 사용한다. 텍스트 파일의 추가·삭제처럼 한 구간이 파일 전체인 경우도 있다.
- 이 단계는 **구간 전체** 선택이다. 한 구간 안의 개별 행 조합, 임의 브랜치·커밋 기준 비교와 행 주석의 에이전트 전달은 후속으로 유지한다. Orca 문서에서 확인한 기존 기능은 파일 스테이징·구간 비교이며, 구간 선택 스테이징 자체를 검증된 Orca 기능으로 단정하지 않는다.

`POST /api/workspaces/:id/scm/jobs`의 `stage-hunks` / `unstage-hunks`는 `selection: { path, expectedRevision, hunks }`를 받는다. 최상위 `expectedRevision`은 SCM 상태, selection의 판은 선택한 diff에 해당한다. 기존 메인 gateway 인증과 소유한 Git 프로세스의 중단 방식을 사용한다.
