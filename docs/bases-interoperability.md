# 프로젝트 보기와 Obsidian Bases

홈의 **프로젝트 → 보기 더하기(+)**에서 `.base` 가져오기와 현재 보기 내보내기를 연다. 이 기능은 앱에 등록된 프로젝트 노트를 대상으로 한다. 일반 보관함 노트나 첨부파일을 프로젝트로 자동 등록하지 않는다. 가져오기는 기존 보기 뒤에 추가하며 원본 `.base`와 Markdown을 고치지 않는다.

## 가져오기

파일을 고르거나 YAML을 붙여 넣은 뒤 보기별 결과를 확인한다. 표·카드·목록·칸반을 지원한다. 일반 노트 속성 및 파일명·실제 파일 폴더·경로·확장자·생성/수정 시각·크기·태그를 표시·묶기·정렬에 사용할 수 있다. 앱의 분류 폴더와 실제 파일 폴더는 다른 속성이다.

전역 필터와 보기 필터는 AND로 합친다. 문자열/숫자/불리언/목록/null 형태를 유지하며 다음 구문을 해석한다. JavaScript로 실행하지 않는다.

- `and`, `or`, `not` 객체, `&&`, `||`, `!`, 괄호
- `==`, `!=`, `>`, `<`, `>=`, `<=`
- `note.속성`, `note["콜론 키:"]`, 접두사 없는 노트 속성, 지원되는 `file.*`
- `file.hasTag(...)`, `file.inFolder(...)`, `list(...)`
- 문자열/목록의 `.contains(...)`, 문자열의 `.startsWith(...)`/`.endsWith(...)`, `.isEmpty()`

수식·`this`·지원하지 않는 함수/파일 속성·여러 정렬·행 수 제한·수동 그룹 순서가 있는 보기는 이유를 표시하고 선택하지 못하게 한다. 조건을 지운 전체 목록으로 바꾸지 않는다. 열 별칭, 요약 계산, 플러그인 표시 옵션 등의 차이는 미리 알린다. YAML 앵커/별칭, 중복 키, 256KB 초과 입력은 거절한다.

가져온 필터는 **Bases 필터** 메뉴에서 확인하거나 해제할 수 있다. 일반 검색 필터를 함께 쓰면 두 조건 모두 적용한다. 잘못된 저장 필터는 결과를 넓히지 않고 오류를 표시한다.

## 내보내기

현재 보기의 표준 설정과 Workbench 복원 정보를 한 `.base` 파일로 저장한다. Workbench로 다시 가져오면 하위 그룹, 색상, 접힘, 앱 전용 속성 등을 복원한다. Obsidian에서 표준 설정을 수정한 파일은 수정된 표준 내용을 우선하고 이전 복원 정보를 적용하지 않는다.

Obsidian에서는 같은 보관함에 있는 `workbench_id`가 있는 프로젝트 노트만 표시한다. 세션 수, 실행 상태, 앱 분류 폴더 등은 표준 노트 속성으로 바꾸지 않는다. 앱 검색 필터를 둔 보기의 경우 Obsidian에서는 결과를 숨기고, Workbench 재가져오기에는 원래 검색을 복원한다. 이러한 차이는 저장 전에 표시한다.

데스크톱에서는 저장 위치를 고르고 브라우저에서는 다운로드한다. 기존 파일은 덮어쓰지 않는다. 같은 이름이 있으면 다른 이름으로 저장한다. 원본 노트의 YAML·본문은 내보내기 대상이 아니며 변경되지 않는다.

## 검증 범위

필터 형식, 자료형, 중첩 논리, 위험하거나 미지원인 식 거절, 원문 유지, 보기 왕복 교환, 외부 수정 우선순위, 기존 파일 덮어쓰기 방지를 회귀 검사한다. 실제 Linux Tauri 검사에서는 가져오기 미리보기, 적용 결과, 설정 복원, 내보내기 미리보기와 저장 API 및 재가져오기를 확인한다. OS 저장 대화상자에서 위치를 선택하는 동작과 Windows/macOS 설치본 검사는 별도 릴리스 검증 대상이다.

형식 근거: [Obsidian Bases 문법](https://obsidian.md/help/bases/syntax), [보기](https://obsidian.md/help/bases/views), [파일 속성 함수](https://github.com/obsidianmd/obsidian-help/blob/master/en/Bases/Functions.md). YAML 처리는 [yaml 라이브러리](https://eemeli.org/yaml/)를 사용한다.
