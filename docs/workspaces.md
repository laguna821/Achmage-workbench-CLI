# 프로젝트와 작업공간

프로젝트는 목적·분류·프로젝트 노트·세션 기록을 묶는다. 작업공간은 그 프로젝트에서 실제 파일을 읽고 AI를 실행하는 폴더다. 기본 작업공간 외에 다른 폴더를 연결하거나 격리 사본을 만들 수 있다. 일반 폴더에는 Git이 필요하지 않다.

대화 상단의 **작업공간 선택**에서 폴더 연결, 이름 변경, 보관과 복원을 한다. 공간을 열면 그곳의 기존 세션을 선택하고, 아직 세션이 없으면 새 대화를 만든다. 입력창에서 새 세션을 추가하면 현재 작업공간을 공유한다. 세션은 만들어진 작업공간에 고정되며 화면 선택만으로 실행 위치가 바뀌지 않는다.

보관은 새 실행을 막는다. 파일이나 세션 기록을 지우지 않고 실행 중인 세션을 강제 중단하지 않는다. 연결된 세션 중 하나라도 실행 중이면 보관과 worktree 제거를 거절한다. 격리 사본의 **버리기**는 별도의 실제 Git 작업이며, 성공했을 때만 해당 공간의 모든 세션을 보관한다. 제거된 공간은 기록으로 유지하며 복원 버튼으로 없는 폴더를 재생성하지 않는다.

## 데이터 계약

- `Work.defaultWorkspaceId`: 프로젝트의 기본 폴더 연결. 기존 `Work.cwd`는 프로젝트 노트가 있는 원래 위치를 유지한다.
- `Workspace`: 프로젝트 ID, 실행 호스트, 실제 cwd, 일반 폴더/worktree 구분, 관리 여부, Git 정보, 보관 시각과 제거 시각.
- `Session.workspaceId`: 생성 시 고정. 기존 `Session.worktree`도 호환을 위해 보존한다. 같은 worktree에서 여러 Claude/Codex 세션을 사용할 수 있다.
- `Artifact.workspaceId + relativePath`: 다른 worktree의 같은 이름을 구별한다. 기존 문서 ID·절대 경로·리비전은 유지한다. 이미 추적한 실제 파일은 겹치는 폴더를 통해 다시 열어도 같은 문서로 연다.

처음 실행할 때 SQLite 트랜잭션으로 연결을 추가한다. 기존 Work/Session/Artifact ID, native session ID, 알 수 없는 과거 필드, 리비전과 노트 원문을 보존한다. 외부 문서는 실제 위치의 폴더 공간으로 연결하고 파일을 옮기지 않는다. 이행 중 쓰기가 실패하면 전체 연결 변경을 롤백한다. 구버전 앱이 나중에 만든 행도 다음 시작에서 연결한다.

엔진 cwd, 참조 문서의 작업 사본, 새 문서 예약, 상대경로 파일 변경, 종료 후 문서 탐색, 세션 기록 내보내기, 그림 생성용 세션과 이미지 파일이 세션의 공간을 따른다. 연결된 폴더에서 이루어진 기존 대화를 가져오면 해당 공간을 재사용한다. 프로젝트 노트는 프로젝트의 원래 위치에 남는다.

## 검증과 후속

임시 데이터베이스·폴더·Git 저장소와 대역 엔진으로 이행 반복/롤백, ID/원문 보존, 실행 경로, 같은 상대경로 파일 분리, 공유 worktree 제거, 대화 가져오기와 그림 저장을 검사한다. 실제 Linux Tauri 화면에서는 폴더 연결→세션 생성→이름 변경→보관/복원→공간 왕복→새로고침 복원을 검사한다.

작업공간별 전체 탭·분할·스크롤·커서 복원은 다음 G1 단계다. 기존 worktree 발견/연결, 기준 ref 선택, 환경 준비, PTY와 Git/PR 작업 흐름은 G3에서 이어진다. 이 문서는 그 기능들이 이미 완료되었다는 의미가 아니다.
