# 작업공간의 Git 변경 검토

작업공간 메뉴의 **Git 변경 검토**에서 현재 브랜치, HEAD, upstream의 앞섬·뒤처짐, 스테이징한 변경과 작업 파일의 변경을 구분한다. 저장소 하위 폴더를 연결한 경우에도 화면에 표시한 Git 루트 전체가 검토 범위다.

파일을 선택하면 이전/이후 줄 번호, 줄바꿈 선택과 실제 Git diff를 표시한다. PNG/JPEG/GIF/WebP는 이전·이후 이미지를 나란히 또는 겹쳐 볼 수 있다. SVG는 코드로 표시한다. 이미지 한 판은 8 MiB, 텍스트 표시는 512 KiB 또는 6,000행까지이며 생략을 알린다. 중첩 저장소는 해당 폴더를 별도 작업공간으로 열어 검토한다.

파일별 또는 목록 전체를 스테이징·취소할 수 있다. 커밋은 스테이징한 내용만 사용하고 실제 저장소 훅과 서명 설정을 유지한다. 실패한 훅을 건너뛰거나 자동 재시도하지 않는다. 커밋 초안은 작업공간별 로컬 WebView 저장소에 보존하며 성공한 커밋 뒤 비운다.

## 파일·실행 보호

- 조회는 `--no-optional-locks`, porcelain v2 `-z`를 사용해 인덱스를 쓰지 않는다. NUL 경로 목록과 literal pathspec으로 공백·개행·한글·와일드카드 모양의 파일명을 그대로 다룬다. 첫 커밋 전 스테이징 취소와 rename 양쪽 경로도 처리한다.
- 변경 화면의 판은 실제 저장소·HEAD·인덱스 해시·Git 상태·변경 경로의 파일 식별/크기/나노초 수정·변경 시각을 포함한다. 실행 전에 다시 검사하며 오래된 판을 거절한다. 외부 터미널 전체를 잠그는 기능은 아니며, 검사 직후 외부 프로세스가 쓰는 경쟁까지 원자적으로 막는다고 주장하지 않는다.
- 앱 안의 Git 변경 작업은 common Git 디렉터리별로 직렬화한다. 작업 중 같은 폴더의 새 세션·문서 저장·준비·제거가 들어오지 않게 기존 폴더 잠금을 사용한다. 실행 중인 에이전트나 준비 작업이 있으면 먼저 끝내거나 중단해야 한다. 이미 열린 외부 터미널은 인수하거나 종료하지 않는다.
- 앱이 준비 과정에서 만든 공유 링크는 대상이 그대로일 때만 untracked 목록에서 제외한다. 사용자가 바꾸거나 스테이징한 링크는 표시한다.
- 작업마다 요청 ID와 입력을 저장해 중복 HTTP 요청으로 두 번 커밋하지 않는다. 진행·결과·최근 128K 문자의 출력·커밋 전후 HEAD를 로컬 SQLite에 남긴다. 재시작 때 결과를 확인하지 못한 작업은 중단 기록으로 남고 자동 재실행하지 않는다.
- 명시적 중단은 이 작업이 새로 시작한 Git 프로세스에만 적용한다. Linux에서는 전용 프로세스 그룹의 훅까지 종료하는 것을 검사했다. 중단은 변경을 되돌리지 않으며 현재 파일·스테이징·HEAD를 확인해야 한다. Windows 자식 훅 종료와 macOS는 별도 실기 검증 대상이다.

## API와 검사

메인 인증 gateway에서만 제공한다. 문서 편집기의 제한된 토큰에는 추가 권한을 주지 않는다.

- `GET /api/workspaces/:id/scm`: 상태와 판.
- `POST /api/workspaces/:id/scm/diff`: 파일·영역·검토한 판에 대한 비교.
- `GET/POST /api/workspaces/:id/scm/jobs`: 기록 또는 명시적 stage/unstage/commit 요청.
- `GET/DELETE /api/scm-jobs/:id`: 결과 또는 소유한 실행 중단.
