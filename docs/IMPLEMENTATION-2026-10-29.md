# 통합 업데이트 실행 기록

목표: 기존 통합 계획과 PKM의 남은 기능을 구현·검증하고 GitHub에 OS별 새 버전을 릴리스한다. 다음 버전은 잠정 `0.3.0`이며, 버전 번호는 실제 릴리스 준비 시 확정한다.

- 시작 기준: 로컬 `b3bceab5`, 공개 v0.2.2 `0cfc9443`
- 구현 브랜치: `feat/unified-workbench-v0.3`
- [통합 계획](design/업데이트-통합계획-2026-10-29.md), [103개 기능 묶음 대조표](design/Orca-이음오피스-기능대조표.md)
- 기본 화면은 한 칸으로 유지하며 사용자가 분할할 때 확장한다. 기존 프로젝트·세션·문서·설정은 보존한다.
- 실제 구현, 자동 검사, 설치본 검증, 게시 여부를 따로 기록한다. 미완료 기능을 완료로 표시하지 않는다.

## 검증·릴리스 순서

1. 변경한 계약과 데이터 보존 동작을 국소 테스트로 확인한다.
2. 연결된 웹/호스트/편집기 타입 검사와 회귀 검사를 수행한다.
3. 실제 Linux 앱에서 창·입력·문서·세션·종료/복구를 확인한다.
4. 준비된 변경을 한 묶음으로 GitHub에 올리고 OS별 빌드/설치 검사를 수행한다. 같은 실패를 수정 근거 없이 반복 push하지 않는다.
5. Windows NSIS/MSI, macOS Apple silicon DMG, Linux AppImage/deb/Arch 패키지의 결과·해시·용량을 확인하고 릴리스 노트에 검증 범위를 명시한다.
6. 기능/설치 검증이 끝난 버전만 공개 릴리스로 게시한다.

## 시작 환경

GitHub 저장소 쓰기 권한과 기존 릴리스 워크플로를 확인했다. 로컬 Node 26.8.1, npm 12.2.0, Rust/Cargo 1.99.1이 있다. Rust는 기본 PATH에 없지만 기존 `~/.cargo/bin` 설치를 사용한다. CI는 현재 Node 24다. 차이는 실행 결과에 기록한다.

현 장치의 Achmage resourceManagement는 비활성이다. 이를 임의로 활성화하거나 자원 정책을 우회하지 않는다. 무거운 작업은 동시에 여러 개 실행하지 않고 현재 자원 상태를 확인한다. 향후 활성 상태라면 예약과 stable resource-run을 사용한다.

기존 다른 작업트리와 미커밋 E2E 파일은 보존한다. 이전 Broadway 실패를 같은 조건으로 재시도하지 않는다. 실행 파일 인자와 display/socket 조건을 수정·기록한 뒤 새 검증을 한다.

## 작업별 결과

- Git 검토/적용에서 인덱스를 수정하지 않도록 변경했다. NUL 경로 파싱, 빈 파일/바이너리 패치, 삭제 실패 전파, 미병합 커밋 브랜치 보존, stale worktree 식별 거부를 추가했다. 임시 Git 저장소 회귀 10개 통과.
- 저장된 모델 ID가 현재 목록에 없어도 그대로 표시한다. 요청 별칭과 실제 모델명을 구분하며 엔진 기본값으로 돌아가는 선택을 명시했다. Claude 모델 캐시는 계정/엔진 버전별로 분리하고 기존 무범위 캐시는 다시 읽는다. 모델 관련 6개 회귀 통과.
- 실제 앱 검사 하네스를 복구했다. 미구현 검사를 성공 처리하지 않고, 검증된 실행파일·임시 데이터·대역 엔진·전용 Broadway/D-Bus로 실행한다. Linux 추상 소켓 readiness와 설정 저장 debounce에 맞게 검사를 수정했다.
- `npm run typecheck`, `npm run build`, Tauri `build --debug --no-bundle` 통과. 실제 Linux Tauri 창 시작/첫 화면/온보딩/저장 검사 4개 통과 및 정상 종료. 이 결과는 최신 Office 전체 기능이나 OS별 설치본 검증을 의미하지 않는다.
- 다음: 재귀 분할과 복원, 작업공간 계약 및 남은 PKM 기능. 릴리스는 아직 게시하지 않았다.
