## 검증·릴리스 순서

1. 변경한 계약과 데이터 보존 동작을 국소 테스트로 확인한다.
2. 연결된 웹/호스트/편집기 타입 검사와 회귀 검사를 수행한다.
3. 실제 Linux 앱에서 창·입력·문서·세션·종료/복구를 확인한다.
4. 준비된 변경을 한 묶음으로 GitHub에 올리고 OS별 빌드/설치 검사를 수행한다. 같은 실패를 수정 근거 없이 반복 push하지 않는다.
5. Windows NSIS/MSI, macOS Apple silicon DMG, Linux AppImage/deb/Arch 패키지의 결과·해시·용량을 확인하고 릴리스 노트에 검증 범위를 명시한다.
6. 기능/설치 검증이 끝난 버전만 공개 릴리스로 게시한다.

## 시작 환경

GitHub 저장소 쓰기 권한과 기존 릴리스 워크플로를 확인했다. 로컬 Node 26.8.1, npm 12.2.0, Rust/Cargo 1.99.1이 있다. Rust는 기본 PATH에 없지만 기존 `~/.cargo/bin` 설치를 사용한다. CI는 현재 Node 24다. 차이는 실행 결과에 기록한다.

현 장치의 Achmage resourceManagement는 비활성이다. 이를 임의로 활성화하거나 자원 정책을 우회하지 않는다. 무거운 작업은 동시에 여러 개 실행하지 않고 현재 자원 상태를 확인한다. 향후 활성 상태라면 예약과 stable resource-run을 사용한다.

기존 다른 작업트리와 미커밋 E2E 파일은 보존한다. 이전 Broadway 실패를 같은 조건으로 재시도하지 않는다. 실행 파일 인자와 display/socket 조건을 수정·기록한 뒤 새 검증을 한다.
