# Git 충돌 검토와 해결

작업공간 메뉴의 **Git 변경 검토 → 해결할 충돌**에서 기준본(base), 현재 쪽(ours), 가져온 쪽(theirs)과 작업 파일을 확인한다. 실제 Git 인덱스의 1·2·3단계를 읽으며, 삭제·새 파일처럼 없는 단계도 구분한다. 재배치 중에는 **재배치 대상**과 **다시 적용할 커밋**으로 표시한다. 재배치의 ours는 대상 브랜치와 이미 적용한 커밋이다.

텍스트를 직접 편집하거나 한쪽 전체 파일, 현재 파일 유지, 삭제를 선택할 수 있다. **파일에 저장**은 작업 파일만 바꾸며, **해결 완료 · 스테이징**은 선택한 파일만 스테이징한다. 충돌 파일은 일반적인 모두 스테이징에 포함하지 않는다. Git 속성의 `conflict-marker-size`를 읽고 표식이 남으면 해결 완료를 막는다. 문서에 의도적으로 같은 표식을 쓰는 경우에만 별도 확인으로 유지할 수 있다.

텍스트 편집은 유효한 UTF-8 2 MiB까지 지원한다. 기존 BOM, 균일한 CRLF와 일반 파일 권한을 보존한다. 텍스트 입력 초안은 작업공간·경로별 WebView 저장소에 남고 파일에 자동 반영되지 않는다. 검토 후 파일·인덱스·진행 중인 작업이 바뀌면 저장을 거절하며, 새 내용을 비교한 뒤 초안을 사용할 수 있다. 저장 공간이 부족하면 화면에 알린다.

바이너리와 UTF-8 외의 파일은 텍스트로 변환하지 않는다. 한쪽 전체 파일 선택은 16 MiB까지이며, Git의 필터와 파일 모드를 적용한다. PNG/JPEG/GIF/WebP는 8 MiB까지 미리보기를 제공한다. 링크는 대상 문자열을 표시하고 링크 자체를 바꾸며, 상위 폴더의 링크를 따라가지 않는다. 서브모듈·폴더 충돌과 더 큰 파일은 같은 작업공간 터미널에서 해결한 뒤 새로고침한다.

## 작업 계속과 취소

충돌을 모두 스테이징하면 **해결한 작업 계속**으로 merge/rebase/cherry-pick/revert의 해당 `--continue`를 실행한다. 기존 커밋 메시지·훅·서명 설정을 사용한다. 재배치가 다음 커밋의 충돌에서 다시 멈추면 그 상태와 실제 출력을 남긴다. 자동으로 다음 충돌을 선택하거나 커밋을 건너뛰지 않는다. 빈 커밋의 skip 등 추가 판단은 터미널에서 한다.

**진행 중인 작업 취소**는 현재 변경에 대한 확인을 받아 해당 `--abort`만 실행한다. 취소는 수작업 해결 내용을 되돌릴 수 있다. Git이 새 파일 덮어쓰기 등을 거절하면 실패를 그대로 표시하며 강제 reset이나 삭제로 재시도하지 않는다. 앱의 일반 **중단**은 실행 중인 프로세스를 멈추는 동작으로, Git 작업의 취소와 다르다.

파일 변경과 충돌 작업은 같은 저장소의 다른 앱 Git 작업과 직렬화한다. 살아 있는 문서 작성권이나 실행 중인 에이전트가 있으면 진행하지 않는다. HEAD·인덱스·작업 파일뿐 아니라 MERGE_MSG, rebase 진행/메시지, sequencer 상태 등도 검토 판에 포함한다. 외부 프로세스 전체에 대한 원자적 잠금은 아니므로 외부 터미널의 동시 쓰기까지 막는다고 주장하지 않는다.

## 복구 파일과 기록

해결 파일을 바꾸기 전에는 해당 작업 파일과 인덱스를, 작업을 취소하기 전에는 Git이 추적하는 변경 파일과 인덱스를 앱 데이터 폴더의 `scm-recovery/<job-id>`에 보관한다. 합계 128 MiB를 넘거나 복구 사본을 만들지 못하면 원본 변경 전에 멈춘다. 작업 기록에 복구 경로를 표시한다. `manifest.json`은 원래 경로·종류·Git 모드·해시와 번호별 `.bin` 파일의 대응표이며, 링크의 대상 문자열도 실행 가능한 링크가 아닌 원시 바이트로 보관한다. 폴더와 서브모듈 내부를 재귀 복사하지 않는다.

복구 사본을 자동 덮어쓰거나 자동 정리하지 않는다. 현재 파일과 비교해 필요한 내용을 직접 되돌릴 수 있다. Git 인덱스 사본은 진단·복구 자료이며 실행 중인 저장소에 자동 복원하지 않는다. 스테이징 실패 시 이미 저장한 작업 파일과 복구 사본을 유지한다. 파일 내용은 Git 작업 DB에 복제하지 않고 해시로 요청 중복을 확인한다. 앱 재시작 시 중단된 작업을 자동 재실행하지 않는다.

## API와 검증 범위

- `POST /api/workspaces/:id/scm/conflict`: `path`, `expectedRevision`에 대한 세 단계·작업 파일과 검토 판.
- `POST /api/workspaces/:id/scm/jobs`: `resolve`와 해결 판·방법·stage 여부, 또는 `continue`/`abort`와 진행 중인 operation. 취소는 `confirmAbort: true`가 필요하다.
- 메인 인증 gateway의 권한과 기존 Git 작업 기록·중단 API를 사용한다. 문서 편집기 제한 토큰에는 Git 권한을 추가하지 않는다.

Linux 실제 Git 저장소와 Tauri 화면을 검증한다. Windows/macOS의 실제 설치·Git 훅·파일 속성, 고급 rename/폴더·서브모듈 UI는 후속이다. hunk·행 주석·PR/CI 및 전체 OS 릴리스는 이 단계의 완료 범위에 포함하지 않는다.
