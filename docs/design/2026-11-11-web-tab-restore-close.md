# 웹 탭 복원과 사이드바 닫기

앱을 다시 열면 저장된 웹 탭이 같은 주소·브라우저 프로필·AI 대화로 이어져야 한다. 사이드바에서 웹 탭을 X 또는 우클릭 메뉴로 닫을 수 있어야 하며, 연결이 끊긴 탭도 제거할 수 있어야 한다.

## 구현

- 호스트에 같은 pageId를 다시 연결하는 restore 경로를 추가한다. 실제로 살아 있는 다른 창의 연결을 빼앗지 않으며, 이전 AI 명령은 다시 실행하지 않는다.
- 화면에 남아 있지만 구버전에서 closed로 처리한 탭은 명시적 닫기 시각이 없는 경우 복구한다. 새로 명시적으로 닫은 탭에는 closedAt을 남겨 다시 켤 때 살아나지 않게 한다.
- 새 탭을 요구하는 오류 화면을 같은 탭 자동 연결과 재연결 버튼으로 바꾼다. 비활성 탭은 선택할 때 복원한다.
- 사이드바 웹 AI 행에 X, 우클릭과 웹 탭 메뉴에 닫기를 추가한다. 상단 탭과 저장된 화면 배치도 함께 정리한다.
- 닫을 때 해당 탭의 각 엔진 대화를 보관한다. 원문은 삭제하지 않고, 보관함에서 대화로 열 수 있다. 메인 대화는 건드리지 않는다.
- 네이티브 닫기는 기본 앱 창에만 허용한다. 페이지 JavaScript 또는 AI 제어권 응답이 없어도 사용자가 탭을 닫을 수 있다.
- 기기 연결 전환은 편집기 저장만 수행하고 웹 탭을 닫지 않는다.

## 확인 범위

호스트·렌더러의 관련 회귀 테스트 24개 및 TypeScript 검사 통과. Linux 네이티브 재시작, 프로필 쿠키 유지, 사이드바 닫기와 닫은 뒤 재실행이 별도 임시 프로필에서 모두 통과했다. Broadway의 WebKitGTK 시작 오류와 검수 스크립트의 인용 오류는 R14에 따로 기록했고, 수정한 스크립트와 격리 X11에서 확인을 완료했다. Windows/macOS에서 실행했다는 의미는 아니다.

이 노트북에 설치하고 재실행한 뒤, 구버전에서 closed로 남았던 저장 탭이 ready로 복구되는 것을 확인했다. 기존 대화 339개 전체 행, 프로젝트 1개, 세션 7개, 문서 6개와 판 32개, 이음오피스 별도 등록은 그대로 유지됐다. 이전 설치본과 DB 백업은 로컬에 보존했다.
