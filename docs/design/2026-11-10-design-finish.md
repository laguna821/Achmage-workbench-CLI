2026-11-10. Hallmark·Impeccable 마감 수정은 소스에 반영했다. [실제 화면 비교](previews/2026-11-10-finish/index.html)에서 라이트/다크와 좁은 화면의 전후를 볼 수 있다. 이번 단계는 설치본 배포가 아니다.

- Hallmark 2.0.0의 app 범위 polish와 독립 마감 리뷰, Impeccable 4.8.0의 polish / craft-floor를 적용했다. OS 통합 지침의 직접 문맥 읽기 대안을 사용했고 Impeccable 자동 context 엔진은 실행하지 않았다.

## 실제 브라우저·에이전트

빈 탭에서 Tauri가 초기 `about:blank` 로드를 생략해 DOM API가 준비되지 않던 문제를 명시적 초기 탐색으로 수정했다. 숨긴 GTK 탭을 다시 표시할 때 크기를 적용하지 못하던 문제는 표시 후 배치를 적용하도록 고쳤다. iframe 주소가 상위 탭 주소를 덮지 않도록 하고, 웹 작업과 메인 작업의 세션을 분리했다.

실제 빌드 앱의 임시 프로필에서 Codex 0.160.0에 자연어로 검색어 입력을 요청했다. 모델이 브라우저 도구를 선택했고 같은 네이티브 페이지의 입력값이 `new york times`로 바뀐 것을 확인했다. 웹 자식 세션이 실행되는 동안 메인 탭에서 별도 요청을 받아 `56`을 답했고, 웹 탭 복귀 후 입력값과 자식 세션이 유지됐다. “완료했다”는 답변만으로 성공 처리하지 않았다.

GTK에서 전체 창을 덮는 배치 레이어가 웹 영역 바깥의 마우스 클릭을 가로채던 문제도 수정했다. 레이어의 빈 영역만 입력을 통과시키고 웹뷰 자식은 계속 조작되도록 했다. 실제 마우스·키보드 입력과 앱 사이드바 전환을 같은 실행에서 확인했다.

macOS 컴파일에서 중복 Info.plist 심볼이 발생하던 부분은 앱 컨텍스트 매크로를 한곳으로 모아 해결했다. Windows 확인용 Cargo example에는 일반 앱에 들어가는 Common Controls v6 리소스가 빠져 있었으므로 같은 생성 리소스를 연결했다. Windows 원인은 캡처한 실행 파일의 `.rsrc` 부재와 `TaskDialogIndirect` import로 좁혔다. 이 함수는 [Microsoft 문서상 Comctl32 v6](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-taskdialogindirect)를 요구한다.

## 확인 범위와 한계

- 웹 타입 검사와 외형·대화 관련 집중 회귀 확인을 통과했다. 이미 통과한 전체 제품 테스트를 반복하지 않았다.
- 홈·채팅·프로젝트 YAML·이미지·검색·9분할의 라이트/다크 화면을 캡처했고, 좁은 화면과 실제 Markdown 편집기는 수정된 부분만 다시 확인했다. Pretendard 포함 서체 로드도 확인했다.
- Hallmark 실제 렌더와 소스 검사에서 기존 링크 16/16, 필드 64/64, 핸들러 1613/1613을 보존했다. 자동 결과는 104 FAIL / 27 REFLEX에서 79 FAIL / 3 REFLEX로 줄었다. 이는 결함 개수가 아니다. 테마 토큰 블록, 기술명, 실제 상태 점, 사용자 문서 텍스트, HIG 데스크톱 크기 기준 등 파서의 오분류와 적용 제외 사유는 [원문 판정표](../../.hallmark/triage.json)에 남겼다. 자동 결과를 임의로 0으로 만들지 않았다.
- 공통 화면 캡처는 OS별 네이티브 성공을 대신하지 않는다. 실제 Codex 병렬 실행은 Linux에서 확인했고 Windows/macOS는 별도 네이티브 드라이버 실행 범위로 보고한다.
