## 1. 설계 의도

**누가, 어디서**: 한 사람(미디어스쿨 교수)이 리눅스 노트북에서 하루 종일 쓴다. 쓰고, 가르치고, 연구하고, 코딩한다. Claude Code와 Codex에 일을 맡기고, 진행을 지켜보고, 승인하고, AI 수정안을 검토하고, 긴 답을 읽는다. 문서는 한글·워드·PPT·마크다운이다.

**하는 일**: 맡긴다 → 지켜본다 → 판단한다(승인·수정안·계획) → 읽는다 → 정리한다. 이 앱의 핵심 화면은 마케팅 페이지가 아니라 작업대다. 읽기와 판단에 걸리는 시간이 가장 길다.

**브랜드 세 마디**(V1): **괘선처럼 정돈된 · 잉크처럼 분명한 · 교정지처럼 근거가 보이는**. 물건으로 치면 연구자의 괘선 노트와 편집자의 교정지다. 줄(1px 괘선)이 영역을 나누고, 잉크 한 색이 행동을 표시하고, 여백의 작은 날인(씰·태그)이 상태와 출처를 적는다.

**미감 방향**: ACH Thesis Spine의 "차분하지만 구조가 강한 작업 공간"을 앱에 옮긴다. 차가운 중립 책상 위에 종이(대화·문서)가 놓인다. 깊이는 그림자가 아니라 괘선과 면의 밝기로 만든다. 색은 계열 하나(Achmage 블루)와 엔진 고유색만, 그것도 드물게.

**원칙 다섯**

1. 읽기가 주인공이다. 대화와 문서는 종이(엔진 룩), 앱의 틀은 책상(중립)이다. 틀은 조용하고 늘 같다.
2. 상태는 날인으로 적는다. 확인 필요·수정안·계획·판(r1)은 작은 태그와 틴트로 표시한다. 옆줄(좌측 색 테두리), 빛, 그라디언트로 표시하지 않는다.
3. 위계는 크기·굵기·자리·여백으로 만든다. 그림자와 움직임은 마지막 수단이다.
4. 움직임은 상태의 증거일 때만. 일하는 중·도착·열림만 움직이고, 움직임 줄이기에서는 멈춘다.
5. 한국어 조판을 먼저 지킨다. 어절 단위 줄바꿈, 한글 자간 0, 숫자는 등폭 정렬.

## 3. 감사 — 지금 화면의 문제 (2026-10-29, 고치기 전)

스크린숏: `/tmp/wb-design-shots/before/{chromium,webkit}-{light,dark}-*.png` (16개 화면 × 2테마 × 2엔진). 스타일시트 실측: 글자 크기 36종(11 · 11.5 · 12 · 12.5 · 13 · 13.5 · 14 · 14.5 · 15 …), 모서리 30종, 그림자 선언 68개, 굵기 6종(500·600·650·700…), 키프레임 16개, 옆줄(1px 넘는 좌측 테두리·inset 줄) 9곳, 장식용 원뿔 그라디언트 4곳, 배경 흐림(glass) 3곳.

**공통**

- 옆줄 9곳(BAN 1): 승인 카드(주황 3px), 수정안 카드(파랑 4px), 작업 기록 띠(회색 2px), 레일 말풍선(inset 2px), 콜아웃(2px), 잇기 카드·보기 카드. 상태가 늘 "왼쪽 색 막대"로만 말한다 — 가장 흔한 AI 관리 화면 버릇이다.
- 빛(AI 오라): 입력창을 도는 빛 궤적, 대기 말풍선의 회전 테두리, 흐르는 꼬리에 빛, 진행 점 빛, 주요 버튼 빛(다크), 레일 현재 눈금 빛. 기본값이 "빛: 옅게"라 늘 켜져 있다.
- 다크에서 틀(사이드바·메뉴·찾기)이 Claude 다크의 핑크를 쓴다. Codex 세션을 보고 있어도 사이드바의 "새 세션"이 핑크로 꽉 차 빛난다 — 어두운 바탕 위 네온 강조(impeccable 금지 색).
- 글꼴: 틀의 작은 라벨(“Ctrl K”, “r1”, “12:00”, “5시간 33%”, “Fake (기본)”)이 SameTone의 세리프 라틴으로 나와 12–13px에서 가늘고 작아진다. 한글은 고딕, 라틴은 세리프라 한 줄 안에서 두 글꼴처럼 보인다.
- 크기 사다리가 없다(36종). 같은 위계가 13 · 13.5 · 14 · 14.5로 흔들린다. 굵기 650·600·700이 섞인다.
- 둥근 알약 수프: 세션 탭, 모드 막대, 필터 칩, 엔진 탭, 기능 알약, 태그가 모두 알약이라 무엇이 탭이고 무엇이 상태인지 모양으로 구분되지 않는다.
- 떠 있는 것이 많다: 모드 막대(그림자 있는 알약), "맨 아래로", 고정된 요청 띠(그림자), 턴 레일 눈금 — 내용 위에 겹친다.
- 순수 검정·흰색: Codex 라이트 본문이 #000000.
- Claude 라이트의 점토색 #C96442은 흰 글씨와 3.9:1, 종이 위 글씨로 3.7:1 — 작은 글자 AA 미달.
- 자리표시 글자(`--faint`)가 흰 바탕에서 약 2.6:1.

| 찾기(Ctrl+K) | 배경 흐림(glass), 노란 형광 표시, 필터 칩 알약, 미리보기 칸의 테두리 상자. |

| 볼트 카드 | 태그 알약이 많고 색이 제각각(사용자 태그색), 제목이 세리프 라틴. 썸네일·발췌는 괜찮다. |
| 노트 보기 | 속성 표가 고정폭 키 + 회색 알약 값. 제목 아래가 비어 보인다. |
| 보관함 | 제목+거대한 찾기 칸이 한 줄에 경쟁, 행이 카드. |
| 첫 안내 | 배경 흐림 + 큰 그림자, 단계 알약. |
| 좁은 창(900px) | 턴 레일이 말풍선과 겹치고, 입력창 아래 줄이 두 줄로 접힌다. |

**AI 슬롭 시험**(impeccable): "AI가 만들었다"는 말에 바로 수긍할 만하다. 원인은 기능이 아니라 기본기 — 크기 사다리 없음, 옆줄, 빛, 알약 수프, 떠 있는 그림자, 꽉 찬 강조색 단추.

## 4. 토큰

토큰은 `apps/web/src/styles.css` 맨 위에 있다. 이름은 기존 것을 유지하고(`--text`, `--muted`, `--faint`, `--accent`, `--line`, `--surface`, `--surface-muted`, `--bg`, `--amber`, `--amber-soft`, `--amber-text`, `--danger`, `--e-font`, `--popover-shadow` 그대로), 새 토큰을 더한다. 다른 기능의 CSS도 이 토큰만 쓴다(오브젝트 안의 hex 금지).

### 4.1 색

두 층이다.

- **틀(책상)**: 사이드바·메뉴·찾기·대화상자. `appearance.ts`의 `NEUTRAL_LOOK`(엔진과 무관, 사용자 설정 대상 아님). 상단 막대도 틀의 색을 쓴다(`--chrome-*`).

## 5. 컴포넌트 규칙

**단추** — 높이 32(기본) · 28(작게) · 36(주요 행동이 하나뿐인 대화상자). 모서리 `--r-md`. 글자 `--fs-ui` 500.
- 주요(`.button.primary`, 보내기): 꽉 찬 강조색, 화면(영역)마다 하나. 빛 없음. 누를 때 조금 진해짐.
- 보조(`.button`): 면 + `--line-strong` 테두리.
- 고스트(`.ghost-button`, `.text-button`, `.icon-button`): 배경 없음, hover에 올림 면.
- 위험(`.danger`): 위험색 글자, 확인이 필요한 곳에서만 꽉 찬 위험색.
- 아이콘 단추 32×32(사이드바 줄 안 24×24), 아이콘 16–18px, `aria-label` 필수.
- 단축키 표시(`kbd`): UI 글꼴 12px, `--r-xs`, 옅은 면 + 괘선, 세리프 없음.

**입력** — 높이 32/36, 모서리 `--r-md`, 테두리 `--line-strong`, 초점에 강조색 테두리 + 2px 고리. 자리표시는 `--muted`(4.5:1 이상). 라벨은 위에.

**알약·칩·태그** — 모양이 뜻을 말한다.
- 상태 태그(씰): 사각에 가까운 `--r-xs`, 12px 600, 의미색 옅은 면 + 진한 글자. 예: 확인 필요, 계획 먼저, r1, +3 −0.
- 선택 칩(필터, 문서 역할): `--r-sm`, 괘선 테두리, 켜짐은 강조색 옅은 면 + 강조색 글자.
- 완전한 알약(`--r-full`)은 개수 배지와 스위치뿐이다.
- 세그먼트(편집/둘 다/미리보기, 시스템/라이트/다크): 바깥 괘선 하나, 켜진 칸은 면이 올라오고 글자가 진해진다(강조색으로 꽉 채우지 않음).

**메뉴(팝오버·오른쪽 클릭)** — 면 + 괘선 + `--elev-2`, 모서리 `--r-lg`, 안쪽 4px. 항목 32px, `--r-sm`, hover 올림 면, 선택은 강조색 옅은 면 + 강조색 글자(꽉 채우지 않음). 단축키 힌트는 오른쪽 `--fs-meta` 흐리게. 위험 항목은 맨 아래, 구분선 뒤, 위험색.

**대화상자·시트** — 대화상자 `--r-xl`, `--elev-3`, 가림막(흐림 없음), 제목 `--fs-lead` display. 옆 시트(외형·MCP)는 오른쪽 괘선 + `--elev-2`, 머리 52px, 구획은 괘선으로.

**토스트** — 아래 가운데, 잉크 면(라이트)/올림 면(다크), `--r-lg`, `--elev-3`, 14px, 동작 단추는 들어 올린 강조색 글자. 3–5초, `role=status`.

**사이드바 줄** — 높이 30, `--fs-meta` 13px, 들여쓰기 14px 단위, 아이콘 15px 흐리게. 현재 줄 = 올림 면 + 진한 글자 600(강조색 면 아님). 상태는 오른쪽 점(확인 필요 주황, 진행 청록, 새 답 강조색 테두리 점). 섹션 제목 12px 600 흐리게, 자간 0. "새 세션"은 사이드바 맨 위의 테두리 단추(꽉 찬 강조색 아님), 찾기는 입력처럼 보이는 단추 + `Ctrl K`.

**상단 막대** — 높이 48, 틀의 색(`--chrome-bg`), 아래 괘선. 가운데 작업 제목은 display 16px 600. 오른쪽: 확인 필요 태그, 테마, ⋯.

**종이(작업 영역)** — 사이드바가 열려 있으면 왼쪽 위 모서리 `--r-lg`에 괘선 테두리로 책상 위에 놓인 종이처럼. 대화 머리(분류·문서·상태)는 13px 한 줄, 세션 탭은 밑줄 탭(현재 탭 = 진한 글자 + 2px 강조색 밑줄 — 탭 표시로 쓰는 밑줄은 옆줄이 아니다).

**입력창(시그니처)** — 화면에서 가장 공들인 하나. 면 + 1px 테두리(룩의 엔진 색 30% 섞음) + 모서리 `--e-radius`(기본 12) + 2px 아래 괘선(hard-offset, ACH 지문 "간헐적 hard-offset"의 유일한 자리). 초점: 강조색 테두리 + 3px 옅은 고리, 빛 없음. 아래 줄의 조절(권한·컨텍스트·기능·모델·강도·엔진)은 28px 고스트 단추로 높이와 글자를 맞춘다. 보내기/멈추기는 32px 강조색 사각(`--r-md`). 일하는 중: 입력창 위 가장자리에 2px 진행 막대가 천천히 지나간다(빛 끔일 때). 빛을 켜면 예전 궤적.

**대화(transcript)**
- 턴 사이: 괘선 하나 + 위아래 여백 24/20.
- 요청 머리: 번호 씰(`--r-xs`, 강조색 옅은 면, 등폭 숫자) · "요청" · 시각, 12px 흐리게.
- 사용자 요청: 오른쪽 정렬 "요청 쪽지". 말풍선 설정에 따라 — 옅게(기본): 강조색 7% 면 + 강조색 18% 테두리, 모서리 12 · 꼬리 4 / 채움: 강조색 면 + 흰 글자, 그림자 없음 / 레일: 둘 다 카드, 옆줄 없이 괘선 테두리.
- 답: 종이 위 맨 글(상자 없음, 레일 설정 제외), 말하는 엔진 이름은 13px 600 엔진 색.
- 작업 기록(도구·생각): 접힌 한 줄 — 화살표 + "명령 1개 · 파일 변경 1건" 13px 흐리게, 배경·옆줄 없음. 펼치면 괘선 상자 안 목록, 명령은 고정폭 13px, 경로는 작업 폴더 기준으로 줄여 한 줄(넘치면 말줄임).
- 승인: 주황 옅은 면 + 주황 35% 테두리 카드(옆줄 없음). 제목 16px 600, 명령은 흰 면 고정폭 상자, 동작은 오른쪽(거절 보조 · 허용 주요). "앞으로 묻지 않기"는 왼쪽 고스트.
- 계획: 괘선 카드, 머리 "계획" + 진행 `3/3` 등폭. 단계 표시는 16px 원 — 끝난 것은 청록 테두리 + 체크(꽉 채우지 않음), 진행 중은 스피너, 대기는 빈 원. 계획 확인 카드 안의 계획 본문은 상자 없이 들여쓴 글.
- 수정안(AI 제안 — ACH provenance): 엔진 색 4% 면 + 25% 테두리 카드, 머리에 엔진 표시 + "○○의 수정안 · 파일", 오른쪽 날인 `r1 기준` + `+3 −0`(등폭, 더함 청록·뺌 위험색). 동작: 미리보기(보조) · 적용(주요 작게) · 취소(고스트).
- 끝 표시: `✓ 끝남 · 46초` 12px 흐리게, 실패·중단은 위험색.
- 흐르는 중: 마지막 글자 뒤 2px 커서가 천천히 깜빡임(빛 없음).
- 첫 출력 기다림: 점 셋이 차례로 옅어졌다 진해짐(테두리 회전 없음).

**카드** — 정말 독립된 대상(파일·노트·세션·수정안)만. 괘선 테두리 `--r-lg`, 그림자 없음, hover에 테두리가 `--line-strong`. 카드 안에 카드 금지.

**표** — `<table>` 그대로, 머리 줄 12px 600 흐리게 + 아래 괘선, 칸 사이 세로선 없음, 숫자 오른쪽 정렬 등폭.

**빈 화면** — 한 줄로 무엇이 없는지 + 무엇을 하면 채워지는지(기존 문구 유지), 흐린 아이콘 하나까지.

**불러오기 · 뼈대** — 300ms 넘게 걸리는 첫 화면·문서 열기는 뼈대(skeleton, 옅은 면이 천천히 숨쉼) + 기존 문구를 보조 글로. 짧은 곳은 12px 스피너. 움직임 줄이기에서 정지.

**설정 스위치** — 켬/끔 설정(홈 로고 움직임, 끝나면 알림)은 체크박스를 스위치 모양으로(손잡이가 트랙을 지나감). `input type=checkbox` 그대로.

## 6. 아이콘

- 앱 자체 선 아이콘 한 벌(`components/Icon.tsx`, 24 그리드, 선 1.75, 둥근 끝). 아이콘 글꼴·이모지 아이콘 없음. 새 아이콘은 같은 규칙으로 경로만 더한다.
- 크기: 14(줄 안 보조) · 16(기본) · 18(상단 막대) — 그 밖 금지.
- 색은 글자색을 따른다(`currentColor`). 의미색은 상태 점·씰에만.
- 엔진 표시(`EngineMark`)는 우리 모양(Claude 불꽃, Codex 육각)과 엔진 색. 상표 로고를 쓰지 않는다.
- 사용자 데이터 속 이모지(DIKM 단계 🟢🔵🟣🟠⬜)는 데이터이므로 그대로 보인다.
