# Achmage 작업실 v2 — 한 작업, 한 화면, 한 입력창

2026-10-15 · 설계 제안 · 사용자 검토 전 · 구현·사용성·RAM 실측 아님

이번 안은 기존 설계제안.md의 공통 work·문서 revision·지식 계층 계약을 유지하면서, 상시 분할 화면과 다열 대시보드를 기본 화면으로 삼았던 UI 권고를 대체한다. 기존 이미지는 비교 기록으로 보존한다.

## 1. 설계의 기준을 바꾼다

사용자에게 필요한 것은 여러 AI의 창을 관리하는 능력보다, 하려던 일을 적은 개입으로 끝내고 나중에도 이어갈 수 있는 환경이다. 보기 좋은 관제실을 만드는 데서 멈추면 사용자는 계속 모든 세션의 중계자가 된다.

이번 방향은 사용자의 원문 「줄이기 위해 분해한다」에 직접 근거한다.

> 설계할 때는 더 자세히 들여다보고, 실행할 때는 더 적게 하도록 만든다.

Step Awareness는 모든 단계를 화면에 늘어놓는 뜻이 아니다. 필요한 결과를 얻는 데 사람이 수행해야 할 단계를 줄이되 Change-Aware Design, Human-Centered Decomposition, Org-Level Diffusion을 모두 보존하는 기준이다. 세 조건 중 하나를 희생한 뒤 클릭 수만 줄였다고 성공을 선언하지 않는다.

최적화 대상은 버튼 개수가 아니라 사용자의 반복 조작, 화면 왕복, 맥락 재설명, 결과 판단 시간, 실패 후 재작업과 다른 사람이 이어받는 비용이다. AI에게 맡긴 뒤 사용량과 지연이 크게 늘어나는 것도 별도로 측정한다.

## 2. 네 원칙을 제품 동작으로 옮긴다

| 원문 원칙 | 사용자가 보는 동작 | 내부에서 유지할 것 | 실패하는 설계 |
|---|---|---|---|
| Step Awareness | 현재 하는 일 한 줄, 결과와 필요한 다음 행동 | 단계별 목적·입출력·완료 조건·의존 관계·복구 지점 | 단계마다 ‘다음’을 누르게 하거나 무한 스피너만 표시 |
| Change-Aware Design | 막힌 단계에서 담당 AI·기기·자료를 바꿔 재개 | 제공자와 역할의 분리, 입력 판 고정, 변경 영향과 무효화 범위 | 모델 교체·기기 단절 때 전체 작업을 처음부터 다시 수행 |
| Human-Centered Decomposition | 원문·변경·근거를 보고 적용/수정/거절, 언제든 중단 | 목적·판단권·권한 범위, 의미 있는 결정 지점과 되돌리기 | 모든 행동에 승인창을 띄우거나 모든 결정을 자동화 |
| Org-Level Diffusion | ‘이 방식 다시 쓰기’로 입력만 바꾸어 실행; 역할별 안내 | 버전 있는 작업방식, 예시, 완료 기준, 책임·복구법·변경 이력 | 만든 사람의 프롬프트와 개인 기억이 없으면 사용 불가 |

기기 간 동기화와 세션 간 전달은 네 번째 원칙의 일부 기반이다. 그것만으로 조직 확산을 충족했다고 할 수 없다. 다른 사람이 실제로 실행하고 수정하며 문제를 찾을 수 있어야 한다. 1인 사용에서도 미래의 나와 다른 전문 역할의 작업 방식을 수용하도록 설계한다.

## 3. 기본 화면의 상시 요소

1. 상단의 ‘작업’ 버튼: 폴더·최근 작업·검색·선택형 보드로 들어가는 공통 입구.
2. 현재 작업 제목과 상태 한 줄: 예를 들어 ‘문서 수정 중 · Claude · 연구실’. 활동 위치와 담당자는 숨기지 않되 기기 목록을 펼쳐 놓지 않는다.
3. 하나의 주 화면: 현재 대화 또는 현재 문서. 동시에 두 작업 면을 강제로 나누지 않는다.
4. 하나의 입력창: 현재 작업에 요청하거나 수신 세션을 골라 보낸다.
5. ‘확인 1’: 사용자의 판단이 실제 필요한 항목만 모으는 입구. 일반 완료 알림은 조용히 남긴다.

‘확인’ 표시가 떠도 사용자의 입력 중 포커스를 빼앗지 않는다. 알림은 작업별로 묶고, 결정한 항목은 즉시 제거한다. 긴급하고 복구 불가능한 상태를 제외한 일반 진행 갱신이 모달을 띄우거나 스크롤 위치를 바꾸지 않는다.

전체 작업 보드는 선택적으로 열어 보는 보기다. 앱 시작 때마다 대시보드에서 작업을 찾아 들어가는 단계를 추가하지 않는다. 기본 재개 지점은 마지막으로 사용한 작업과 문서 위치다.

## 4. 같은 화면의 다섯 상태

| 상태 | 진입 | 표시 | 복귀와 보존 |
|---|---|---|---|
| 작업 진행 | 작업 열기 | 대화·결과·간결한 전달/회신 기록 | 초안·스크롤·수신자 선택 유지 |
| 다른 세션에 보내기 | 메시지의 보내기 / 입력창의 보내기 / @ | 수신자 선택 팝오버, 전달 대상 문서/범위, 회신 위치 | 현재 작업을 떠나지 않고 요청 기록으로 접힘 |
| 문서 보기·편집 | 결과 파일 열기 | 문서가 현재 면을 채움; 선택 부분에 AI 제안 표시 | 대화로 돌아오면 이전 위치, 문서는 편집 상태 유지 |
| 작업 찾기 | 상단 작업 / 검색 단축키 | 최근·폴더·보드를 같은 면에서 선택 | 작업을 고르면 탐색 화면 닫힘 |
| 진행 확인·복구 | 상태 한 줄 / 진행 보기 | 단계별 완료와 현재 예외; 현재 단계만 상세 | 완료한 단계 보존, 선택한 재개 지점 표시 |

팝오버는 한 번에 하나만 연다. 팝오버 위에 또 다른 팝오버를 쌓지 않는다. 닫기와 Esc, 뒤로 가기를 일관되게 제공한다. 탐색 화면과 작업 면은 분할하지 않는다. 키보드 단축키는 보조 수단이고 모든 주요 동작은 보이는 텍스트 버튼으로도 접근한다.

기능을 숨기는 것만으로 단순화하지 않는다. 반복 조작은 서비스가 처리하고, 꼭 필요한 조작에는 이름 있는 입구를 남긴다. 아무것도 없는 채팅창에 모든 기능을 자연어로 찾아 쓰게 만드는 방식은 피한다.

## 5. 세션 사이 메시지의 구체적 사용법

예: 강의 자료를 작성하는 Claude 대화에서 현재 HWPX의 인용 검토를 연구실 Codex 세션에 맡긴다.

- 사용자는 결과의 ‘보내기’를 누르고 ‘자료 검토 · Codex · 연구실’을 선택한다.
- 요청은 ‘이 문서의 인용 근거를 확인해줘’. 현재 문서의 정확한 판과 선택된 근거가 함께 붙는다. 기본 범위를 읽을 수 있고 필요할 때 바꿀 수 있다.
- ‘보내기’를 누르면 해당 세션으로 요청하고, 현재 면에는 ‘자료 검토 세션에 요청함’이라는 접힌 기록이 남는다.
- 회신은 원래 작업에 들어온다. 다른 창으로 가서 답을 복사해 오지 않는다.
- 후속 질문은 그 회신의 ‘답장’으로 이어가며, 원래 수신 세션과 질문 연결을 유지한다.

입력창에서 @자료검토로 동일 동작을 할 수 있다. @는 숨겨진 필수 문법이 아니라 빠른 대안이다. 수신자 선택에는 작업 이름·세션 별칭·실제 AI·실행 기기·현재 상태가 함께 있어 동명이인을 구분한다. 사용자가 정확한 native 세션을 지정할 수 있고, 작업의 역할을 지정하면 현재 연결된 세션을 표시한다.

‘검토 요청’과 ‘작업 맡기기’는 다르다. 검토 요청의 기본은 결과에 대한 의견 회신이고 파일 쓰기를 자동 부여하지 않는다. 작업 맡기기는 범위와 결과 위치를 명확히 한다. 사람이 선택한 범위 안에서 실행하도록 하며, 기존 승인된 반복 방식에 불필요한 확인을 추가하지 않는다.

자동 회신은 요청된 왕복에 포함된다. 후속 자율 토론·반복 검토·다른 작업의 쓰기 권한은 자동 확장하지 않는다. 기본 왕복이 끝나면 종료하고, 사용자가 지정한 반복 한도와 종료 기준이 있을 때만 더 진행한다.

전달 계약: requestId, workId, sourceSession, targetSession/role, question, attachmentRefs+revisions, replyTo, authorityScope, deadline/cancellation, attempt status. 이는 내부 데이터이며 사용자에게 UUID 폼을 입력시키지 않는다.

대기 중·전달됨·처리 중·회신·전달 확인 불가를 구별한다. 네트워크가 끊겨 응답을 못 받았다고 곧바로 같은 지시를 다시 실행하지 않는다. 로컬 수신기는 requestId로 중복을 걸러내고 처리 상태를 조회한다. 외부 어댑터가 실행 확인을 못 제공하면 ‘확인 불가’를 남기고 자동 재전송을 막는다.

수신 세션이 이미 작업 중이면 기본적으로 다음 입력 가능한 지점까지 대기한다. 강제 끼어들기는 명시적으로 선택한다. 승인 입력을 기다리는 세션에 일반 요청을 키 입력으로 던지지 않는다. 같은 문서에 두 작성자가 동시에 쓰지 않게 하고 검토자는 고정된 판을 읽는다.

Herdr의 공식 agent.prompt/wait, 이벤트 구독과 입력 API는 실행 어댑터 후보다. 이 API가 위와 같은 업무 의미·문서 판·회신 연결까지 자동 제공하는 것은 아니다. Herdr를 채택해도 이 계약은 Achmage 층에서 유지한다. 이번 작업에서는 설치나 실제 세션 메시지 발송을 하지 않았다.

## 6. 한 대화처럼 보여도 세션을 섞지 않는다

공통 화면은 작업에 대한 사용자용 기록이다. 각 제공자의 실제 대화는 독립적으로 유지한다. A와 B가 같은 전체 기억을 갖는다고 가정하지 않는다.

현재 대화 면에는 사용자가 보낸 요청, 주요 결과, 전달 기록, 회신과 중요한 결정만 모인다. 원래 세션의 메시지는 출처 링크로 열 수 있고, 같은 work에서 여러 세션을 전환할 수 있다. 다른 작업에서 온 회신도 보낸 작업과 세션이 표시된다.

같은 작업이라는 이유로 전체 채팅 기록을 모두에게 계속 복제하지 않는다. 수신자에게는 질문과 선택한 맥락, 필요한 문서 판만 보낸다. 화면을 단순하게 보이게 하려고 매 갱신마다 별도의 LLM 요약을 실행하지 않는다. 전달 영수증과 상태는 구조화 이벤트로 만든다.

## 7. 크로스 디바이스는 두 동작을 구분한다

A. 다른 기기에서 같은 실행 보기: 연구실에서 실행 중인 작업을 노트북·모바일이 원격으로 관찰하고 조작한다. 실행 프로세스는 연구실에 남는다. 이것이 기본이다.

B. 다른 기기에서 재개하기: 해당 실행이 끊겼거나 이동이 필요할 때, 필요한 파일·정확한 판·맥락·완료 상태를 확인하고 지원되는 방식으로 새 실행을 연다. 기존 프로세스의 이동으로 표현하지 않는다.

현재 실행 기기는 상태 한 줄과 수신자 선택에 보인다. 모든 기기의 연결 상태를 기본 화면에 고정하지 않는다. 오프라인·로그인 필요·요청 미수신은 관련 동작 옆에 즉시 표시한다.

사람이 편집 중인 초안과 커서 위치는 잃지 않는다. 원격 쓰기는 문서 revision·편집 소유자 기준으로 검증한다. 연결이 끊긴 기기는 캐시된 기록을 볼 수 있으나 제어 성공을 표시하지 않는다. 동기화 충돌과 아직 서버에 확인되지 않은 수정은 별도 상태다.

공식 Codex/Claude 모바일 페어링을 임의로 승계할 수 있다고 가정하지 않는다. 독립 앱은 제공되는 인증·원격 인터페이스별로 연결 범위를 검증한다.

## 8. 문서 중심 사용도 같은 구성에서 해결한다

파일을 열면 문서가 주 화면을 차지한다. 대화 입력은 하단의 얇은 요청창으로 남는다. 문단을 선택하면 요청 범위가 그 선택으로 제한되고, 제안은 해당 위치에 표시된다. 사용자가 문서를 읽는 동안 다른 세션은 계속 진행한다.

한글 HWPX·PDF·Markdown은 각각 맞는 뷰어/편집 어댑터를 사용한다. HOP/RHWP와 PDFCraft의 기존 엔진을 재사용할 후보로 유지한다. 화면 디자인이 모든 문서 형식의 편집 지원을 의미하지 않는다.

AI 제안은 제안 당시 문서 판과 선택 구간을 보존한다. 사용자가 그 뒤 문서를 바꾸면 오래된 제안을 즉시 덮어쓰지 않고 재검증한다. 적용·되돌리기·저장·재열기·한국어 IME가 기본 검증 범위다. 원문·인용 페이지·글꼴 대체 문제는 필요한 위치에서 드러낸다.

두 문서를 실제로 대조할 때는 탭 전환 또는 일시 비교를 선택할 수 있다. 분할화면은 사용자가 필요할 때만 켜는 후순위 기능이다.

## 9. Human·Wiki·OS·Research는 화면 메뉴보다 작업의 기반이다

작업을 시작할 때 관련 원문과 과거 결정을 회수하고 필요한 범위만 연결한다. 네 저장소의 카드를 매번 사용자가 하나씩 고르는 절차는 기본에서 제거한다. 기존 승인된 범위와 작업 목적이 명확할 때 자동 선택하고, ‘참고한 근거 4개’에서 이름·이유·읽은 범위·판·제외 기능을 제공한다.

- Human: 사용자의 목적, 관점, 이유. 원문 불변.
- Wiki: 이어갈 맥락과 이전 판단. 파생 기억과 원문을 구분.
- OS: 승인된 방법. 후보·초안은 자동 활성화하지 않음.
- Research: 왜 그 판단을 했는지, 실패 조건과 미확인, 정확한 연구 판.
- GitHub/파일: 실제 코드·문서 결과. 정본과 파생 파일을 구분.

자료 회수와 적용할 권한은 다르다. 과거 기록 속 ‘실행해’는 현재 권한으로 쓰지 않는다. 기본 회수 결과가 새 목적과 충돌하면 현재 명시 요청이 우선한다.

종료 시 불필요한 노트를 양산하지 않는다. 재개에 필요한 기록을 남기고 새 통찰·반복 방법이 있을 때만 제안한다. 사용자가 선언한 ‘코드는 GitHub, 이유와 배움은 Human, 맥락은 Wiki, 반복 방법은 OS’의 역할 분리를 유지한다. 공간 비우기는 보관과 복원이 확인된 별도 계약이며 화면을 닫는 순간 파일이나 프로세스를 삭제하지 않는다.

## 10. 다른 사람도 쓸 수 있는 작업방식

‘강의 자료 다듬기 v3’는 예시다. 다음을 버전 있는 작은 작업방식으로 보존한다.

- 목적과 완료 기준
- 필요한 자료와 입력 예시
- 작성·검토·결정 역할 및 기본 담당 연결
- 필수 판단 지점과 자동으로 이어갈 범위
- 단계별 결과, 실패 시 복구법
- 실제 확인한 환경·어댑터·문서 지원 범위
- 변경 이력과 이전 판으로 돌아갈 방법

Codex/Claude 또는 Windows/Linux 이름을 모든 단계에 박아두지 않고 역할별 필요 능력을 선언한다. 실행 시 실제 담당과 기기를 연결한다. 실행 중에는 선택한 판을 고정하고, 새로운 판이 나와도 중간 실행을 조용히 바꾸지 않는다.

‘이 방식 다시 쓰기’는 다음 입력을 고르는 작은 양식으로 시작한다. 실행 방법을 모르는 사람에게 전문가 프롬프트를 요구하지 않는다. 공유·게시·조직 배포는 별도 명시 범위를 따른다. 이 설계 자체가 조직 확산 효과를 검증한 것은 아니다.

## 11. 단순한 화면을 가능하게 하는 내부 계약

단일 거대 에이전트가 모든 클릭을 해석하는 구조로 만들지 않는다.

- GUI가 work·folder·document·request·run 상태를 결정적 서비스로 읽고 쓴다.
- 세션 어댑터가 각 도구의 실제 기능을 확인한다: 읽기/입력/중단/재개/쓰기/상태.
- 의미 검색·계획·작성·검토에만 필요한 AI를 사용한다.
- 단계 결과와 입력 판을 보존해 바뀐 단계만 다시 수행한다.
- 상태 이벤트는 작업별로 묶되, 복구와 감사에 필요한 실제 기록은 버리지 않는다.
- 재전송·중복 클릭·재접속에 대해 요청 식별자와 확인 가능한 처리 상태를 유지한다.

작업 조작 자체의 모델 호출은 0회를 목표로 한다. 근거를 회수하는 의미 검색과 생성은 별도 사용량이다. 작동하는 모델이나 계정이 바뀌어 비용이 달라지면 숨기지 않는다.

한 화면이라는 이유만으로 RAM이 줄지는 않는다. 닫힌 문서의 렌더러·페이지 캐시를 제한하고, 비활성 작업의 UI 인스턴스는 해제하되 실행 중인 작업은 별도 수명으로 관리한다. 단순 화면에서 보이지 않는 CLI 20개가 계속 상주하면 경량화가 아니다. 중단·종료는 실행 소유자가 관리하며 다른 앱의 프로세스를 임의로 종료하지 않는다.

## 12. 이번 제안의 수용 기준

실제 구현 후 아래 동일 목적의 왕복으로 평가한다. 아직 측정하지 않았으므로 숫자 개선을 주장하지 않는다.

| 시나리오 | 검증할 결과 |
|---|---|
| 현재 문서를 다른 세션에 검토 요청 | 작업 화면 왕복·내용 복사 없이 수신자 식별과 전달 범위 확인 가능 |
| 바쁜 세션으로 메시지 보내기 | 현재 실행을 오염시키지 않고 대기 상태와 회신 연결 보존 |
| 두 세션 이름이 같음 | 작업·AI·기기로 구분하고 잘못된 대상에 조용히 전송하지 않음 |
| 모바일→노트북 이동 | 같은 폴더와 work, 마지막 작업 위치, 실제 실행 호스트가 일치 |
| 연구실 연결 단절 | 완료한 문서 유지, 대기/미수신을 구분, 다른 기기 재개 시 중복 쓰기 방지 |
| AI 제안 후 사람이 수정 | 오래된 제안을 덮어쓰지 않음; 되돌리기와 저장 결과 보존 |
| 업무 목적이 중간에 바뀜 | 바뀐 단계와 영향 받은 후속 결과만 재검토 |
| 같은 방식으로 다음 강의 제작 | 이전 프롬프트 복사 없이 입력 교체, 정확한 방식 판과 완료 기준 표시 |
| 다른 사람이 이어받음 | 만든 사람에게 설명을 요구하지 않고 목적·입력·진행·문제·복구법 파악 |
| 폴더·상태·원문 탐색 | 모델 호출 없이 동작하며 한글 입력·포커스·키보드 접근 유지 |

조작 수와 함께 맥락 전환 횟수, 재설명 분량, 다음 행동을 찾는 시간, 놓친 확인, 오발송, 복구 후 중복 작업, 전체 RAM과 모델 호출을 기록한다. 측정 단위와 참여자 범위를 전후 동일하게 유지한다.

## 13. 만들 순서

첫 수직 시제품은 ‘기존 작업 열기 → 문서/대화 전환 → 다른 세션에 검토 요청 → 같은 작업으로 회신 → 연결 단절 후 재개’다. 이것이 단순하고 신뢰할 수 있게 동작하는지 확인한다. 이후 같은 계약에 근거 회수·폴더·작업방식 재사용을 붙인다.

기존 Achmage 서비스와 work 계약을 보존한다. UI를 단순화한다는 이유로 지식 시스템이나 런타임을 전부 다시 쓰지 않는다. 기본 앱 기반은 이전 제안처럼 얇은 GUI이며, Orca는 실제 사용 기준선, Herdr는 선택 가능한 실행 어댑터다. 최종 프레임워크와 저메모리 우승자는 실측 전 확정하지 않는다.
