# 모바일 연결과 공통 편집 상태 v3

2026-10-16 · 설계 제안 · 구현/구독 인증 E2E/RAM 실측 미완료

## 핵심 결정

개인용 첫 버전은 연구실 실행 서비스 + 반응형 웹/PWA + Tailscale Serve로 제안한다. PC와 휴대폰이 같은 작업 상태에 접속한다. Hermes는 필요할 때 붙이는 별도 작업자와 메신저 입구다.

사용자의 핵심 조건은 채팅 안에서 사람이 고친 내용이 다음 AI 작업의 기준이 되어 재전달·재검수 부담을 줄이는 것이다. 편집기 임베딩이나 자동 저장만으로 이 조건을 충족했다고 보지 않는다.

## 연결 구성과 최소 사용자 동선

PC 브라우저와 모바일 PWA → Tailscale HTTPS → 작업실 서비스 → Codex app-server / Claude Code adapter / Achmage 서비스.

초기 설정에서 PC와 휴대폰을 같은 tailnet에 등록한다. PC의 ‘모바일에서 열기’ QR로 HTTPS 주소를 열고 홈 화면에 추가한다. 별도 앱 기기 승인이 필요하면 짧은 만료와 일회성 교환을 사용하며 계정 토큰을 QR에 넣지 않는다. 네트워크 연결은 Tailscale, 작업 접근 권한과 재접속은 앱의 책임이다.

서버가 실행의 수명을 관리한다. 모바일 브라우저를 닫아도 실행이 유지되도록 설계하고, 재접속 때 마지막 이벤트 이후를 이어받는다. 요청 ID로 재전송 중복 실행을 막는다. 실행 PC가 꺼지거나 잠들면 작업이 계속된다고 표시하지 않는다. 휴대폰 오프라인 편집은 로컬 초안으로 남기고, 서버 반영 전에 AI 전달 완료로 표시하지 않는다.

첫 버전은 한 호스트로 검증한다. 이후 연구실 Windows와 Linux 노트북을 각각 실행 노드로 등록하고 작업에 hostId를 보존한다. 같은 work라도 실제 파일이 있는 호스트의 확인된 revision을 입력으로 사용한다. Dropbox 파일 도착과 실행 준비를 동일 상태로 간주하지 않는다.

## 제공자 탭

작업은 공통 workId, 각 Claude/Codex 세션은 provider + hostId + nativeSessionId로 식별한다. [+]에서 제공자를 선택하며 작업·문서·실행 위치를 기본으로 이어받는다. 탭이 많아도 모든 에이전트를 상시 실행하지 않는다.

Claude에서 Codex로 넘길 때 동일한 대화 엔진으로 변환하지 않는다. 목적, 확정 입력 문서 판, 사람이 바꾼 점, 남은 질문, 결과 회수 위치를 새 native session에 전달한다. 기존 공식 앱에 열린 모든 세션을 자동 제어할 수 있다고 가정하지 않는다. 먼저 이 앱이 생성한 세션을 확실히 관리하고 기존 세션 가져오기/재개는 별도로 검증한다.

계정 한도와 개별 세션 토큰 사용량을 분리한다. 공식 인터페이스가 제공하는 수치만 최신 시각과 함께 표시하며, 확인 불가를 0%로 보이지 않는다. 구독 한도와 API 과금 모드는 명시적으로 구분한다. 최초에는 사용자가 새 탭에서 선택하고, 실행 중 조용한 제공자 교체나 유료 API 전환은 하지 않는다.

## 편집에서 AI까지의 계약

1. 하나의 문서에 artifactId를 부여하고 저장마다 확정 revision과 콘텐츠 해시를 남긴다. 세션마다 별도 첨부 사본이 늘어나는 구조를 피한다.
2. 사용자가 요청을 보내면 편집기의 입력 조합과 미저장 변경을 먼저 확정하고 서버 저장 응답을 기다린다. 저장이 실패하면 그 문서를 사용하는 실행만 보류하고 입력을 보존한다.
3. 실행 전에 해당 판을 도구가 읽을 파일과 필요한 구조화 추출물에 반영한다. 추출물에도 원본 revision을 연결한다. 새 지시에는 입력 판과 관련 변경을 포함하고 필요한 원문을 읽도록 한다. 긴 문서를 매 키 입력마다 모델에 재전송하지 않는다.
4. 실행은 baseRevision을 기록한다. 이미 실행 중인 모델의 과거 문맥이 자동 수정된다고 가정하지 않는다. 문서가 다시 바뀌면 결과 적용 전 차이를 확인하고, 필요할 때 영향받은 부분만 다시 작업한다.
5. AI 수정은 제안 패치/산출물로 받는다. 적용 직전 현재 판과 baseRevision을 비교한다. 사람이 바꾼 내용과 충돌하면 덮어쓰지 않고 해당 부분만 제시한다. 외부 CLI의 직접 파일 쓰기도 감시만으로 안전하다고 간주하지 않고 작업 사본/격리 경로와 적용 단계를 둔다.
6. 다른 세션에 보낼 때 경로만 보내지 않고 확정 판과 접근 가능한 콘텐츠를 함께 연결한다. 수신 측 준비가 끝나야 전달 완료로 표시한다.
7. 화면에는 평소 ‘저장됨’ 정도로 간단히 표시하고, 다음 실행 시 ‘수정본으로 시작’과 같이 사실에 맞는 짧은 상태를 사용한다. 저장됨, AI 입력 준비됨, AI가 검토 완료함은 서로 다른 사실이다.

AI가 문서를 읽었다고 기록하는 것은 이해와 정답을 보증하지 않는다. 목적은 낡은 판·누락·덮어쓰기 때문에 사람이 반복 검수하는 부담을 앱이 제거하는 것이다. 내용에 대한 최종 판단은 남는다.

Markdown은 내용과 변경 비교부터 검증한다. HWPX는 텍스트뿐 아니라 표·스타일·레이아웃 등 문서 구조를 포함하므로 일반 텍스트 병합과 동일하게 취급하지 않는다. PDF 주석, OCR 추출, 원본 내용 편집도 구분한다. 모바일의 복잡한 HWPX 편집과 글꼴·IME 재현성은 별도 실기 검증 대상이다. 형식별 도구 계약이 만족되지 않으면 읽기/검토로 기능 범위를 정직하게 제한한다.

Human·Wiki·OS·Research는 work의 출처와 결과로 연결하되, 문서 편집 동기화를 이유로 Human 원본 메타데이터를 재작성하거나 OS 후보를 자동 활성화하지 않는다.

## 현재 공식 문서에서 확인한 범위

- Codex: app-server는 자체 rich client 통합과 thread/turn/auth/rateLimits 인터페이스를 제공한다. 초기 연결은 로컬 stdio와 자체 웹 게이트웨이를 권고한다. 실험적인 원격 WebSocket을 그대로 외부에 노출하는 구조를 기본으로 삼지 않는다. 로컬 개인 앱 인증과 상용/hosted 배포 인증의 범위는 구별해야 한다.
- Claude: 2026-10-07 Help Center 업데이트에 따르면 SDK, claude -p, third-party app 사용은 계속 구독 한도를 사용할 수 있다. 수정하지 않은 공식 실행 파일과 본인 공식 로그인 흐름을 사용한다. 앱이 Claude 로그인 자격증명을 직접 수집·중계하는 설계와 구분한다. 실제 설치 버전의 SDK/CLI 인증과 승인 처리는 기능 검증이 필요하다.
- Claude Remote Control: 공식 모바일/웹에서 로컬 세션에 접속하는 기능이다. 그 페어링을 자체 앱 내부로 그대로 가져올 수 있는 공개 인터페이스라고 간주하지 않는다.
- Tailscale Serve: tailnet 내부 웹 서비스 접근과 HTTPS를 맡는다. Funnel은 공개 노출이므로 개인 첫 버전의 기본이 아니다.
- Hermes: agent/gateway/dashboard가 있으므로 단순 메신저만 있는 제품으로 설명하지 않는다. 다만 자체 문서 편집 상태, Claude/Codex native session, 실행 수명 계약까지 대신해 주는 것으로 가정하지 않는다.

구독 인증 지원이 무제한 사용이나 추가 비용 부재를 뜻하지 않는다. 계정의 한도, 선택된 인증·과금 경로, 향후 정책 변경을 별도로 다룬다.

## 검증 순서

첫 번째 기능 검증은 두 제공자의 본인 구독 인증, 스트리밍, 승인, 재개를 최소 UI에서 확인한다. 동시에 Markdown 한 문서로 편집→확정→다음 AI 입력→다른 제공자 검토→결과 회수를 검증한다.

필수 재현 사례:
- 직접 고친 문장을 재첨부 없이 다음 요청이 사용한다.
- AI 실행 중 사람이 다시 수정하면 결과가 사람의 수정본을 덮어쓰지 않는다.
- 모바일 저장 직후 PC 또는 다른 세션에서 요청해도 같은 확정 판을 사용한다.
- 휴대폰 탭 종료/네트워크 단절 뒤 결과·승인·편집 위치를 복원한다.
- 재접속 요청이 같은 AI 실행을 두 번 만들지 않는다.
- 저장/추출/전달 실패를 완료로 표시하지 않는다.

이후 HWPX와 PDF를 형식별로 추가하고 Linux 실행 노드 및 데스크톱 패키징을 검토한다. RAM 목표 수치는 실제 두 공식 앱 대비 idle/active 문서/다중 세션 측정 후 정한다. PWA는 자체 Electron 번들을 줄일 수 있는 선택이지만 브라우저·에이전트·문서 엔진 메모리는 여전히 사용한다.
