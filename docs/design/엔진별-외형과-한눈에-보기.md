# 엔진별 외형 · 한눈에 보기 · 자동 제목 · 대화 층위

2026-10-16 · PRD v1.0 보완 설계. 사용자 요청: Orca처럼 전부 같은 모양이고 탭 이름(`Claude Chat`, `Codex Chat`)으로만 구분하면 세션이 많아질수록 무엇이 어디서 진행 중인지 읽히지 않는다.

## 1. 엔진별 외형(룩) — 2 엔진 × 라이트/다크 = 4가지

| 룩 | 시작 세트 | 성격 |
|---|---|---|
| Codex · 라이트 | Achmage 볼트 Minimal 라이트 (흰 바탕, #005BAC, 청록 #00ADA9, 남색 코드 #193664) | 볼트 라이트 그대로 |
| Codex · 다크 | 새로 만든 미드나이트 (남흑 #070B14, 하늘 #5AA9F0, 청록) | 라이트의 청색 계열을 밤으로 |
| Claude · 다크 | Achmage 볼트 Minimal 다크 + CMDS Operator Console (#08090A, 핑크 #F27AA4) | 볼트 다크 그대로 |
| Claude · 라이트 | 새로 만든 종이·점토 (#FAF9F5, #C96442) | 따뜻한 바탕 |

- 지금 보고 있는 세션의 엔진 룩이 창 전체(상단·사이드바·대화·입력창)를 입는다. 시작 화면에서는 고른 엔진의 룩.
- 한 룩 = 색 13가지(배경, 입력창·카드, 본문, 보조, 선, 엔진 색, 빛 보조색, 제목, 작은 제목, 굵은 글씨, 링크, 코드 배경·글자) + 글꼴·크기·줄 간격·굵기 + 말풍선(채움/옅게/레일) + 입력창 모서리·테두리 + 빛 효과 + 쉬는 동안의 엔진 색 테두리.
- 엔진마다 "앱 화면 따르기 / 항상 라이트 / 항상 다크".
- 바꾸는 곳: 오른쪽 클릭(빠른 메뉴: 엔진 색·배경·글자 크기·말풍선), ⋯ → 외형 설정(옆 패널, 바꾸는 즉시 실제 화면에 미리 보임, 4개 룩 카드, 다른 화면·다른 엔진 값 가져오기, 기본값).
- 설정은 게이트웨이 DB에 저장(`PUT /api/prefs`, `prefs.updated`). 창 저장소는 첫 화면 깜빡임 방지용 사본만.
- 기본 글꼴은 사용자가 만든 **Achmage SameTone 1.000** (가변 100–900, OFL). 앱에 WOFF2와 OFL·NOTICE·licenses를 함께 넣고, 설치된 사본이 있으면 그것을 먼저 쓴다.

### 분할 화면 대비

PRD는 분할 화면을 기본으로 열지 않고 "필요할 때만 켜는 후순위 기능"으로 둔다. 엔진별 룩은 분할 화면에서 가치가 커지므로, 룩은 문서 전체가 아니라 `.look-scope` 요소 단위 토큰으로 만들었다(테마·말풍선·테두리 차이도 하위 선택자가 아니라 그 요소에 설정되는 토큰). 패널 하나가 다른 룩을 가져도 안쪽에 그대로 들어갈 수 있다. 분할 화면 자체(끌어서 나누기, 2분할까지, 입력창 하나가 초점 패널을 대상으로)는 단계 C 후보로 남긴다.

## 2. 한눈에 보기 (Ctrl+K)

탭 순서가 아니라 "나에게 필요한 것" 순서로 모든 작업의 세션을 본다.

- 세 줄: **내 확인이 필요해요**(승인 대기) · **진행 중** · **최근**(새 답이 먼저).
- 카드 하나가 그 세션 엔진의 룩을 입는다(카드 자체가 `.look-scope`). 글을 읽기 전에 색·표시로 Claude/Codex가 갈린다.
- 카드: 엔진·모델, 상태(진행 중이면 현재 활동), 작업 제목, 세션 제목, 마지막 답의 앞부분(진행 중이면 활동), 시각, 폴더 경로, "새 답".
- 검색(작업·세션·답 내용), ↑↓·Enter·Esc.
- 상단 "한눈에" 버튼에 진행 중 수와 새 답 수.
- **Ctrl+Tab**: 최근 본 순서의 세션 카드가 뜨고, Ctrl을 놓으면 연다(Alt+Tab처럼).
- 세션 탭은 활성 + 최근·진행 중 4개까지만, 나머지는 `+N`(이 작업만 걸러 한눈에 보기). 안 본 답은 탭·사이드바·카드에 점.

PRD 2.4의 "보드 보기는 후속 단계"를 사용자 요청으로 앞당겼다.

## 3. 자동 제목 — 모델 호출 없이

ChatGPT·Codex처럼 첫 요청으로 제목을 붙이되, 대화가 쌓이면 **전체를 관통하는 핵심**을 따라 바뀐다. AI가 대화를 읽어 제목을 다시 짓는 방식이 아니며 토큰을 쓰지 않는다(`apps/host/src/titles.ts`).

1. 요청을 문장·낱말로 나누고 한국어 조사(을/를/에서/으로…)와 요청 어미(해줘/하자…)를 떼어 내용어만 남긴다. "정리해줘"는 행위 명사 "정리"로 남는다. 한 음절 명사는 받침과 조사가 맞을 때만(탭이 → 탭).
2. 여러 요청에 걸쳐 나온 낱말일수록 점수가 높다(한 요청 안 반복은 조금만). 첫 요청과 최근 요청에 약간의 가산.
3. 두 번 이상 나온 핵심어가 둘 미만이면 첫 요청의 중심 문장을 명사구로("미디어 리터러시 과목 업데이트 계획을 세워보자" → "미디어 리터러시 과목 업데이트 계획").
4. 핵심어가 있으면 그것을 가장 많이 담은 문장에서 핵심어와 "같이 반복된 짝 낱말"만 남겨 제목으로.
5. 새 제목이 지금 제목보다 확실히(1.3배 + 여유) 높을 때만 바꾼다. 지나가는 화제로는 안 바뀐다.
6. 직접 이름을 바꾸면 고정, 이름을 비우면 다시 자동. 작업 제목도 그 작업의 모든 세션 요청으로 같은 규칙.

예: "회의록 정리" → (수업 계획서 요청이 이어지면) "수업 계획서".

## 4. 대화의 세 층위

멀리서도 "내 요청 / AI의 답 / AI의 작업 기록"이 갈리도록:

- **요청**: 턴마다 번호·시각(`③ 요청 · 14:02`)과 엔진 색 말풍선, 턴 사이 구분선.
- **답**: 본문 글꼴·크기(룩 설정).
- **작업 기록**: 작고 흐린 띠(왼쪽 회색 선, 옅은 바탕). 펼치면 명령·파일·도구 목록.
- 턴 끝: `✓ 끝남 · 46초` / 중단·실패는 경고색.
- 긴 답을 읽는 동안 그 턴의 요청이 위에 한 줄로 붙어 있다(누르면 그 요청으로).
- 오른쪽 **턴 레일**: 요청마다 눈금, 승인 대기는 주황, 지금 위치 강조, 보이는 범위 음영. 눌러서 이동.
- 레일 모드(다크 기본)에서는 요청 카드를 더 진하게, 답 카드는 중립으로 해 두 카드가 같아 보이지 않게 했다.
