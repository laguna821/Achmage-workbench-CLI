# 설계 목적과 범위

## 목적

프로젝트 안에서 사람이 문서를 만들고 편집하는 동안 여러 AI에게 독립 작업을 맡기고, 결과를 같은 맥락으로 이어 쓰는 앱을 만든다. 핵심 행동의 진입점과 현재 작업 대상을 분명하게 보여주는 것이 개편의 목적이다. `design-principles/purpose/create-value` [HIG transfer]

대상은 한국어 문서·연구·코딩 작업을 장시간 수행하는 사용자다. Windows·macOS·Linux의 Tauri/WebView 데스크톱 UI가 대상이며, macOS 전용 SwiftUI 앱으로 바꾸는 계획은 아니다. 좁은 창·확대·키보드 사용을 포함한다. 새로운 모바일 제품 설계는 이번 범위가 아니다. [House]

## 전면 개편의 범위

| 구분 | 포함 |
|---|---|
| 앱 셸 | 창 안 탐색, 상단 작업 탭, 도구 모음(toolbar), 분할 보기(split view), 패널 표시 정책 |
| 공통 UI | 버튼·목록·메뉴·팝오버·시트·확인창·검색·알림·빈 상태·오류·키보드 초점 |
| 작업 UI | 메인/문서 AI 대화, 모델·권한·첨부, 실행/승인/수정안/완료 표시 |
| 프로젝트·자료 | 개요/YAML, 프로젝트 노트, 썸네일·템플릿, 폴더, Bases식 보기, 그래프, 볼트 |
| 편집기 | 문서 공통 셸과 내장 이음오피스의 형식별 내부 도구 모음·메뉴·AI·대화상자 |
| 개발·운영 화면 | 터미널, worktree, 변경 비교·충돌·GitHub, 연결·설정·온보딩·보관/삭제 |
| 새 웹 경험 | 앞선 Aside 설계의 화면·상태·패널 계약. 실제 렌더러 연결은 해당 기능 계획에 종속 |

편집 엔진·파일 형식·AI 공급자 프로토콜·host 저장소를 새로 만드는 것은 프론트엔드 개편의 선행 조건이 아니다. 필요한 UI 계약만 기존 명령과 상태에 연결한다. 기존 기능을 감추거나 제거해 간결해 보이게 만드는 것은 완료로 인정하지 않는다. [Engineering]

## 반드시 이어갈 사용자 경험

1. 프로젝트 이름 클릭은 바로 개요·메타데이터로 이동한다. 프로젝트·폴더·대화·문서는 이름과 아이콘/종류로 구분한다.
2. `새로 만들기`와 우클릭으로 AI 없이 새 문서·폴더·세션을 만들 수 있다.
3. 문서 탭은 기본적으로 편집에 집중한다. 메인 탭으로 돌아오면 메인 탐색과 입력이 돌아온다.
4. 문서별 AI는 메인 세션과 독립 실행하며, 탭 전환·분할·크기 변경이 작업을 끊지 않는다.
5. 부모 세션은 자식의 진행·결과를 알 수 있고 자체 요청도 계속 처리한다.
6. Ctrl+K에서 사용자 원문 프롬프트·대화·문서·볼트를 찾고 정확한 위치를 연다.
7. 볼트의 읽기 전용 표시·뒤로/앞으로·상위 폴더 이동과 나란히 보기를 유지한다.
8. 이음오피스 별도 설치·앱으로 열기·같은 파일 저장·복귀·최신 맥락 반영을 유지한다. 연결 설정은 Dropbox 중심의 기존 요구를 따른다.
9. 모델 목록·프로젝트 삭제·완료 알림처럼 이미 추가한 기능을 새로운 메뉴에서 찾을 수 있다.

위 항목은 사용자 요구에 따른 제품 계약 [House]다. HIG의 맥락 보존과 자유로운 이동 원칙이 이를 뒷받침한다. `design-principles/flexibility/preserve-a-persons-context` `design-principles/agency/give-people-the-freedom-to-explore`

## 화면의 세 가지 상태

```text
기본 작업 상태
  프로젝트 탐색 | 열린 작업 탭 + 현재 도구 모음
               | 메인 대화 / 프로젝트 개요 / 선택한 내용

편집 집중 상태
  열린 작업 탭 + 현재 문서 도구 모음
  문서 편집 영역                         | 이 문서의 AI (필요할 때)

나란히 작업 상태 — 사용자가 선택
  프로젝트 탐색 | 대화 또는 문서          | 볼트·다른 문서·웹
               | 각 칸의 작업 탭과 도구   | 각 칸의 작업 탭과 도구
```

이 도식은 레이아웃 관계를 보여주는 계획이며 완성 시안은 아니다. 각 패널의 고정 폭을 지금 임의로 정하지 않는다. 기본 작업의 탐색은 발견 가능하게 두고, 문서 편집 때 가리는 정책은 사용자의 기존 요청을 따른다. 앱 내부 **편집 집중 모드**와 OS 전체 화면 모드는 구별한다. OS 전체 화면 진입·종료를 탭 선택만으로 강제하지 않는다. `going-full-screen/best-practices/continue-to-provide-access-to-essential` [HIG transfer + House]

|---|---|---|---|---|
| 프로젝트 목록에서 길을 잃음 | Simplicity | 계층과 현재 위치 표시 | 사이드바 + 내용 목록 + 경로 | `design-principles/simplicity/establish-hierarchy` [HIG transfer] |

## 미감과 언어

내용은 넓고 안정된 면에 놓고, 탐색·행동·선택을 구별한다. 강조색은 현재 위치와 중요한 행동에 사용한다. Liquid Glass는 선택한 제어/탐색 요소에서만 검토하며, 긴 대화·문서·표 뒤에 적용하지 않는다. `materials/liquid-glass/dont-use-liquid-glass-in-the` [HIG transfer]

한국어 명칭은 “프로젝트”, “새로 만들기”, “편집기에 집중”, “작업공간 보기”, “이 문서의 AI”, “이 페이지의 AI”, “작업 중”, “입력 필요”처럼 행동과 대상을 드러내도록 한다. `writing/getting-started/determine-your-apps-voice` [House]

## 가정과 미정 사항

- 브랜드·본문 서체·엔진별 사용자 룩은 기존 설정을 계승한다. HIG의 역할 구분과 접근성 기준으로 점검하되 다른 앱처럼 보이게 하려고 사용자 설정을 초기화하지 않는다.
- 기본 모드는 기존처럼 단일 작업 영역이다. 분할은 사용자가 선택한다.
- [HIG none] 유리 효과의 최종 강도와 장시간 읽기 밀도는 대표 화면 비교 후 선택할 미감 항목이다. 이번 계획은 범위를 제한한 후보로 두며 핵심 기능 결정을 막지 않는다.
- [HIG none] 성능·병렬 실행·WebView 수명은 HIG가 규정하지 않는다. 기존 제품 계약과 실제 측정으로 판단한다.
