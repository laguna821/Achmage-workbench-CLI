## 결론

흐리게 느껴질 만한 구현상의 변화가 있다. 특히 상단 제목 축소, 보조 글자의 대비 감소, 제목과 분류 표시의 위계 약화가 확인됐다. 이미지로 그린 글자나 실제 글꼴 손상은 확인되지 않았다. 현재 앱은 정상 로드된 Pretendard Variable로 텍스트를 렌더링한다.

HIG 전체를 포기할 이유는 없다. 13px·회색 표기를 광범위하게 적용한 이번 구현의 선택을 수정하면 된다. 0.3의 유용했던 위계와 밀도를 복원하면서 프로젝트 중심 구조, 문서·웹·세션 구분, Pretendard를 유지하는 범위가 적절하다.

## 관찰과 원인

| 구역 | 0.3.3 소스 | 현재 소스·네이티브 측정 | 판단 |
|---|---|---|---|
| 상단 제목 | 16px / 600, SameTone | 13px / 600, Pretendard | 실제 축소. 서체도 역할별 변경됨 |
| 일반 사이드바 항목명 | 13px / 400 | 13px / 400 | 모든 글자가 작아졌다는 설명은 틀림 |
| 탭 제목 | 13px / 400 | 13px / 400, 활성 600 | 비활성 이름과 분류가 같은 회색·크기로 읽힘 |
| 사이드바 섹션명 | 12px / 600 | 13px / 600 | 항목명과 크기 차이가 없어짐 |
| 보조 글자 대비 | 기본 중립 팔레트 약 5.47:1 | 현재 기본 라이트 약 4.46:1 | 작고 가는 보조 글자가 더 약하게 보일 조건 |
| 일반 행 글자 대비 | 약 9.20:1 | 약 17.91:1 | 모든 글자가 연해진 것은 아님 |
| 색상 지정 폴더명 | 600 | 400 | 강조가 약해짐 |
| 종류 표기 | 작은 배지와 역할별 크기 | 여러 종류·상태·이름이 13px로 모임 | 위계가 평평해지고 긴 이름이 먼저 잘림 |

대비는 글자와 배경의 상대휘도 비율이다. 이전 값은 **소스 기본값 계산**, 현재 값은 격리 실행에서 얻은 실제 기본 색상 계산이다. 사용자가 별도로 지정한 테마나 과거 설치본의 실제 픽셀 수치로 일반화하지 않는다. 점수 하나가 가독성 전체를 설명하지도 않는다.

### 실제 글꼴과 화면 배율

- 실제 격리 Linux/WebKitGTK 실행에서 Pretendard Variable의 로드 완료를 확인했다.
- 표본 요소와 상위 요소에 지속적인 blur, scale/transform, 낮은 opacity, 별도 zoom이 없었다.
- `antialiased`와 `optimizeLegibility`는 0.3.3에도 있었다. 새 흐림의 원인으로 지목할 수 없다.
- 번들 Pretendard와 이 노트북에 설치된 같은 이름의 글꼴은 SHA-256이 같다. 다만 **0.3 실행 당시 실제 선택된 글꼴은 미확인**이다.
- 이 노트북의 실제 화면 배율은 125%다. 이번 비교는 격리 X11의 100% 렌더링이다. 125% 합성이나 OS별 래스터화의 영향을 검증했다고 주장하지 않는다.

### 코드 구조에서 발견한 문제

1. `--fs-ui`만 바꿔도 해결되지 않는다. `hig-shell.css`, `hig-workspace.css`가 여러 역할을 직접 13px로 덮어쓴다.
2. 사이드바의 중립 팔레트 격리가 제거되어 선택한 에이전트의 look에서 `--text/--muted`를 상속할 수 있다. 반면 배경은 별도 `--chrome-*` 규칙이다. 사용자 지정 테마에서는 예상 밖 조합이 생길 수 있다.
3. `.sidebar .side-row.row-docs`의 우선순위가 뒤의 `.sidebar .row-docs`보다 높아 문서 묶음의 600 굵기 의도가 400으로 덮인다.
4. `문서 AI` 묶음 안의 `문서 AI`, `NAVER · 웹 AI` 옆의 `웹 AI`가 반복된다. 긴 작업명·문서명에 더 많은 폭을 주는 편이 유용하다.

## Impeccable·Hallmark 적용 판단

Impeccable의 typeset 및 기술 감사 지침을 수동 적용하고, 독립적인 시각 검토와 소스 비교를 각각 수행했다. Hallmark의 기존 앱 재설계·서체·대비·밀도 기준을 적용했다. OS 통합 지침에 따라 Impeccable 자동 엔진은 실행하지 않았다. 자동 점수나 전면 디자인 인증을 받은 것으로 표시하지 않는다.

| 기준 | 이번 화면의 문제 | 적용 방향 |
|---|---|---|
| Impeccable: 정보 위계 | 이름·종류·상태가 비슷함 | 이름을 14px / 500, 프로젝트를 600, 보조 표시를 13px로 분리 |
| Impeccable: 읽기 순서 | 반복 종류가 공간을 선점함 | 묶음 안의 중복 종류 배지 축소, 실제 이름 폭 확대 |
| Hallmark: 대비 | 비활성 탭 이름까지 지나치게 물러남 | 클릭 가능한 이름은 진하게, 종류만 보조 톤 |
| Hallmark: 앱 밀도 | 28px 행과 작은 글자가 촘촘함 | 기본 탐색 행 32px, 과도한 전역 확대는 피함 |
| Hallmark: 일관성 | 테마 상속과 CSS 덮어쓰기가 섞임 | 탐색 전용 의미별 토큰으로 정리 |
| 유지할 요소 | 프로젝트 구조·활성 탭·기능 경계 | 프로젝트/채팅/문서/웹 묶음과 아이콘 유지 |

## 시각 제안

[현재 ↔ 제안 비교 열기](previews/2026-11-11-readability/comparison.html)  
[현재 화면](previews/2026-11-11-readability/current.png) · [제안 화면](previews/2026-11-11-readability/proposal.png) · [실측 값](previews/2026-11-11-readability/measurements.json)

실제 설치 바이너리를 별도 테스트 프로필에서 실행한 화면이다. 대화 내용은 테스트용이며 사용자 데이터는 사용하지 않았다. 제안은 그 격리 창에만 CSS로 적용했다. **0.3 실행 화면이나 최종 완성 디자인은 아니다.**

| 역할 | 현재 | 제안 |
|---|---|---|
| 작업명·비활성 탭 이름 | 13px / 400 | 14px / 500 |
| 프로젝트명·활성 이름 | 13px / 600 | 14px / 600 |
| 상단 제목 | 13px / 600 | 14px / 600 |
| 사이드바 행 높이 | 28px 최소 | 32px 최소 |
| 주요 글자 | 검정 또는 muted | `#202733` |
| 보조 글자 | `#6c6c70` | `#4e5968` |
| 탐색 배경 | 파란색이 섞인 회색 | 더 중립적인 `#f3f5f8` |
| 반복 종류 배지 | 각 행마다 표시 | 묶음으로 구분되는 행에서 축소 |

제안 배경의 주요 글자 대비는 약 13.74:1, 보조 글자는 약 6.51:1이다. 탐색 제목은 또렷하게 하되 모든 글자를 순검정·굵게 만드는 방식은 피했다. 폰트는 Pretendard 그대로다.

제안 CSS는 시각 비교용이다. 실제 구현에서는 단순한 `display:none` 대신 그룹 내 중복일 때만 종류 배지를 생략하고, 검색·혼합 목록에서는 유지해야 한다. 접근 가능한 이름, 툴팁, 종류 아이콘을 보존한다. 상단 전체 색조와 분할 화면의 밀도는 최종 구현에서 함께 맞춘다.

## 적용 순서와 완료 기준

1. **서체 역할·색상 토큰 정리**  
   `foundation.css`에 탐색 제목/보조/강조의 크기·굵기·색상을 정의한다. `hig-shell.css`, `hig-workspace.css`의 중복 고정값을 해당 역할로 치환한다. 사이드바 팔레트를 선택한 채팅의 look과 분리하고 `row-docs` 우선순위 충돌을 해소한다. 색상 지정 폴더의 강조도 복원한다.

2. **이름의 공간 확보**  
   `nav/rows.tsx`, `GroupTabs.tsx`에서 종류 중복을 조건부로 줄인다. 프로젝트·채팅·문서·웹 묶음은 유지하며, 파일 확장자 배지가 있는 탭의 `문서` 반복도 줄인다. 들여쓰기와 빈 펼침 공간을 필요한 행에만 적용한다. 전체 이름은 툴팁과 접근 가능한 이름에서 제공한다.

3. **좁은 화면과 다중 프로젝트 배치에 적용**  
   기본 행 32px를 유지하면서 9분할 등 좁은 패널에서는 보조 라벨부터 줄인다. 중요한 이름의 글자를 먼저 축소하지 않는다. 가독성 문제를 보완하기 위해 곧바로 새로운 설정 메뉴를 추가하지 않는다.

4. **변경 범위만 확인하고 마감**  
   긴 한글 이름, 활성/비활성/키보드 포커스, 라이트/다크, 좁은 사이드바를 한 번씩 확인한다. 실제 Linux 125%와 Windows/macOS의 관련 화면 확인은 구현 완료 조건에 포함한다. 새 기능 검증이나 전체 릴리즈 점검을 반복할 범위는 아니다.

완료 기준은 사용자에게 중요한 **프로젝트명 → 작업명 → 종류·상태** 순서가 즉시 구분되는 것이다. CSS 수치 변경이나 디자인 체크리스트 통과만으로 완료 처리하지 않는다.
