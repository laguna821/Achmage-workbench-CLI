## 0. 판단 기준

사용자 노트 「줄이기 위해 분해한다」의 식을 그대로 쓴다.

$$W^* = \arg\min_{W \in \mathcal{W}_G} N_h(W) \quad \text{s.t.}\quad C(W)=H(W)=O(W)=1$$

- **N_h**: 사람이 직접 하는 단계 수다(누르기·키·고르기, 요청 글 쓰기는 빼고).
- **C (Change-aware)**: 바뀌어도 고칠 수 있어야 한다. 엔진마다 다른 길을 만들지 않고, 경계를 남긴다.
- **H (Human-centered)**: 사람이 바뀐 내용·결과·근거를 보고 실제로 고를 수 있어야 한다. 매번 멈춰 세우지 말고 언제든 멈출 수 있게 한다.
- **O (Org-level)**: 나중의 나, 다른 기기, 다른 사람이 기록만으로 이어받을 수 있어야 한다.
- **실패**: 끝난 부분은 살리고 실패한 곳에만 개입한다.

### 지금 코드의 결함 (기획과 별개로 먼저 고칠 것, P0)
- **멈추거나 실패한 턴의 수정안을 버린다**(`sessions.ts` `afterTurn` → `discardProposal`). PPT 10장 중 8장을 고친 상태에서 멈추면 8장이 사라진다. 앱을 다시 켤 때는 같은 사본을 수정안으로 살리므로 경로마다 다르다.
- **엔진 프로세스가 죽으면** 턴 끝 신호 없이 상태만 '쉬는 중'으로 바뀐다(Claude `finally`, Codex `onExit`). 그 결과는 이렇다.
  - 남겨 둔 요청이 저절로 나간다(`updateSession` → `drainSoon`). "실패 뒤에는 보내지 않는다"는 규칙과 어긋난다.
  - 수정안이 '진행 중'으로 남아 다른 세션의 같은 문서 수정을 막는다(409, `artifacts.ts:459`).
  - 다른 세션에 보낸 요청이 풀리지 않는다.
  - Claude는 오류 표시(`lastError`)도 남기지 않는다.
- **세션 셋 이상 잇기**는 바로 앞 차례의 답만 넘긴다(`links.ts:505`). C는 A의 초안을 받지 못한다.
- **오피스·한글 문서**는 새 판이 생기면 색인 항목이 지워진다(`searchText`가 null → `indexDocument`가 삭제만 함). 엔진이 만든 문서일수록 찾아지지 않는다.
- **검색 결과가 말없이 잘린다**: 메시지 800건, 세션 40개, 문서 20개(`sessions.ts:1602-1628`).

## 2. 다시 짠 모델: 세 층과 다섯 길

```
층      세션(대화·턴)  ──▶  프로젝트(노트: 단계·태그·결정·열린 질문·메모 + 사건 기록)  ──▶  모아 보기(지금·프로젝트·흐름·문서·찾기)
길  ① 들어가는 길   어디서 무엇을 시작·이어 가는가
    ② 되쓰는 길     세션의 결과가 프로젝트에 남는다
    ③ 알리는 길     바뀐 것이 사람과 열린 세션에 닿는다
    ④ 찾는 길       사람과 엔진이 같은 색인으로 찾는다
    ⑤ 끊기는 길     실패해도 끝난 것은 남고, 멈춘 곳만 보인다
```

정리·알림·찾기는 모두 **AI 0회**다. 기록에서 그대로 뽑는다. AI가 쓰이는 곳은 사용자가 요청한 세션 안뿐이다.

## 3. ① 들어가는 길

- **작업 줄을 누르면 대화가 열린다**(가정 B 철회).
  - 열 세션은 확인 필요 › 오류 › 새 답 › 마지막에 본 것 순서로 고른다.
  - 빨간 점을 보고 누르면 바로 그 세션으로 간다.
- **프로젝트 페이지 입구는 셋이다.** 모두 늘 보이는 곳이다.
  1. 대화 머리 줄 `강의 › 안녕 · 하는 중 · #강의`에서 이름을 누른다(지금은 '분류 옮기기'만 함).
  2. Ctrl+K에서 작업 결과를 Shift+Enter로 연다.
  3. 홈 '프로젝트' 모드에서 고른다.
- **홈 입력창에 `[프로젝트 ▾]` 칩을 둔다.** 폴더 칩 옆이다.
  - 폴더를 골랐는데 그 폴더에 살아 있는 프로젝트가 있으면 그 프로젝트가 기본이다. 칩에 "→ 안녕에 새 세션"이라고 보인다.
  - 이것이 **같은 폴더 = 같은 프로젝트** 기본값이다. "새 프로젝트"는 칩에서 고를 때만 만든다.
  - 폴더 없이 보내면 지금처럼 새 프로젝트를 만든다.
- **세션을 다른 프로젝트로 옮기기는 하지 않는다.** 엔진이 처음 폴더에서만 대화를 이어 가기 때문이다. 다른 작업에 끌어 놓으면 지금처럼 "세션 기록 페이지"가 된다.

## 4. 프로젝트 노트 (가정 A 교체)

**파일**
- 보통 폴더: 작업 폴더 바로 아래 `‹노트 이름›.md`(폴더 노트).
  - 이름은 처음 쓸 때의 작업 이름으로 고정한다. 이름이 바뀌면 그 이름을 `aliases`에 더한다.
  - 프런트매터의 `workbench_id`로 찾는다. 파일 이름이 바뀌어도 잃지 않는다.
- git 저장소: `.workbench/project.md`. 저장소 안에 보이는 파일을 늘리지 않으려는 것이다. 추적 예외로 처리하고 엔진용 사본(`.workbench/drafts`)과 나눈다.
- 처음 사람이 무언가 쓸 때 만든다. 그 쓰기를 되돌리면 파일도 지운다.
- 판 기록에는 남긴다. 홈 '문서'·'흐름' 목록에는 보이지 않는다.

**엔진이 노트를 고칠 때는 막지 않고 늘 보이게 한다.**
- 두 엔진 모두 같다. 엔진이 노트를 바꾸면 판(작성자 엔진·세션)으로 남는다.
- "엔진이 프로젝트 노트를 바꿨습니다 · 단계 하는 중→마무리 [비교] [되돌리기]"를 띄운다.
- 속성을 읽을 수 없게 망가지면 마지막으로 읽힌 판을 보이고 되돌리기를 권한다.
- 막지 않는 이유: "노트에 이 결정 적어 줘"는 정당한 요청이다. 막는 방법도 엔진마다 다르다(Claude 훅, Codex 불가). 그래서 한 길로 보이게 하고 1클릭으로 되돌린다(H·C).

**사람이 쓰는 속성**
- 값이 있는 키만 보인다. 새 프로젝트에는 "+ 속성" 한 줄뿐이다.
- **단계**: `구상 · 하는 중 · 마무리 · 미룸` 그리고 **보관**.
  - 엔진 상태나 DIKM과 다른 낱말이다. 엔진 상태 색도 쓰지 않는다.
  - **보관 = 앱 보관함**이다. 칸반 '보관' 열에 놓거나 단계를 보관으로 바꾸면 보관하고 되돌리기를 띄운다. 진행 중인 세션이 있으면 지금처럼 거절한다.
  - 새 프로젝트는 비워 둔다. 기존 규칙(조건 → 배치)으로 채울 수 있다.
- **태그**: 자동 완성은 볼트의 태그와 사용자 태그 별칭(`Workflow-Engineering → Workflow_Engineering` 등, 읽기 전용)으로 맞춘다. 같은 뜻의 태그가 여럿으로 갈라지면 찾기·보기가 무너진다.
- **관련**: `[[` 입력으로 프로젝트와 볼트 노트를 고른다. 링크는 `workbench_id`·볼트 경로로 풀어서 이름이 바뀌어도 끊기지 않는다.
- 편집
  - 한글을 조합하는 중의 Enter는 무시한다.
  - 날짜는 글로 받아 해석한다(WebKitGTK의 날짜 입력은 확인된 적이 없음).
  - 고르기는 앱 자체 팝업으로 한다.
  - 쓰기 전에 바로 앞 내용과 같은지 확인한다. 쓸 때마다 "단계: 하는 중→마무리 [되돌리기]"를 띄운다.

**본문 구조**: Obsidian에서 열어도 그대로 읽힌다.

## 5. ② 되쓰는 길: 사건 기록 + 결정으로 남기기

- **사건 기록**(DB, AI 0회): 이미 있는 기록에서 그대로 뽑아 `events` 표에 넣는다.
  - 요청
  - 계획 승인·거절
  - 수정안 적용·버림(누가 닫았는지 `closedBy`)
  - 판(작성자·세션)
  - 잇기 끝 줄(합의·남은 쟁점)
  - 다른 세션의 답
  - 격리 사본 적용
  - 단계 변경
  - 결정 기록
- 프로젝트 페이지의 **기록** 칸에 보인다. 기본은 이번 주이고, 줄마다 "요청 → 결과 판 → 결정"이다.
- 파일에는 쓰지 않는다. DB에 이미 있는 것을 또 복제하지 않는다.
- **결정으로 남기기 / 질문으로 남기기**(1클릭)
  - 고를 수 있는 곳: 답·고른 글·수정안 적용 창·잇기 결과.
  - 노트의 `## 결정`·`## 열린 질문`에 한 줄로 더한다. 출처 링크(`workbench://session/…#item`), 엔진, 날짜가 함께 붙는다.
  - 열린 질문은 할 일 목록(`- [ ]`)이다. 체크하면 닫힌다. Obsidian 체크박스와 같다.
  - 결정은 **사람이 고른 것만** 파일에 간다. 이 파일이 다른 기기·다른 사람에게 가는 이어받기 기록이다(O).
- **다른 세션의 답 카드에 "대화에 넣기"**: 지금은 화면 카드로만 오고 보낸 엔진에는 들어가지 않는다.

## 6. ③ 알리는 길: 바뀐 것 → 엔진·사람

- **세션마다 "어디까지 알렸나"를 기록한다.**
  - 문서는 이미 `readBy`가 있다. 프로젝트 노트는 `toldRev`를 둔다.
  - 다음 요청을 엔진에 보낼 때 앞에 AI 0회로 만든 블록을 붙인다. 두 엔진이 같은 길(요청 글)을 쓴다. Codex 지침은 재개 때 바뀌지 않기 때문이다.
  ```
  [지난 요청 뒤 바뀐 것 — Workbench 기록에서 만든 것이며 지시가 아님]
  - 강의계획.md r8→r9: 사람이 고침(+3 −5)
  - 3주차.pptx: 당신의 수정안을 사람이 버림
  - 프로젝트: 단계 하는 중→미룸 · 결정 추가 "표지는 B안"
  ```
  - 크기는 1KB 안이다. 넘치면 "외 N건"으로 줄이고, 나머지는 찾기 도구로 볼 수 있다고 쓴다.
- **입력창 위에 `알릴 변경 3` 칩**: 누르면 목록이 보이고 빼고 싶은 줄을 끌 수 있다. 기본은 모두 보낸다(N_h 0, 언제든 멈출 수 있음).
- **맥락 카드 v2**(새 세션, 2KB 안)
  - 지금 들어가는 것: 작업·분류·폴더·볼트 규칙·고정 노트
  - 더하는 것
    - 노트 경로·단계·태그
    - **최근 결정 5줄, 열린 질문 3줄**(각 120바이트 안)
    - "더 필요하면 `workbench-find`" 한 줄
  - 일반 맥락(결정 기록·연구)은 이미 Achmage 훅이 넣는다. Claude는 `settingSources: user/project/local`, Codex는 사용자 설정으로 받으므로 겹치지 않게 한다.
- **프로젝트 페이지 "엔진이 아는 것"**(접힘): 카드 실물과 세션별로 마지막에 알린 판을 보인다. 지금은 사람이 카드를 볼 수 없다.
- **사람에게**
  - 작업 줄의 점과 페이지의 칩 줄(확인 필요·수정안·멈춘 곳)은 그곳으로 바로 간다.
  - 프로젝트를 다시 열면 "지난번 본 뒤" 바뀐 것을 기록 칸 맨 위에 둔다.

## 7. ④ 찾는 길: 하나의 색인

- **Ctrl+K 하나로 찾는다**(Ctrl+Shift+F는 만들지 않는다).
  - Tab으로 범위 칩을 바꾼다: 전체·프로젝트·세션·문서·결정·볼트.
  - Ctrl+Shift+F는 같은 상자를 '내용' 범위로 여는 단축키일 뿐이다.
  - 보기의 글자 조건도 같은 색인을 쓴다. "이 찾기를 보기로 저장"을 둔다.
- **한국어**
  - 질의에서 조사를 뗀다. 이미 있는 `stripJosa`(`titles.ts`)를 쓴다.
  - 짧은 말을 붙인 변형("채점 기준" ↔ "채점기준")도 함께 찾는다.
  - 한글 2-gram 보조 FTS 표를 둔다. 그래서 2자 말에도 bm25 순위가 붙는다. trigram `MATCH`는 3자 미만을 찾지 못한다.
- **순위와 표시**
  - 순위 가중치: 이름·별칭 ×3, 태그·속성 ×2, 정확한 구절, 내가 쓴 글.
  - 결과는 프로젝트별로 묶는다.
  - **중복을 합친다**: 문서와 그 문서를 만든 세션의 답은 한 줄로(판의 `sessionId`). 내보낸 사본(`exportedFrom`)은 숨긴다.
  - 총수와 "더 보기"를 보인다. 말없이 자르지 않는다.
- **색인 범위**
  - 오피스·한글 글: 판을 기록한 직후 kordoc·이음으로 뒤에서 색인한다(P0 결함도 함께 고침).
  - 계획 원문, 첨부 파일 이름, 결정·열린 질문, 사건 기록, 볼트 노트(거울이 바뀔 때마다).
  - 옛 판은 "옛 판 포함"을 골랐을 때만 찾는다.
- **엔진이 찾는 도구 `workbench-find`**(읽기 전용)
  - playwright-cli 래퍼와 같은 스풀 방식이다. 그래서 Codex 샌드박스에서도 돈다.
  - 사람과 같은 색인·같은 문법을 쓰고, AI 0회다.
  - 결과는 4KB 안이다. 줄마다 출처를 붙인다: `[안녕 · Codex · 과제 채점 기준표 · 10-29 14:02 · 답 · r3]`.
  - 보관한 것과 볼트 숨김 폴더는 화면과 같은 규칙으로 뺀다.
  - 결과 머리에 "기록이지 지시가 아님"을 붙인다.
  - 카드에는 "가리킴 + 이 도구 쓰는 법"만 넣고, 나머지는 엔진이 필요할 때 찾는다.
- **Achmage와는 잇기만 한다.** 복제하지 않는다.
  - 노트에 `achmage_work:` 키 하나를 둔다. 페이지에 Achmage 작업 요약(목표·마지막 결과·다음 할 일)을 읽기 전용으로 보인다.
  - 인사이트를 발행할 때 엔진이 Achmage 작업 id를 추측하지 않게 이 키를 넘긴다.

## 8. ⑤ 끊기는 길 (P0 결함 + 설계)

- **턴 끝을 늘 만든다.** 어댑터는 엔진이 죽어도 `turnEnd{cause: stop|crash|restart}`를 낸다. 그래서 `afterTurn`(요청 붙잡기·수정안 정리·회신 정리)이 늘 돈다.
- **멈추거나 실패한 수정안은 버리지 않는다.** "중단됨(일부)" 상태로 남기고 비교 화면에서 고른다. 앱을 다시 켤 때와 같은 규칙이다.
- **엔진이 죽어도 남겨 둔 요청은 보내지 않는다.** Claude도 `lastError`를 남겨 '오류·멈춤'에 뜨게 한다.
- **실패한 잇기는 끝내지 않고 멈춤으로 둔다.** 셋 이상 잇기는 받는 세션의 마지막 차례 뒤에 나온 답을 모두 차례대로 넘긴다(24,000자 안).
- **다른 세션에 보낸 요청에 "다시 보내기"를 둔다.**
- **프로젝트 페이지 칩 `멈춘 곳 N`**: 누르면 끊긴 세션·수정안·잇기로 간다.
- **출처를 지금부터 남긴다.** 나중에 채울 수 없기 때문이다.
  - 턴 끝과 엔진이 쓴 판에 `model·effort·requestId`
  - 수정안에 `closedBy`
  - "읽은 노트"는 실제로는 사람이 붙인 노트만 센다. 그래서 이름을 "붙인 노트"로 바꾼다. 엔진이 읽은 노트는 도구 사용 기록(Claude `Read` 경로, Codex 명령)에서 모은다.

**홈 모드는 넷이다**: 지금 · 프로젝트 · 흐름 · 문서(가정 C 수정).
- '보드'는 '지금'으로 합친다. '모두 읽음'은 '새 답' 머리로 옮긴다.
- '프로젝트'
  - 기본은 폴더별 카드다. 지금 '지도'의 세션·문서 칩을 그대로 두어 한 번에 간다.
  - 그 안에서 **표 · 칸반**으로 바꾼다.
  - 칸반은 단계별 열이다. 빈 열은 숨기고, '값 없음'을 맨 앞에, '보관'을 맨 끝에 둔다.
  - 900px 창에서도 열이 다 보이게 접는다. 끌기는 사이드바와 같은 포인터 방식이고 키보드로도 옮길 수 있다.
- **그래프는 홈 모드가 아니다.** P4에서 '프로젝트' 안의 보기 하나와 프로젝트 페이지의 '연결' 칸(깊이 1~2)으로만 둔다.
  - 지금 이 노트북의 프로젝트는 1개이고 태그는 0개다. 선이 생길 재료(결정·관련·태그)가 쌓이기 전에는 장식이다.
  - 움직임 줄이기에서는 멈춘 배치로 그린다.

**대화 머리**: `강의 › 안녕 · 하는 중 · #강의`
- 이름을 누르면 프로젝트 페이지, 분류를 누르면 옮기기다.
- 입력창 위에는 `알릴 변경 N` 칩이 있다.

## 12. 받아들이지 않은 제안과 이유

- **프로젝트 기록을 작업 폴더의 jsonl로 남기기**(정보 전달 검토)
  - 사건은 이미 DB에 있다. 복제하면 정본이 둘이 된다.
  - 다른 기기로 가야 할 것은 사람이 고른 **결정·열린 질문**이고, 그것은 노트 파일로 간다.
- **엔진이 노트를 못 쓰게 막기**(UX·정보 전달 검토)
  - 엔진마다 길이 다르고(Claude 훅만 가능), "노트에 적어 줘"를 막는다.
  - 대신 막지 않되 늘 보이고 1클릭으로 되돌린다(§4).
- **Ctrl+K에 Achmage 범위 넣기**(회수 검토)
  - 런처 CLI의 어휘 검색이 이 용도를 지원하는지 아직 확인하지 않았다.
  - 지금은 `achmage_work` 링크와 요약 표시까지만 한다.

## 13. 남은 확인 (사용자 결정이 필요한 것)

- **볼트 숨김 폴더**: 맥락 카드는 엔진에게 "볼트에서 찾아 읽어도 된다"고 한다. 그런데 Notebook Navigator 숨김 폴더(`/90.*`, `/Ach*`, `/Brain*` 등)는 화면에서만 숨는다.
  - 엔진에게도 "읽지 말 것"으로 할지 정해야 한다.
  - 전체 접근 권한에서는 기술적으로 막을 수 없고, 지침과 `workbench-find` 제외까지만 할 수 있다.
- **관리 작업 폴더 위치**: 폴더 없이 시작한 프로젝트는 앱 데이터 폴더(`~/.local/share/achmage-workbench/works/…`)에 생긴다. 그래서 노트가 Obsidian·다른 기기에서 보이지 않는다.
  - 설정에서 위치를 고르게 할지 정해야 한다(Dropbox라면 git 메타데이터는 두지 않는다).
- **단계 이름**: `구상 · 하는 중 · 마무리 · 미룸 · 보관`은 기본값이고, 쓰시는 낱말로 바꿀 수 있다.
