  - 작업의 카드 목록은 우클릭 "카드로 보기"로만 들어간다.

- **찾기**: SQLite FTS5 trigram 표 두 개가 있다.

- **세션에서 모을 수 있는 사실**:

## 1. 핵심 정의

> **프로젝트 = 작업 하나 = 노트 한 장.** 노트는 **속성(YAML)** 과 **본문** 으로 이루어진다.

- **사람이 쓰는 속성**: 태그, 상태, 관련 프로젝트·노트, 설명, 마감, 그 밖에 사람이 만든 키.
  - 노트 파일의 프런트매터에 그대로 저장한다. Obsidian이 읽는 모양 그대로다.
- **자동 속성**: 세션 수, 엔진, 마지막 활동, 파일 수 같은 것.
  - 파일에 쓰지 않고 볼 때 계산한다.
  - Obsidian의 `file.*` 속성이나 Bases의 수식 칸과 같은 자리다.
  - 끊임없이 바뀌는 값을 파일에 쓰면 판이 쌓이고, 엔진·사람의 편집과 부딪힌다.
- **본문**: 위에서부터 아래 순서로 놓인다.
  1. 속성
  2. 대시보드(세션·파일·예약·격리 사본)
  3. 메모(사람이 쓰는 마크다운)
  - 대시보드는 앱이 그린다. 파일에는 메모만 들어간다.

### 가정 A. 노트 파일은 작업 폴더의 `.workbench/project.md`

- `.workbench/`는 이미 작업 템플릿 자리(`.workbench/templates/`)라서 규칙이 하나로 모인다.
- 처음 고칠 때 만든다. 아무것도 안 고친 작업에는 파일이 생기지 않는다.
- 평범한 `.md`라서 좋은 점이 셋이다.
  - Obsidian으로 열면 속성이 그대로 보인다.
  - 엔진(Claude·Codex)이 프로젝트 맥락으로 읽을 수 있다.
  - git에 함께 남길 수 있다.
- 사람이 고친 판은 문서 판 기록에 남는다. 엔진이 고치면 다른 문서처럼 수정안이 되어 검토를 거친다.
- 대안: 앱 DB에만 두고 "마크다운으로 내보내기"를 붙이는 방법도 있다.
  - 엔진이 읽을 수 없고, Obsidian과 같은 모양이라는 장점이 사라진다.
  - 그래서 택하지 않았다.
- 코드 저장소인 작업 폴더에서는 `git status`에 `.workbench/`가 보인다.
  - 처음 만들 때 "`.gitignore`에 넣을까요" 같은 질문은 하지 않는다.
  - 대신 프로젝트 페이지 ⋯ 메뉴에 "git에서 빼기"를 둔다.

### 가정 B. 작업 줄을 누르면 프로젝트 페이지

- 사용자 말 그대로 "프로젝트를 고르면 → 메타데이터 → 대시보드"다. 옵시디언의 폴더 노트와도 같다.
- 대화로 바로 가는 길은 지킨다.
  - 사이드바 세션 줄을 누르면 대화가 열린다. 세션이 하나뿐인 작업도 펼치면 세션 줄을 보인다.
  - 프로젝트 페이지 머리에 **"이어서: ‹마지막 세션›"** 단추가 있다. 한 번 누르면 대화로 간다.
  - 프로젝트 페이지 아래 입력창에서 그 프로젝트의 새 세션을 바로 시작한다.
  - 알림, Ctrl+K, 홈의 "이어서 하기"는 지금처럼 세션으로 바로 간다.
- 대안: 작업 줄은 지금처럼 대화로 두고 줄 옆에 "프로젝트" 아이콘을 두는 방법도 있다.
  - 마우스를 올려야 보이는 버튼은 찾기 어렵고 "프로젝트를 고른다"는 말과 어긋나 택하지 않았다.

- **속성 편집**은 옵시디언 Properties 방식이다. 값을 눌러 고친다. 형식은 넷이다.
  - 글
  - 목록: 태그나 링크
  - 날짜
  - 고르기: 상태
- **태그**는 기존 태그 이름을 자동 완성한다(작업·페이지·볼트 노트에서 모은 것). 저장하면 `Work.tags`도 같은 값으로 맞춰, 지금의 보기·규칙이 그대로 돈다.
- **관련**은 `[[` 를 치면 프로젝트 이름과 볼트 노트 이름을 자동 완성한다. 볼트 노트를 고르면 읽기 전용 링크만 남기고, 볼트 원본에는 쓰지 않는다.
- **키 글자와 모양은 그대로 둔다.** 사람 볼트 규칙과 같다.
  - 고친 키의 줄만 바꾼다. 다른 키, 순서, 빈 값, 따옴표, 본문 바이트는 그대로다.
  - 모르는 키도 지우지 않는다.
- **자동 속성**: 위 그림의 항목들이다. AI 호출은 없다.
  - 토큰·비용은 아직 기록이 없어서 P5에서 턴마다 기록을 시작한 뒤에 보인다.
- **대시보드**
  - 세션: 엔진 표시, 상태, 마지막 답 한 줄. 누르면 그 대화가 열린다.
  - 파일: 형식, 마지막 판과 작성자, 대기 수정안. 누르면 그 문서가 열린다.
  - 예약과 격리 사본.
  - 묶음마다 8개를 보이고 "더 보기"를 둔다.
- **맥락 카드**: 이 프로젝트의 새 세션에 노트 경로·설명·상태·태그를 넣는다. 기존 2KB 맥락 카드 안에서다. 엔진이 프로젝트가 무엇인지 매번 다시 듣지 않아도 된다.

## 3. 프로젝트 보기 — Bases식 표·카드·칸반 (P2)

옵시디언 Bases와 같은 생각이다. 저장한 보기 하나는 다음으로 이루어진다.

- 출처: 프로젝트
- 거르기
- 열(속성)
- 정렬
- 묶기
- 모양: 표 · 카드 · 칸반

```
보기: 진행 중 강의          [표] [카드] [칸반]      거르기: #강의 ."상태"!="끝"   정렬: 마지막 활동 ↓
┌──────────────┬───────┬──────┬──────────┬────────────┬───────────┐
│ 이름          │ 상태   │ 세션  │ 확인 필요  │ 마지막 활동   │ tags      │
├──────────────┼───────┼──────┼──────────┼────────────┼───────────┤
│ 안녕          │ 진행 ▾ │ 7    │ 1        │ 2시간 전     │ #강의 …    │
│ 가을 특강     │ 검토 ▾ │ 3    │ 0        │ 어제         │ #강의      │
└──────────────┴───────┴──────┴──────────┴────────────┴───────────┘

칸반(묶는 속성: 상태)
 아이디어 (2)   진행 (5)        검토 (1)      보류 (0)    끝 (9)
 ┌─────────┐   ┌──────────┐   ┌─────────┐
 │ 가을 특강 │   │ 안녕      │   │ …       │      ← 끌어 옮기면 그 노트의 `상태:` 줄만 바뀜
 │ 세션 3   │   │ ● 확인 1  │   └─────────┘
 └─────────┘   └──────────┘
```

- **거르기**는 지금의 보기 문법을 쓰고 비교만 더한다.
  - 예: `."세션">3`, `."마감"<@next7d`, `."상태"!="끝"`.
  - 자동 속성도 같은 이름으로 거른다.
  - 노션식 필터 화면은 만들지 않는다. 질의 한 줄과 미리보기 개수를 둔다.
- **표에서 바로 고치기**: 사람 속성 칸을 누르면 그 자리에서 고친다. 자동 속성 칸은 읽기 전용이다.
- **칸반**은 사람 속성 하나로 열을 나눈다. 기본은 `상태`다.
  - 끌어 옮기면 그 프로젝트 노트의 그 줄만 바뀐다.
  - 지금의 "보드"(세션 상태 열, 엔진이 정해 끌 수 없음)와는 다른 축이다.
  - 상태 값 목록은 기본 `아이디어 · 진행 · 검토 · 보류 · 끝`이고, 사람이 바꿀 수 있다.
  - 값이 없는 프로젝트는 "값 없음" 열에 둔다. 추정해서 채우지 않는다.
- 저장한 보기는 사이드바 "보기"에 있다. 지금 보기와 같은 자리, 같은 저장소다.

### 가정 C. 홈 모드를 다섯 개로 다시 짠다

지금: 지금 · 보드 · 지도 · 흐름 · 문서
바꾼 뒤: **지금 · 프로젝트 · 그래프 · 흐름 · 문서**

- "보드"(세션 상태 열)는 "지금"과 같은 축이라 "지금"의 묶음으로 합친다.
- "지도"(폴더 › 작업 카드)는 두 곳이 대신한다.
  - "프로젝트"의 카드 모양을 폴더로 묶은 것
  - "그래프"
- 모드 수를 늘리지 않는다(기본 화면은 극도로 단순하게).

## 4. 찾기 — Omnisearch식 (P3)

```
찾기 (Ctrl+Shift+F)  [ 채점 기준                               ]
 전체 · 프로젝트 · 세션 · 문서 · 볼트
 ▸ 프로젝트  안녕 — 메모: "…과제 **채점 기준**은 루브릭 3단계로…"          #강의 · 2시간 전
 ▸ 세션      과제 채점 기준표 (Codex) — 요청: "**채점 기준**표를 만들어…"   안녕 · 1시간 전
 ▸ 문서      평가안.docx — "…**채점 기준**과 배점…"                         안녕 · r3
 ▸ 볼트      AI 글쓰기 수업 설계 — "…**채점 기준**을 학생과 함께…"           20. Information
```

- **한 상자에서 다 찾는다.** 대상은 다섯이다.
  - 프로젝트: 이름·별칭·속성·메모
  - 세션: 요청과 답
  - 문서: 최신 판
  - 볼트 노트: 읽기 전용 색인
- **순위**는 bm25로 매기고 다음을 더한다.
  - 이름·별칭은 ×3, 태그·속성은 ×2.
  - 최근 활동에 작은 가산점을 준다.
- **한국어**: 3자 이상은 FTS5 trigram `MATCH`(순위 있음)로 찾는다. 1~2자는 `LIKE`로 거른다.
  - 앞선 계획의 결론과 같다.
- **발췌**: 맞은 곳 앞뒤를 굵게 보인다.
- **결과를 누르면** 그 자리로 간다.
  - 세션이면 그 메시지로 스크롤하고 잠깐 강조한다.
  - 문서·노트면 맞은 줄 근처를 보인다.
- 키보드만으로 쓸 수 있다(↑↓·Enter·Tab으로 종류 바꾸기).
- Ctrl+K(명령·이동)와 나누는 이유: Ctrl+K는 "어디로 갈까", 찾기는 "어디에 썼더라"다.
- AI 0회다. 볼트 색인은 볼트 거울이 바뀔 때 그 노트만 다시 넣는다.

## 5. 그래프 (P4)

- **점(노드)**
  - 프로젝트: 크기는 세션 수, 색은 상태 또는 앱 폴더.
  - 태그 점: 켜고 끈다.
  - 링크된 볼트 노트: 켜고 끈다.
- **선**
  - `관련` 속성
  - 메모의 `[[링크]]`
  - 같은 태그: 태그 점을 켰을 때
  - 세션이 읽은 볼트 노트: 끄고 켠다.
- **전체 그래프**는 홈의 "그래프" 모드다.
  - 거르기 줄을 둔다. 보기 문법과 같다.
  - 고아 숨기기, 색 묶음을 쓸 수 있다.
  - 누르면 프로젝트 페이지가 열린다. 마우스를 올리면 이웃을 강조한다.
- **로컬 그래프**는 프로젝트 페이지의 접힌 칸 "연결"이다(깊이 1~2). 분할 화면이 아니다.
- **그리는 방법**은 무게(force) 배치다.
  - 프로젝트 수백 개 규모라 SVG + 작은 자체 시뮬레이션 또는 `d3-force`(ISC, 작음)로 충분하다.
  - 라이브러리를 고르기 전에 WebKitGTK에서 노드 300·선 600으로 프레임을 잰다.

## 6. 볼트와의 관계

- **볼트는 지금처럼 읽기 전용 거울이다.**
  - 프로젝트 노트는 볼트가 아니라 작업 폴더에 있다.
  - 볼트 노트는 링크의 끝(점)일 뿐이다.
- **양쪽에서 보인다.**
  - 볼트 노트를 열면 "이 노트를 쓴 세션 N"이 있다. 여기에 "연결된 프로젝트"를 더한다.
  - 프로젝트에서는 `관련`의 볼트 노트를 누르면 앱 안에서 읽기 전용으로 열린다.
- **볼트로 가는 길은 지금처럼 인사이트 발행 하나다.**
  - 프로젝트를 정리한 글을 볼트에 남기려면 "인사이트 초안"을 쓴다.
  - `01. Inbox/Achmage 인사이트/`에 새 파일로만 남는다.

## 8. 정해 둔 기본값 (바꾸려면 알려 주세요)

- **가정 A**: 프로젝트 노트는 `작업 폴더/.workbench/project.md`이고, 처음 고칠 때 만든다. 자동 속성은 파일에 쓰지 않는다.
- **가정 B**: 작업 줄을 누르면 프로젝트 페이지가 열린다. 세션 줄·이어서 단추·알림·Ctrl+K는 대화로 바로 간다.
- **가정 C**: 홈 모드는 지금 · 프로젝트 · 그래프 · 흐름 · 문서다. 보드는 지금으로, 지도는 프로젝트·그래프로 합친다.
- 상태 기본값은 `아이디어 · 진행 · 검토 · 보류 · 끝`이고, 보관함(수명)과는 따로 간다. 끝이라고 저절로 보관하지 않는다.
- 정리·찾기·그래프는 AI 0회다. 볼트는 읽기 전용이다.
