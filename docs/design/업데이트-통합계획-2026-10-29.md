## 목표와 결론

사용자가 원한 것은 **옵시디언식으로 프로젝트와 세션을 관리하면서, Orca의 강력한 작업공간 기능과 이음오피스 전체 문서 기능을 한 앱에서 쓰는 것**이다. 다음 업데이트는 이 세 흐름을 연결하는 제품 개편으로 잡는다.

현재의 가장 큰 문제는 기능 몇 개가 숨어 있는 정도가 아니다. Office 편집기 AI·템플릿을 의도적으로 제거한 연결 방식, 세션에 종속된 간단한 worktree, 좌우 두 칸 전용 화면 모델이 요구를 제한한다. 이 기초를 고치지 않고 버튼을 더하면 같은 누락이 반복된다.

- 이음오피스: 셸과 공통 기능, 편집기 9종, CLI/MCP를 모두 대조하고 이식한다. 원본에서 동작하는 기능을 임의로 생략하지 않는다.
- Orca: 중첩 분할, 작업공간 관리, 터미널, Git 검토·피드백·PR, 내장 브라우저·Design Mode, 세션 연속성을 핵심 묶음으로 완성한다. 원격·모바일·추가 제공자·실험적 오케스트레이션도 범위표에 남기되 각각의 완료 조건을 둔다.
- PKM: 프로젝트 노트, Notebook Navigator식 목록, Bases식 보기, 볼트·검색·그래프는 이 구조 위에서 이어진다.
- 한글: 이음오피스 한글이 기본 편집기다. HOP는 개선 코드만 패치로 가져온다. hallym-kordoc은 기본 생성 스킬이며, 결과 HWPX는 같은 이음 편집기로 연다.
- doory: 새 문서 진입점과 문서 탭에 정식으로 포함한다.

상세 범위는 [Orca·이음오피스 기능 대조표](Orca-이음오피스-기능대조표.md)를 따른다. 이 계획의 단계는 내부 구현 순서다. 일부 단계를 끝낸 상태를 “전체 통합 완료”로 배포하지 않는다.

모델 메뉴는 이미 실제 엔진 목록을 받는다. 따라서 “모델명이 전부 하드코딩됐다”는 진단은 틀리다. 확인한 점은 Claude 목록 24시간 캐시, `resolvedModel` 미보존, 선택 ID가 목록에 없으면 화면에서 기본 모델로 보이는 처리다. 실제 요청 ID와 화면 표시가 어긋나는지 재현해야 한다. 과거 모델 조사 JSON은 남아 있지만 이번에 새 모델 요청을 실행하지 않았다.

## 3. 통합 데이터 구조

다음 관계를 계약으로 먼저 정의한다. 화면의 분류 폴더와 실제 디스크 경로를 분리한다.

```text
ProjectNote                프로젝트의 목적·속성·결정·기록을 담는 Markdown 노트
  └ Workspace              일반 폴더 또는 Git worktree, 실제 cwd와 실행 호스트
      ├ Session            Claude/Codex 등 실제 대화, workspace에 고정
      ├ Terminal           상호작용 가능한 PTY와 프로세스 소유권
      ├ Artifact           문서 ID·실제 경로·판·편집 상태
      └ TabGroupLayout     leaf(탭 목록) / split(방향·비율·자식들)
```

- 일반 문서 작업은 Git 없이 시작한다. 코딩 작업에서만 저장소·브랜치·worktree 항목이 나타난다.
- 기본 화면은 한 칸이다. 사용자가 나누면 좌우·상하로 중첩할 수 있고, 세션·문서·터미널·diff·브라우저를 탭으로 배치한다.
- 작업공간마다 탭, 분할, 활성 탭, 스크롤·커서, 브라우저 참조를 복원한다. 비율만 저장하는 현재 방식은 바꾼다.
- 창을 닫거나 숨기는 것, 세션 중단, worktree 보관, 디렉터리 삭제는 서로 다른 동작이다.
- `workspaceId + relativePath`로 파일 정체성을 구분한다. 서로 다른 worktree의 같은 경로를 같은 문서로 합치지 않는다.
- 문서에는 한 명의 작성자만 두고, 다른 뷰는 같은 문서 세션을 공유하거나 읽기 뷰가 된다. 탭을 옮겼다고 AI·문서 프로세스를 중복 생성하지 않는다.
- 기존 Work/Session/Artifact ID와 프로젝트 노트는 마이그레이션 매핑으로 보존한다. GitHub main과 현지 master의 차이도 병합 전에 유지한다.

### 사이드 채팅과 탭 참조

1. 프로젝트에서 Markdown과 PPTX를 연다.
2. PPTX 옆 채팅에서 `+` 또는 `@`로 Markdown 탭을 고른다.
3. 저장하지 않은 변경은 원본처럼 상태를 알린다. “저장하고 첨부” 또는 명시적인 스냅샷 경로를 제공하며 옛 파일을 몰래 보내지 않는다.
4. 참조에는 문서 ID·판·해시, 편집 대상에는 PPTX와 선택 범위를 고정한다.
5. 프로젝트의 같은 세션이 요청·도구·취소·완료 기록을 소유한다. 문서 패널을 열 때 별도 대화를 몰래 만들지 않는다.
6. AI가 PPTX를 편집하고 그 탭에 결과를 보여 준다. 저장 후 다음 요청이 새 판을 읽는다. 참조한 Markdown은 바뀌지 않는다.
7. 새 문서 요청은 새 탭으로 넘겨 한 번만 실행한다. 재연결 때 같은 생성 작업이 중복 실행되지 않는다.

이음의 앱 내부 제한 도구 루프와 Workbench의 일반 CLI 세션은 동일하지 않다. 실제 세션에서 형식별 도구와 편집기 상태를 연결할 수 있는지 G2에서 작은 종단 검증을 먼저 한다. 단순히 원본 AI 패널을 표시하는 것만으로 완료하지 않는다.

### 템플릿은 서로 다른 두 기능을 모두 가져온다

- PPT 디자인 템플릿/갤러리와 저장한 스타일: 선택·미리보기·글꼴·문서별 기억·추가 스타일 요구.
- 사용자 양식 스킬: `metadata.ieum-template`, 원본 보존, 새 문서 사본, 빈 양식 미리보기, 등록·수정·가져오기·내보내기·업데이트.

한림대 PPT 테마 같은 사용자 자산을 다시 만들거나 특정 이름으로 하드코딩하지 않는다. 실제 기존 양식 파일을 추가하고 다시 쓰는 경로를 만든다.
