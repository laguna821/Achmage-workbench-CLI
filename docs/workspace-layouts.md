# 작업공간별 탭과 배치

세션, 문서, 프로젝트 노트와 볼트 보기를 같은 탭 줄에 연다. 탭은 그룹마다 순서와 활성 항목, 최근 선택 순서를 기억한다. 탭을 끌어 다른 그룹의 탭 줄에 넣거나 화면 가장자리로 옮기면 해당 위치로 이동한다. 탭에 초점이 있을 때 방향키/Home/End로 선택하고, Ctrl+Shift+좌우로 순서를 바꾼다. 가운데 클릭과 Delete로 닫을 수 있다.

창 하나에는 최대 16개 그룹, 배치 하나에는 최대 128개 탭을 둔다. 마지막 탭을 닫으면 빈 그룹이 접힌다. 파일과 세션 기록은 삭제하지 않으며 AI 실행을 종료하지 않는다. 문서 저장에 실패하면 전환·닫기를 보류한다. 프로젝트 노트 본문을 직접 편집 중이면 저장 또는 취소한 뒤 공간을 바꾼다. 저장 요청 자체가 실패해도 편집창과 입력을 유지한다.

탭은 위치와 별개의 고정 ID를 가진다. 방문한 탭은 숨겨도 같은 편집기를 유지하며, 그룹을 이동해도 React 부모와 DOM 노드를 바꾸지 않는다. 재시작할 때는 활성 탭부터 읽고 나머지는 선택할 때 연다. Markdown 편집기의 입력·DOM 유지와 iframe DOM 유지 검사, 실제 Linux 앱 탭 이동 검사를 포함한다. 모든 Office iframe 내부 상태의 복원 검증을 뜻하지는 않는다.

## 공간 전환과 복원

대화의 **작업공간 선택** 또는 상단 **배치 선택**에서 공간을 고르면 그 공간의 전체 탭·분할·초점으로 바뀐다. 저장되지 않은 문서가 있으면 먼저 저장을 확인한다. 상단의 **전체 작업 배치**로 기존 혼합 배치에 돌아갈 수 있다. 사이드바와 검색에서 여는 항목은 현재 선택한 칸으로 들어가므로 볼트 노트와 다른 프로젝트를 같은 배치에 둘 수 있다. 배치 선택은 세션의 실행 폴더를 바꾸지 않는다.

다음을 gateway에 저장해 앱의 로컬 포트가 바뀌어도 복원한다.

- 탭 ID·순서·활성 탭·최근 선택 순서, 그룹의 중첩 구조·비율·초점.
- Markdown/텍스트 편집기의 커서·선택 범위·스크롤, 문서 보기 모드와 읽던 위치.
- 대화의 스크롤 위치와 새 답을 따라갈지 여부.

내부 Office 편집기의 페이지·셀·객체 선택과 브라우저/터미널 상태는 각 편집기·도구 연결 단계에서 확장한다. 볼트/프로젝트 목록 자체의 스크롤 영속 복원과 Windows/macOS 설치본 검사는 후속 검증 대상이다.

## 저장 계약과 충돌

`GET/PUT /api/layouts/:key`가 `global` 또는 Workspace ID별 record를 읽고 쓴다. record는 `revision`, `updatedAt`, `layout.version=2`를 가진다. PUT은 `expectedRevision`을 요구한다. 각 배치는 최대 512 KB이며 전역 화면 설정의 64 KB 제한과 분리된다. 화면 설정에는 선택한 `layoutScope`만 남는다.

다른 창이 먼저 저장했으면 409로 거절하고 현재 화면을 유지한다. 배너에서 **저장된 배치 불러오기** 또는 **현재 배치로 저장**을 명시적으로 선택한다. 충돌 후 자동 재시도로 다른 창의 변경을 덮어쓰지 않는다.

이전 한/두 칸 또는 재귀 v1 배치와 프로젝트별 문서 목록은 v2 탭으로 읽는다. 원래 화면 설정은 로컬 DB의 `layouts.legacyPrefs`에 별도로 보존한다. 기존 프로젝트·세션·문서 ID나 파일 내용은 이 이행으로 바꾸지 않는다.
