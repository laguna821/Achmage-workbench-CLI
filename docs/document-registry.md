# 열린 문서와 편집 권한

Gateway는 각 문서 뷰의 창·세션·판·미저장 여부를 기록한다. 같은 파일을 여러 탭이나 창에서 열 수 있지만 한 뷰만 원문을 저장한다. 중복 Artifact ID와 심볼릭 링크도 실제 경로로 묶으며, 별도 worktree의 파일은 독립이다.

작성자는 60초 기한의 편집 권한을 받고 10초마다 갱신한다. 읽기 뷰는 기존 작성자가 닫힌 뒤 **편집 권한 받기**를 선택한다. 갱신 실패나 기한 만료 시 입력을 멈추고 기존 편집기와 초안을 유지한다. 이전 토큰은 원문 저장, 수정안 적용, 판 되돌리기에 사용할 수 없다. 파일을 열어 편집하는 뷰가 없으면 기존 CLI/API의 저장 경로도 계속 쓸 수 있다.

문서의 판 충돌 검사는 편집 권한과 별도로 유지한다. 외부 프로그램의 수정·삭제는 계속 감지하며, 디스크를 변경하지 않는 snapshot 기록은 편집 권한에 막히지 않는다. 프로젝트 노트의 본문·속성 쓰기도 같은 파일 권한을 확인한다.

Markdown은 읽기 전환 때 CodeMirror를 새로 만들지 않아 선택·Undo·입력을 유지한다. 텍스트 복구 사본은 뷰별로 분리하며 읽기 뷰가 다른 뷰의 사본을 지우지 않는다. Office/doory는 편집 권한만 갱신해 iframe의 미저장 편집 상태를 유지한다. 이 연결의 실제 Office/doory 편집 검증과 새 포트의 복구 사본 이행은 후속이다.

API:

- `GET /api/document-views`: 공개 가능한 뷰 상태. 저장 토큰은 포함하지 않는다.
- `POST /api/artifacts/:id/views`: 등록·갱신·명시적 권한 요청.
- `DELETE /api/document-views/:viewId`: 해당 창의 뷰 닫기.
- 문서 저장 요청: `x-workbench-view`, `x-workbench-write`를 사용한다. 읽기 뷰나 만료된 권한이 권한 없는 일반 API 쓰기로 후퇴하지 않는다.

실제 Linux 검사는 같은 파일의 두 뷰와 독립 API 작성자를 사용한다. 한 작성자 제한, 읽기 뷰 갱신, 권한 상실 시 입력/DOM 보존, 재획득 후 명시적 충돌 해결, 닫기 인계, 새로고침을 확인했다. 두 OS 창·Windows/macOS 설치본 검증은 별도다.

이 레지스트리는 문서 참조의 미저장 상태를 확인하기 위한 기반이다. `@`/`+`의 저장 확인과 참조 판 고정은 다음 변경에서 연결한다.
