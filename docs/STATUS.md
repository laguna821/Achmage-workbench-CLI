### 실제 검증됨 (모의 응답 없음)

- `scripts/smoke-real.ts`로 **설치본과 같은 묶음 게이트웨이**(`host.mjs`)를 대상으로 **14/14 통과**(2026-10-16, 모델·강도 전환 단계 포함: Claude `setModel` → `claude-sonnet-5-5`, Codex `thread/read` → `gpt-6-luna · low`).
  - 검증 항목: 응답 · 승인 → 파일 생성 · 거절 → 미실행 · 중단 → "중단됨" · 유휴로 엔진을 내린 뒤 같은 세션 재개 · 앱 재시작 뒤 같은 세션 재개.
- `scripts/ui-shots.ts`로 실제 화면(Chromium)을 따라감: 새 작업 → Claude 응답 → Codex 세션 추가 → 승인 카드 → 허용 → 결과 → 작업 찾기·폴더 생성.
- 설치된 앱(시스템 WebKitGTK 2.52)이 niri/Wayland에서 뜨고, 화면이 오류 없이 시작(`client.log`), 종료 시 게이트웨이 정리.
- 단위 테스트 24개(`npm test`): 두 엔진 변환기, 요청 중복 방지, 응답 중 중복 전송 거절, 재시작 복구, 이벤트 재생 범위, 한글 조합 Enter, 대화 묶기, 모델·강도 저장, Codex 기본 모델·강도, 자동 제목(조사·어미, 핵심 추적, 흔들림 방지, 수동 고정).

### 측정 (Linux, 유휴, 앱 스코프 전체 PSS)

| 구성 | 시스템 WebKit 설치본 | AppImage |
|---|---|---|
| Tauri 셸 | 108 MB | 109 MB |
| WebKit 화면 + 네트워크 | 140 + 33 MB | 139 + 34 MB |
| AppImage 런타임 | — | 22 MB |
| 게이트웨이(Node) | 83 MB | 85 MB |
| **합계** | **363 MB** | **388 MB** |

- **2026-10-16 엔진별 외형·한눈에 보기 이후 재측정(설치본, 엔진 유휴 종료 뒤)**: 셸 99 + 게이트웨이 84 + WebKit 화면 213 + 네트워크 33 = **431 MB**. WebKit 화면이 140 → 213 MB로 늘었다. 글꼴 파일을 뺀 A/B에서도 214 MB라 SameTone 때문은 아니다. `WEBKIT_DISABLE_COMPOSITING_MODE=1`이면 410 MB(−21 MB)지만 애니메이션 품질 영향이 있어 적용하지 않았다. 원인 분석(합성 레이어·필터·스크립트 크기)은 후속.
- 시작 직후 1분 동안은 상태 확인용 Codex app-server(약 320 MB)가 떠 있다가 유휴 종료된다.
- PRD 목표 "유휴 UI + 게이트웨이 300 MB 이하"를 이전 단계 기준 **약 60 MB**, 현재 **약 130 MB** 넘는다. 대부분 WebKitGTK 기본 비용. 엔진은 쓸 때만 추가(Codex app-server 약 234 MB, Claude 세션당 약 250–340 MB).
- 엔진 유휴 종료 전에는 Codex app-server가 상주해 593 MB였다.
- 설치 크기: 실행 파일 + 게이트웨이 1.3 MB + 화면 0.4 MB (시스템 WebKit·Node·각 CLI 별도). AppImage 106 MB(WebKit 포함). 화면 첫 전송 gzip 127 KB.
- 비교 기준(같은 노트북, 2026-10-16 RSS): Orca 셸 약 1.03 GB.

### 미검증 · 제한

- **Windows**: 빌드·실행 미검증(NSIS 미작성). Linux 결과로 대신하지 않는다.
- **로그아웃 상태에서 로그인 완료**: 로그인 시작 경로만 구현. 실제 로그인 완료는 확인하지 못함(두 계정 모두 로그인된 상태).
- **창 닫기 = 앱 종료**: PRD의 "트레이로 이동, 작업 유지"는 미구현. 닫으면 진행 중 응답이 멈추고 다음 실행에서 "멈춤"으로 표시된다.
- **Node 24+ 필요**: 게이트웨이를 시스템 Node로 실행한다(번들하지 않음).
- 이 노트북 설치는 시스템 WebKit 실행 파일. 배포용 AppImage는 별도로 빌드된다.
- Claude의 추론 강도는 엔진이 적용 결과를 보고하지 않아 "최근 응답"에는 모델만 표시된다(Codex는 모델·강도 모두).
- 세션별 승인 방식 선택 없음(Claude: 매번 묻기, Codex: on-request + workspace-write).
- Claude 세션은 사용자 설정(`~/.claude`)을 읽으므로 Achmage 훅도 함께 실행된다.

## 단계 B — 대화 안 문서

- 문서는 작업 폴더의 실제 파일과 게이트웨이의 불변 리비전(`dataDir/artifacts/<id>/r<N>`)으로 다룬다.
  - 오래된 리비전으로 저장하거나 디스크가 바뀐 상태에서 저장하면 거부한다.
  - 되돌리기와 외부 변경 채택도 새 리비전으로 남긴다.
- AI 수정은 고정된 판의 작업 사본(`.workbench/drafts`)에서 수정안으로 만든다.
  - 수정안은 기준 판 위에서만 적용한다.
  - 한 문서에 동시에 수정안을 만드는 세션은 하나다.
  - "다른 세션에" 보내기는 검토 전용이고, 답은 원래 대화에 카드로 돌아온다.
- 형식: Markdown(CodeMirror), HTML(격리 미리보기), PDF(pdf.js, PDFCraft 쪽 편집 → 새 파일), HWPX/HWP(kordoc: 글 보기·패치·쪽 미리보기, HWP는 읽기 전용).
- 실제 엔진 검증(`scripts/smoke-docs.ts`): HWPX 대표 시나리오 통과. Markdown 두 단계는 Claude 턴이 멈춰 실패했고, 원인은 아직 진단하지 않았다.

## 디자인 문서 — doory 편집기 (2026-10-20)

조사: [design/doory-연동-조사.md](design/doory-연동-조사.md).

**결정**
- doory(오픈소스 Canva 대안)는 서버 없이 편집기만 들여온다.
- AI는 Codex·Claude 세션이 파일을 직접 고친다. 편집기 안에는 AI 기능을 붙이지 않는다.

### 구현됨
- **형식**: `<이름>.design.json`(doory 문서 schema v1)이 다섯 번째 문서 형식 "디자인"이다.
  - 이미지는 `<이름>.assets/<내용 해시>.<확장자>`에 둔다. 내용 해시라 리비전마다 같은 바이트를 가리킨다.
  - 작업 폴더 밖이나 `.workbench` 아래 경로는 열지 않는다.
- **편집기**: `vendor/doory`는 고정 커밋 `2eb2557c` 그대로다(`scripts/vendor-doory.sh`).
  - `apps/design`이 doory의 `EditorAdapter`를 Workbench 게이트웨이에 연결하고, `/design/` iframe으로 띄운다.
  - 자동 저장은 새 리비전이 된다. 다른 곳에서 새 판이 생기면 저장을 거부하고, 편집기 충돌 안내에서 "최신 판 열기"나 "사본으로 저장"을 고른다.
  - 서버가 필요한 템플릿·스티커·브랜드·공유·원격 AI는 뺐다.
  - 글꼴은 SameTone(기본)과 doory 기본 글꼴, 이 컴퓨터 글꼴(fontconfig)이다.
  - 자주 보이는 메뉴는 한국어로 바꿨다.
  - "작업 폴더에 저장"(내보내기)은 디자인 옆에 파일로 쓰고, PDF는 문서로 추적한다.
- **대화 흐름**
  - 디자인 파일 카드에 1쪽 썸네일이 보인다.
  - 수정안 카드는 전/후 썸네일과 개체 단위 변경(추가·삭제·글자·위치·모양)을 보여 준다. 비교 화면은 페이지별 전/후 그림과 변경 목록이다.
  - 썸네일은 숨은 iframe에서 doory 엔진으로 그린다. 45초 동안 안 쓰면 iframe을 내린다.
  - 편집기에서 고른 개체는 요청의 참조(`DocRef.selection.pageId/objectIds`)가 된다.
- **엔진 안내**: 프롬프트에 디자인 규칙(구조, 중심 기준 좌표, type 이름, 이미지 경로, 유효한 JSON)과 현재 개체 목록을 넣는다.
  - 깨진 JSON 수정안은 이유를 표시하고 적용하지 않는다.
- **새 디자인**: 문서 메뉴에서 크기 프리셋(정사각·카드뉴스·세로·가로·A4)으로 만든다.
- **크레딧**: 시작 화면과 편집기 아래에 AAL 크레딧을 항상 보인다.
- **셸로 쓴 파일 추적(모든 형식)**: 엔진이 셸 명령으로 쓴 문서 파일도 턴이 끝날 때 작업 폴더를 훑어 추적한다(깊이 3, 4000항목 제한).
- **이벤트 스트림**: 연결 즉시 헤더를 보낸다. 첫 이벤트 전까지 "연결 끊김"으로 보이던 문제를 고쳤다.

## 이음오피스 기능 도입 (2026-10-28)

조사: [design/이음오피스-도입-조사.md](design/이음오피스-도입-조사.md).

**원칙**
- ~~이음의 편집 화면은 가져오지 않는다.~~ → 같은 날 바뀜: 편집 화면을 Workbench 안에 넣는다(아래 "앱 안 오피스 편집"). `ieumoffice` 명령줄 도구는 엔진 편집·쪽 그림에 아직 쓴다.
- 이음의 검증된 규칙(구독 판별, 과금 환경변수, 멘션)은 출처를 표기해 옮긴다(Apache-2.0, `third_party/ieumoffice`).
- 한글은 kordoc(생성·미리보기)과 HOP(사람 편집)이 맡는다.

### 구현됨
- **엔진 과금 보호**: Claude·Codex를 띄울 때 API 키·클라우드 경로 환경변수 16개를 지운다.
  - 엔진이 보고하는 로그인 종류로 구독/종량제를 표시한다.
  - 엔진을 찾는 경로를 넓혔다. SDK에 들어 있는 Claude 실행 파일로 돌 때는 그렇다고 표시한다.
- **워드·PPT·엑셀**
  - docx/pptx/xlsx를 판으로 추적하고, 판마다 쪽 그림(144dpi)과 글 보기를 한 번 만들어 둔다.
  - 엔진은 `ieumoffice ... apply`로 작업 사본을 고친다. 수정안은 쪽 그림 전/후와 글 차이로 보여 준다.
  - 열리지 않는 사본은 이유를 표시하고 적용하지 않는다.
- **이음오피스 설치**: 연결 화면·첫 안내에서 누르면 설치한다.
  - GitHub 최신 Linux 배포판을 받아 SHA-512를 확인하고, 실행 없이 풀어 `~/.local/opt/ieumoffice/<판>`에 둔다.
  - 이 노트북에서 실제 설치에 24초 걸렸다.
- **`@` 멘션**: 열린 문서를 먼저 보여 준다. 한글 조합 중에는 열리지 않고, 고른 멘션 안을 고치면 멘션이 풀린다.
  - 붙인 문서마다 읽기/고치기를 칩에서 바꾼다.
- **새 문서로**: 한글·워드·PPT·엑셀·마크다운·디자인·HTML 중에서 고른다.
  - 게이트웨이가 겹치지 않는 이름을 미리 잡고, 엔진에 형식별 방법을 알려 준다(HWPX는 hallym-kordoc, Office는 ieumoffice).
  - 턴이 끝나면 출처(`derivedFrom`)와 함께 추적한다. 없거나 열리지 않으면 알린다. 기존 파일은 덮어쓰지 않는다.
- **열린 문서 탭**: 작업마다 최대 8개를 대화 옆에 둔다.
- **첫 실행 안내**: 환영 → 엔진(구독 상태, 공식 설치 명령, 데이터 전송 안내) → 문서 도구(설치 버튼) → 쓰는 법.
- **MCP·스킬**: 두 엔진의 실제 MCP 서버·스킬을 한 표로 보여 준다.
  - 다른 엔진에 넣는 일은 누를 때만 한다. 쓸 경로를 먼저 보여 준 뒤 공식 명령(`claude mcp add-json`, `codex mcp add`)이나 폴더 복사로 쓰고, 덮어쓰지 않는다.
  - Codex 앱 내장 서버는 복사 대상에서 뺀다.
  - 이음 사용법 스킬을 엔진에 넣을 수 있다.
- **HOP 연동 1단계**: HWPX/HWP의 "HOP로 열기"(그 밖의 형식은 기본 앱으로 열기).
  - 그 앱에서 저장하면 12시간 동안 지켜보다가 다음 판("HOP에서 저장")으로 자동으로 받는다.
- **이벤트**: 문서 도구 상태(`tools.status`)를 화면에 실시간으로 알린다.

### 실제 검증됨
- **실제 Codex**(`scripts/smoke-convert.ts`, 5/5)
  - 열린 마크다운 → 새 HWPX(hallym-kordoc)
  - 출처 기록
  - 같은 마크다운 → 새 PPTX 4장(ieumoffice)
  - 워드 문장 고치기 → 수정안 → 적용(r2)
  - 화면: 대화 카드, `@` 목록, 새 문서 칩
- **실제 엔진 상태**: 게이트웨이 환경에 가짜 `ANTHROPIC_API_KEY`를 넣어도 Claude(max)·Codex(pro) 모두 구독으로 판별·실행했다.
- **이음 CLI(Linux)**: md↔docx, csv→xlsx, 시트 읽기, docx→PDF, 쪽 PNG(각 약 2.6초)
- **단위 테스트 55건**(이음 실도구 테스트 3건 포함)
- **화면**(Playwright): 워드·PPT·엑셀 쪽 보기/글 보기, 연결 화면 문서 도구, 첫 안내, MCP·스킬 표와 쓰기 확인

### 미검증 · 제한

## 앱 안 오피스 편집 — 워드 (2026-10-28)

**방향 수정(사용자)**: "내 CLI 앱 안에서 올인원으로 다하는" 워크플로우.
- 이음오피스를 따로 설치해 쓰는 것이 아니다. 모든 형식을 Workbench 탭에서 열어 바로 고친다.
- AI는 Workbench 대화(실제 Claude·Codex 세션)에 남는다. 판·수정안 규칙도 그대로다.

### 구조
- **`vendor/ieumoffice`**: 이음오피스 v0.12.7(`30ff4f0`)을 `scripts/fetch-ieum.sh`로 받는다. 커밋하지 않고, 원본을 고치지 않는다.
- **`apps/office`**: 이음의 편집 화면을 Vite로 빌드한다. Electron 프리로드 대신 브라우저 다리(`bridge.ts`, `docs.ts`)를 넣는다.
  - 열기는 판의 바이트, 저장은 다음 판(`expectedRevision`)이다. 오래된 판 위 저장은 거부하고 Workbench가 안내한다.
  - 편집기 자체 AI(패널, 리본 AI 버튼, 오른쪽 메뉴 AI 항목, F7 교정)는 숨기고 막는다.
  - 저장하지 못한 편집: 편집기가 30초마다 만드는 복구 사본을 브라우저 저장소에 둔다. 충돌 중 떠나면 바로 남기고, 다음에 열 때 되살린다.
- **별도 출처**: 편집기 화면은 두 번째 포트(`editors-port`, 실행마다 유지)에서만 열린다.
  - 문서마다 그 문서만 읽고 저장하는 토큰을 준다.
  - Workbench 창의 토큰·저장소·화면에는 닿지 않는다. 편집기 코드에 허점이 있어도 게이트웨이 전체로 번지지 않는다.
- **WebKit 보정**: TipTap(`@tiptap/react` 3.31)은 화면에 붙지 않은 편집기를 1ms 뒤 지운다. WebKit에서는 이 타이머가 React 첫 효과보다 먼저 돌아 첫 편집기가 지워지고 화면이 하얘졌다. 빌드 때 10초로 바꾼다(원본 무수정, 바뀌면 빌드가 멈춤).
- **라이선스**: `office/THIRD-PARTY-NOTICES.txt`(이음 LICENSE·NOTICE, Unicode, 글꼴, 실제로 묶인 npm 35개).

### 동작
- `.docx`는 "편집"이 기본이다. 다음 때 먼저 저장해 새 판을 만든다.
  - Ctrl+S
  - 대화 탭이나 다른 화면으로 옮길 때
  - "글 보기"로 바꿀 때
  - 요청을 보낼 때(기존 규칙)
- 다른 곳(AI 수정안 적용 등)에서 새 판이 생기면
  - 저장 안 된 편집이 없으면 바로 새 판을 보여 준다.
  - 있으면 "최신 판 열기(한 번 더 확인 후 버림) / 내 편집을 새 판으로(다른 판은 기록에 남음)" 중에서 고른다.
- 수정안 비교·옛 판 보기 중에도 편집기는 숨긴 채 살아 있어 편집이 유지된다.

### 실제 검증됨
- **Chromium**(`scripts/office-editor-check.ts`, 실제 화면·게이트웨이, 12/12)
  - 열기, AI 숨김(홈·검토 탭), Ctrl+S→r2, 탭 이동 저장, 다시 열기
  - 충돌 안내와 "내 편집을 새 판으로", 새 판 자동 표시
  - 충돌 중 떠난 편집 되살림, 최신 판 열기, 보기 전환 저장
  - 출처·토큰 격리(앱 출처에 편집기 없음, 다른 문서·앱 API 거부)
- **WebKitGTK 2.52**(`scripts/webkit-office-check.py`, 3/3): 열기 3.5초, 입력 시 "저장 안 됨", Ctrl+S→r2. CSS anchor 위치 지정·`text-autospace`·`zoom` 지원 확인.
- **단위 테스트 60건**(편집기 출처·토큰·저장 거부 5건 추가)

### 미검증 · 제한
- 한글 입력기(fcitx5·ibus)로 직접 치는 확인은 사람이 해야 한다. 자동 검사는 `insertText`로 넣었다.
- 아직 안 되는 것: docx 안 큰 그림(지연 로딩 `genoffice-docx-media:`), 암호 문서, 다른 이름으로 저장·내보내기·인쇄.
- 옛 판 보기와 "글 보기"는 아직 이음 CLI 렌더를 쓴다(이음 설치 필요).
- 디자인(doory) 편집기는 아직 앱과 같은 출처다.
- 다른 형식은 다음 차례다. 조사 결과 슬라이드·엑셀은 문서 처리가 Electron 메인 프로세스에 있어서 게이트웨이로 옮겨야 한다(엑셀은 Rust 보조 프로그램 포함).
