# 진행 기록

기준: [PRD v1.0](PRD-v1.0.md) · 시안 [assets/ui](../assets/ui) · 2026-10-16 · Linux 노트북(CachyOS, niri, Wayland)

## 단계 A — 설치형 기반과 실제 엔진 연결

### 구현됨

| 항목 | 내용 |
|---|---|
| 설치형 앱 | Tauri 2 셸이 게이트웨이(Node)를 자식 프로세스로 띄우고 창을 연다. 종료 시 게이트웨이도 정리. 단일 실행. |
| 게이트웨이 | HTTP 명령 + SSE 이벤트(재연결 시 `since` 재생, 범위 밖이면 스냅샷 재요청). SQLite(`~/.local/share/achmage-workbench/state.sqlite`)에 작업·폴더·세션·대화·requestId. |
| Codex | 공식 `codex app-server`(PATH와 ChatGPT 번들 중 최신). 스레드 시작·재개, 턴, 중단, 승인(명령·파일·권한), 계획, 사용량. 쉬면 엔진을 내리고 다음 요청 때 같은 스레드로 재개. |
| Claude | 공식 Claude Agent SDK + 설치된 `claude`. 스트리밍 입력, `canUseTool` 승인, 중단, `resume`, TodoWrite 계획, `rate_limit_event` 사용량. 쉬면 프로세스를 닫고 다음 요청 때 재개. |
| 기본 화면(시안 01) | 상단: Achmage · 작업 ▾ · 새 작업 · 작업 제목(눌러서 이름 바꾸기) · 확인 N · ⋯(연결·로그인·사용량). 분류 경로 · 상태 한 줄(상태·엔진·실행 위치) · 세션 탭(두 개 이상일 때, 두 번 눌러 이름 바꾸기) · 대화 한 열 · 입력창 하나(엔진·세션 선택) · 다른 작업 진행 수. |
| 대화 표시 | 도구 호출·생각을 한 줄로 접기, 승인 카드(Enter 허용 / Esc 거절), 계획 카드, 중단 표시. Markdown 렌더. |
| 새 작업 | 첫 화면에서 엔진(Claude/Codex)·폴더(없이 시작 / 선택 / 최근)를 고르고 바로 보내기. 폴더 없이 시작하면 앱 전용 폴더 생성. |
| 작업 찾기(시안 04) | 검색, 최근/폴더 탭, 중첩 폴더 생성·접기, 폴더별 새 작업, 확인 필요 바로가기. 분류 이동은 앱 안 분류만 바꾸고 실제 파일은 그대로. |
| 입력 | 한글 조합 중 Enter 오발송 방지, 작업·세션별 초안 보존. |
| 모델 · 추론 강도 | 입력창 오른쪽 선택기. 목록은 엔진이 직접 알려준 값(Codex `model/list` + `config/read`, Claude Code initialize, 24시간 캐시). "기본"은 사용자 설정(예: `~/.codex/config.toml`)을 따른다. 바꾸면 다음 메시지부터 적용: Codex는 매 턴 모델·강도를 명시해 "기본으로 되돌리기"도 실제로 되돌아가고, Claude는 실행 중인 프로세스에 `setModel`·`effortLevel` 적용. 상태 팝오버에 엔진이 보고한 "최근 응답" 모델 표시. |
| 왼쪽 사이드바 | PRD 2.1대로 기본은 닫힘. 상단 왼쪽 버튼으로 고정 열기/닫기(기억됨): 새 작업 · 찾기 · 폴더 트리 · + 폴더. |
| 엔진별 외형 | Claude·Codex × 라이트·다크 4가지 룩(Codex 라이트 = 볼트 Minimal 라이트, Claude 다크 = 볼트 다크 + CMDS Operator Console, Codex 다크·Claude 라이트는 새 세트). 보고 있는 세션의 엔진 룩이 창 전체를 입는다. 엔진 탭(자체 표시·색·글꼴), 세션 탭·사이드바·화자 표시에 엔진 표시. 오른쪽 클릭 빠른 메뉴, 옆 패널 외형 설정(색 13가지·글꼴·크기·줄 간격·굵기·말풍선·모서리·테두리·빛·엔진별 라이트/다크 고정, 즉시 미리 보기). 입력창 빛 궤적, 대기 말풍선, 스트리밍 꼬리, 궤도 로더(CMDS Achmage), `prefers-reduced-motion` 정지. 설계: [엔진별 외형과 한눈에 보기](design/엔진별-외형과-한눈에-보기.md) |
| 글꼴 | 사용자가 만든 Achmage SameTone 1.000(가변, OFL)을 기본으로 앱에 포함(WOFF2 2.1 MB + OFL·NOTICE·licenses). 설치본이 있으면 그것 우선. |
| 한눈에 보기 | Ctrl+K 또는 상단 버튼(진행 수·새 답 수). 모든 작업의 세션을 "내 확인 필요 / 진행 중 / 최근" 카드로, 카드마다 그 엔진 룩. 검색·키보드. Ctrl+Tab 최근 세션 전환기. 세션 탭은 활성+최근 4개, 나머지 `+N`. 안 본 답 표시. |
| 자동 제목 | 모델 호출 없이 요청들에 반복되는 핵심어로 세션·작업 제목을 만들고, 새 핵심이 확실히 앞설 때만 바꾼다. 직접 바꾼 이름은 고정, 비우면 자동. 기존 세션도 시작 시 한 번 채움. |
| 대화 층위 | 턴 단위(번호·시각이 있는 요청, 답, 흐린 작업 기록 띠, 끝남·소요 시간), 긴 답을 읽는 동안 그 요청이 위에 고정, 오른쪽 턴 레일(요청 눈금·승인 대기·현재 위치). |
| 화면 설정 저장 | 게이트웨이 DB(`PUT /api/prefs`, `prefs.updated` 이벤트). 게이트웨이가 지난 포트를 다시 써서 창 저장소(초안 등)가 재시작 뒤에도 유지된다. |
| 로그인 | Codex: app-server `account/login/start` → 브라우저. Claude: `claude auth login --claudeai`. 상태는 공식 명령 값만 표시, 모르면 "확인 불가". |

### 실제 검증됨 (모의 응답 없음)

- `scripts/smoke-real.ts`로 **설치본과 같은 묶음 게이트웨이**(`host.mjs`)를 대상으로 **14/14 통과**(2026-10-16, 모델·강도 전환 단계 포함: Claude `setModel` → `claude-sonnet-5-5`, Codex `thread/read` → `gpt-6-luna · low`).
  - 검증 항목: 응답 · 승인 → 파일 생성 · 거절 → 미실행 · 중단 → "중단됨" · 유휴로 엔진을 내린 뒤 같은 세션 재개 · 앱 재시작 뒤 같은 세션 재개.
- `scripts/ui-shots.ts`로 실제 화면(Chromium)을 따라감: 새 작업 → Claude 응답 → Codex 세션 추가 → 승인 카드 → 허용 → 결과 → 작업 찾기·폴더 생성.
- 설치된 앱(시스템 WebKitGTK 2.52)이 niri/Wayland에서 뜨고, 화면이 오류 없이 시작(`client.log`), 종료 시 게이트웨이 정리.
- 단위 테스트 24개(`npm test`): 두 엔진 변환기, 요청 중복 방지, 응답 중 중복 전송 거절, 재시작 복구, 이벤트 재생 범위, 한글 조합 Enter, 대화 묶기, 모델·강도 저장, Codex 기본 모델·강도, 자동 제목(조사·어미, 핵심 추적, 흔들림 방지, 수동 고정).

### 측정 (Linux, 유휴, 앱 스코프 전체 PSS)

| 구성 | 시스템 WebKit 설치본 | AppImage |
|---|---|---|
| Tauri 셸 | 108 MB | 109 MB |
| WebKit 화면 + 네트워크 | 140 + 33 MB | 139 + 34 MB |
| AppImage 런타임 | — | 22 MB |
| 게이트웨이(Node) | 83 MB | 85 MB |
| **합계** | **363 MB** | **388 MB** |

- **2026-10-16 엔진별 외형·한눈에 보기 이후 재측정(설치본, 엔진 유휴 종료 뒤)**: 셸 99 + 게이트웨이 84 + WebKit 화면 213 + 네트워크 33 = **431 MB**. WebKit 화면이 140 → 213 MB로 늘었다. 글꼴 파일을 뺀 A/B에서도 214 MB라 SameTone 때문은 아니다. `WEBKIT_DISABLE_COMPOSITING_MODE=1`이면 410 MB(−21 MB)지만 애니메이션 품질 영향이 있어 적용하지 않았다. 원인 분석(합성 레이어·필터·스크립트 크기)은 후속.
- 시작 직후 1분 동안은 상태 확인용 Codex app-server(약 320 MB)가 떠 있다가 유휴 종료된다.
- PRD 목표 "유휴 UI + 게이트웨이 300 MB 이하"를 이전 단계 기준 **약 60 MB**, 현재 **약 130 MB** 넘는다. 대부분 WebKitGTK 기본 비용. 엔진은 쓸 때만 추가(Codex app-server 약 234 MB, Claude 세션당 약 250–340 MB).
- 엔진 유휴 종료 전에는 Codex app-server가 상주해 593 MB였다.
- 설치 크기: 실행 파일 + 게이트웨이 1.3 MB + 화면 0.4 MB (시스템 WebKit·Node·각 CLI 별도). AppImage 106 MB(WebKit 포함). 화면 첫 전송 gzip 127 KB.
- 비교 기준(같은 노트북, 2026-10-16 RSS): Orca 셸 약 1.03 GB.

### 미검증 · 제한

- **Windows**: 빌드·실행 미검증(NSIS 미작성). Linux 결과로 대신하지 않는다.
- **로그아웃 상태에서 로그인 완료**: 로그인 시작 경로만 구현. 실제 로그인 완료는 확인하지 못함(두 계정 모두 로그인된 상태).
- **창 닫기 = 앱 종료**: PRD의 "트레이로 이동, 작업 유지"는 미구현. 닫으면 진행 중 응답이 멈추고 다음 실행에서 "멈춤"으로 표시된다.
- **Node 24+ 필요**: 게이트웨이를 시스템 Node로 실행한다(번들하지 않음).
- 이 노트북 설치는 시스템 WebKit 실행 파일. 배포용 AppImage는 별도로 빌드된다.
- Claude의 추론 강도는 엔진이 적용 결과를 보고하지 않아 "최근 응답"에는 모델만 표시된다(Codex는 모델·강도 모두).
- 세션별 승인 방식 선택 없음(Claude: 매번 묻기, Codex: on-request + workspace-write).
- Claude 세션은 사용자 설정(`~/.claude`)을 읽으므로 Achmage 훅도 함께 실행된다.
