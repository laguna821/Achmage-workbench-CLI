- 시작 직후 1분 동안은 상태 확인용 Codex app-server(약 320 MB)가 떠 있다가 유휴 종료된다.
- PRD 목표 "유휴 UI + 게이트웨이 300 MB 이하"를 이전 단계 기준 **약 60 MB**, 현재 **약 130 MB** 넘는다. 대부분 WebKitGTK 기본 비용. 엔진은 쓸 때만 추가(Codex app-server 약 234 MB, Claude 세션당 약 250–340 MB).

- 설치 크기: 실행 파일 + 게이트웨이 1.3 MB + 화면 0.4 MB (시스템 WebKit·Node·각 CLI 별도). AppImage 106 MB(WebKit 포함). 화면 첫 전송 gzip 127 KB.
- 비교 기준(같은 노트북, 2026-10-16 RSS): Orca 셸 약 1.03 GB.

- ~~창 닫기 = 앱 종료~~ → 2026-10-28 창을 닫으면 트레이로 숨고 작업이 이어진다(트레이 메뉴: 열기·끝내기, 다시 실행하면 창이 나타남). 창이 뒤에 있으면 답·확인 필요·실패를 OS 알림으로 알린다(⋯에서 끔). 트레이가 없는 데스크톱에서는 다시 실행해서 연다. 실제 창 닫기·알림은 자동 검사가 없어 사람이 확인한다.
- **Node 24+ 필요**: 게이트웨이를 시스템 Node로 실행한다(번들하지 않음).
- 이 노트북 설치는 시스템 WebKit 실행 파일. 배포용 AppImage는 별도로 빌드된다.

- ~~세션별 승인 방식 선택 없음~~ → 2026-10-28 입력창 아래 권한(묻기·자동·전체 접근)으로 해결. 아래 "여러 세션 · 일하는 중 대화 · 권한" 참고.
- Claude 세션은 사용자 설정(`~/.claude`)을 읽으므로 Achmage 훅도 함께 실행된다.

## 단계 B — 대화 안 문서

- 문서는 작업 폴더의 실제 파일과 게이트웨이의 불변 리비전(`dataDir/artifacts/<id>/r<N>`)으로 다룬다.
  - 오래된 리비전으로 저장하거나 디스크가 바뀐 상태에서 저장하면 거부한다.
  - 되돌리기와 외부 변경 채택도 새 리비전으로 남긴다.
- AI 수정은 고정된 판의 작업 사본(`.workbench/drafts`)에서 수정안으로 만든다.
  - 수정안은 기준 판 위에서만 적용한다.
  - 한 문서에 동시에 수정안을 만드는 세션은 하나다.
  - "다른 세션에" 보내기는 검토 전용이고, 답은 원래 대화에 카드로 돌아온다.
- 형식: Markdown(CodeMirror), HTML(격리 미리보기), PDF(pdf.js, PDFCraft 쪽 편집 → 새 파일), HWPX/HWP(kordoc: 글 보기·패치·쪽 미리보기, HWP는 읽기 전용).
- 실제 엔진 검증(`scripts/smoke-docs.ts`): HWPX 대표 시나리오 통과. Markdown 두 단계는 Claude 턴이 멈춰 실패했고, 원인은 아직 진단하지 않았다.

## 디자인 문서 — doory 편집기 (2026-10-20)

조사: [design/doory-연동-조사.md](design/doory-연동-조사.md).

**결정**
- doory(오픈소스 Canva 대안)는 서버 없이 편집기만 들여온다.
- AI는 Codex·Claude 세션이 파일을 직접 고친다. 편집기 안에는 AI 기능을 붙이지 않는다.

### 구현됨
- **형식**: `<이름>.design.json`(doory 문서 schema v1)이 다섯 번째 문서 형식 "디자인"이다.
  - 이미지는 `<이름>.assets/<내용 해시>.<확장자>`에 둔다. 내용 해시라 리비전마다 같은 바이트를 가리킨다.
  - 작업 폴더 밖이나 `.workbench` 아래 경로는 열지 않는다.
- **편집기**: `vendor/doory`는 고정 커밋 `2eb2557c` 그대로다(`scripts/vendor-doory.sh`).
  - `apps/design`이 doory의 `EditorAdapter`를 Workbench 게이트웨이에 연결하고, `/design/` iframe으로 띄운다.
  - 자동 저장은 새 리비전이 된다. 다른 곳에서 새 판이 생기면 저장을 거부하고, 편집기 충돌 안내에서 "최신 판 열기"나 "사본으로 저장"을 고른다.
  - 서버가 필요한 템플릿·스티커·브랜드·공유·원격 AI는 뺐다.
  - 글꼴은 SameTone(기본)과 doory 기본 글꼴, 이 컴퓨터 글꼴(fontconfig)이다.
  - 자주 보이는 메뉴는 한국어로 바꿨다.
  - "작업 폴더에 저장"(내보내기)은 디자인 옆에 파일로 쓰고, PDF는 문서로 추적한다.
- **대화 흐름**
  - 디자인 파일 카드에 1쪽 썸네일이 보인다.
  - 수정안 카드는 전/후 썸네일과 개체 단위 변경(추가·삭제·글자·위치·모양)을 보여 준다. 비교 화면은 페이지별 전/후 그림과 변경 목록이다.
  - 썸네일은 숨은 iframe에서 doory 엔진으로 그린다. 45초 동안 안 쓰면 iframe을 내린다.
  - 편집기에서 고른 개체는 요청의 참조(`DocRef.selection.pageId/objectIds`)가 된다.
- **엔진 안내**: 프롬프트에 디자인 규칙(구조, 중심 기준 좌표, type 이름, 이미지 경로, 유효한 JSON)과 현재 개체 목록을 넣는다.
  - 깨진 JSON 수정안은 이유를 표시하고 적용하지 않는다.
- **새 디자인**: 문서 메뉴에서 크기 프리셋(정사각·카드뉴스·세로·가로·A4)으로 만든다.
- **크레딧**: 시작 화면과 편집기 아래에 AAL 크레딧을 항상 보인다.
- **셸로 쓴 파일 추적(모든 형식)**: 엔진이 셸 명령으로 쓴 문서 파일도 턴이 끝날 때 작업 폴더를 훑어 추적한다(깊이 3, 4000항목 제한).
- **이벤트 스트림**: 연결 즉시 헤더를 보낸다. 첫 이벤트 전까지 "연결 끊김"으로 보이던 문제를 고쳤다.

**사용자 방향**: 이음이 Electron이라고 Workbench까지 Electron처럼 만들 필요는 없다. Workbench 안 이음 편집기는 Rust/Tauri 방식으로 만든다.

- **구조**: 웹뷰 하나에서 모두 돈다. 별도 프로세스는 없다.
  - 편집 화면과 preload: 이음 것을 그대로 쓴다. 통신은 페이지 안 전송으로 간다.

    - 경로·해시·압축: 브라우저 라이브러리
    - 창·메뉴·대화상자: 없음
    - 안내 상자: Workbench 알림으로
  - 쓰지 않는 기능은 빼고 묶는다: 이음 AI, 템플릿·AI 쪽 생성, 발표자 창, 숨은 창 PDF·인쇄.

  - 편집 로직(`apps/sheets/src/main`): 페이지의 Web Worker에서 원본 그대로 돈다.
  - 이음의 Rust xlsx 엔진(`apps/sheets/native/xlsx-engine`, 수식은 IronCalc)은 원래 따로 띄우는 보조 프로그램이다. 여기서는 WebAssembly(`wasm32-wasip1`)로 빌드해 Worker 안에서 부른다(`apps/office/native/xlsx-wasm`).
    - WASI에서 안 되는 두 곳은 빌드 때 사본에 패치한다(`wasi.patch`): 임시 폴더를 `/tmp`로, 시트 색인을 스레드 대신 바로 실행.
    - 엔진의 파일·시계·난수 요청은 Workbench의 작은 WASI 층(`platform/wasi.ts`)이 메모리 속 작업 사본으로 답한다.
  - 빌드에 Rust `wasm32-wasip1` 대상과 WASI sysroot 34가 필요하다. sysroot는 압축 해제 전에 sha256을 확인한다(C로 된 bzip2·zstd용). `cargo --locked`로 빌드한다.
- **판에 수식 결과 저장**
  - 이음의 저장은 수식 칸의 저장된 값을 파일에 있던 그대로 두고, Excel이 열 때 다시 계산하게 한다(`fullCalcOnLoad`).

  - 엔진이 보증하지 못하는 결과(없는 함수 `#NAME?`, 엔진 실패, 로캘 함수 NUMBERSTRING·DOLLAR)는 파일 값을 그대로 둔다.
  - 행·열·시트 구조를 바꾼 저장과 큰 통합 문서(8MB, 50만 칸, 수식 2만 개 초과)는 이음 그대로 저장한다.
- **단축키**: Ctrl+S·Ctrl+Z·Ctrl+Y를 페이지 키맵이 편집기의 메뉴 명령으로 보낸다.
- **저장 상태**: "저장 안 됨"은 편집기의 편집 기록 수로 판단한다.

### 구현됨

- 입력창 왼쪽 아래 "계획 먼저". 켜고 보내면 엔진은 이번 차례에 계획만 세우고(아무것도 바꾸지 않음) "이 계획대로 진행할까요?" 카드가 뜬다: **계획대로 진행**(Enter) / **더 다듬기**(Esc). 진행하면 세션 권한으로 실행하고 "계획 먼저"가 꺼진다. 더 다듬기면 켜진 채로 고칠 점을 보내면 된다. 계획을 기다리는 중에 다른 요청을 보내면 그 카드는 "다른 요청으로 넘어감". 요청에는 "계획 먼저" 표시. 문서 아래 서랍에서도 같은 단추.
- Claude: Claude Code의 계획 모드(`permissionMode: "plan"`). 끝의 ExitPlanMode가 카드가 되고(계획 본문이 카드에), 진행하면 `setMode`로 세션 권한으로 돌아가 같은 턴에서 일한다. 전체 접근이어도 계획 확인은 늘 묻는다.
- Codex: 그 차례만 읽기 전용 샌드박스·묻지 않음(`never`)에 계획만 세우라는 안내를 붙여 보낸다(앱 서버의 계획 모드는 실험 API라 쓰지 않음). 턴이 끝나면 게이트웨이가 카드를 띄우고, 진행은 "계획대로 진행해 주세요."를 원래 권한으로 보낸다.
- 작업 중에 보낸 "계획 먼저" 요청은 끼어들지 않고 끝나면 보낸다(대기열에서도 계획 먼저를 유지).

### 실제 검증됨

- 단위 테스트 5건(`plan.test.ts`). 전체 113.
- `scripts/plan-check.ts` 6/6(Codex·Claude 같은 단계): 계획과 카드, 더 다듬기는 계속 계획, 진행은 세션 권한(가짜 엔진이 보고: Claude `acceptEdits`, Codex `workspaceWrite`)으로 실행하고 토글이 꺼짐.
- **실제 엔진** `scripts/smoke-plan.ts` 4/4(임시 폴더, "hello.txt에 hi"): 두 엔진 모두 계획 단계에서는 파일을 만들지 않았고, 진행 뒤에 만들었다. Claude는 ExitPlanMode로 물었고 Codex는 턴 뒤 게이트웨이가 물었다.

### 미검증 · 제한

## `/` 명령·스킬 (2026-10-28)

### 구현됨

- 입력창 맨 앞에 `/`를 치면 그 세션 엔진의 명령과 스킬 목록(명령·스킬 표시, 설명, 인자 힌트). 글자를 치면 좁혀지고(이름이 그 글자로 시작하는 것 먼저, 그다음 스킬), ↑↓·Enter·Tab으로 고르고 Esc로 닫는다.
- Claude: 그 세션의 Claude Code 프로세스에 `supportedCommands()`(Claude Code 기본 명령은 명령, 사용자·프로젝트·플러그인 명령과 스킬은 스킬). 프로세스가 없으면 그때 띄우고 다음 요청이 그대로 쓴다(따로 확인용 프로세스를 띄우지 않아 훅이 헛세션을 남기지 않음). 고른 `/이름 …`은 그대로 Claude Code에 간다.
- Codex: `skills/list`(작업 폴더 기준, 켜진 스킬). `/이름 …`으로 보내면 Codex 방식(`$이름 …` + `skill` 입력)으로 바꿔 보낸다. 목록에 `/compact`도 있다.
- `/compact`는 두 엔진 모두 "지금 압축"과 같다(요청으로 보내지 않음).

### 실제 검증됨

- `scripts/commands-check.ts` 8/8(Codex·Claude 같은 단계): 목록, 좁히기와 고르기, 고른 스킬이 엔진에 스킬로 감(가짜 엔진이 받은 모양을 보고), `/compact` 압축.
- 실제 엔진 목록(요청은 보내지 않음): Codex 76개(스킬 75 + compact), Claude 77개(명령 55, 스킬 22). 각 1.3~1.6초.

### 미검증 · 제한

- 실제 엔진에서 스킬을 골라 실행해 보지는 않았다(목록만 확인).
- 세션이 아직 없는 새 작업(엔진만 고른 상태)에서는 목록이 없다. 첫 요청 뒤부터 나온다.

## 그림 — GPT Image(Codex 전용) (2026-10-28)

참고: 사용자 Obsidian 플러그인 CMDS Achmage 1.3.0의 Plan image generation. 플러그인은 자체 ChatGPT 로그인으로 Codex responses 엔드포인트에 `image_generation` 도구를 직접 부른다. Workbench는 사용자의 Codex 로그인 그대로 Codex 0.160의 내장 그림 도구(`image_gen`, 기능 `image_generation` 기본 켜짐)를 쓴다. API 키는 쓰지 않는다.

### 구현됨

| 항목 | 내용 |
|---|---|
| 그리는 방법 | 그림 한 장 = Codex 턴 하나. 게이트웨이가 "image_gen을 한 번만 부르고 명령·파일 작업은 하지 말라"는 지침과 프롬프트(템플릿 → 요청 → 비율 → 항상 붙일 규칙, 플러그인 순서)를 보낸다. Codex가 알린 `imageGeneration` 항목에서 그림(Codex가 자기 폴더에 저장한 파일, 없으면 base64)을 받아 작업 폴더 `images/<날짜>-<요약>.png`에 복사한다. 덮어쓰지 않는다. |
| 입력창 "그림" | 왼쪽 칸(권한·컨텍스트 다음). 메뉴: 다음 요청을 그림으로, 템플릿(기본 5개 + 내 템플릿, "관리"), 비율(자동·가로·세로·정사각), 투명 배경, 그릴 세션. 템플릿을 고르면 켜지고, 요청 하나를 보내면 다시 꺼진다(고른 것은 기억). 켜진 동안 입력창 위 칩과 자리표시가 바뀌고 `@`는 꺼진다. |
| Claude 대화 | Claude는 그리지 못하므로 이 작업의 Codex 그림 세션("그림", 처음 쓸 때 만듦)이 그린다. 칩과 메뉴에 그렇게 쓰고, 그림은 Claude 대화에 카드로 보인다. 화면은 Claude 대화에 머문다. Codex 세션에는 "…에서 온 요청"으로 남고, 그 답은 새 답으로 세지 않는다. 그릴 세션을 직접 고르거나 새로 만들 수 있다. |
| 그림 카드 | 그리는 중("멈춤") → 그림("열기"·"경로 복사"·"현재 문서에 넣기"·"다시 그리기") 또는 못 그림(이유: 그림 없이 끝남, 멈춤, 이미지 한도와 다시 쓸 수 있는 때, 앱 재시작). 요청에는 "그림" 표시. 마크다운 내보내기에도 남는다. |
| 여기에 그림 그리기 | 마크다운 편집기 머리줄 "그림" 또는 Ctrl+Alt+G. 커서 자리에 작은 양식이 열린다(고른 글이 설명이 됨). 그리는 동안 그 자리에 표시가 있다(글이 아님, 편집에 따라 움직이고 보기 전환·문서를 떠나도 남음). 끝나면 `![설명](images/….png)`를 그 자리에 넣어 다음 판으로 저장한다. 문서의 Codex 세션이 일하는 중이면 그림 세션이 그린다. |
| 미리보기·서랍 | 마크다운 미리보기는 작업 폴더의 그림(문서 기준 상대 경로)을 보인다. 문서 아래 서랍은 그 턴의 그림을 작게 보인다. |
| 템플릿 | 내 템플릿과 규칙은 게이트웨이 데이터 폴더 `image-templates.json`. 플러그인의 템플릿은 그 `data.json`에 있어 읽지 않았다(기본 5개만 옮기고 이름을 한국어로). |
| 게이트웨이 | `POST /api/sessions/:id/images`, `GET /api/images/:id`, `GET·PUT /api/image-templates`, `GET /api/works/:id/image?path=`(작업 폴더 안의 png·jpg·webp·gif만, 실제 경로 확인). 그림 기록은 SQLite meta에 300개까지. |

## 에이전틱 브라우징 — Playwright CLI (2026-10-28)

설계: [워크스테이션-다음설계 5장](design/워크스테이션-다음설계.md#5-에이전틱-브라우징). 사용자 방향: "브라우징은 Playwright CLI를 붙이면 되지 않을까?", 그리고 "앱에서 편하게 로그인 + 껐다 켜도 다시 로그인 안 하게".

### 구현됨

| 항목 | 내용 |
|---|---|
| 도구 | Microsoft Playwright CLI(`@playwright/cli` 0.1.22, Apache-2.0)와 그 판이 정한 Chromium(Chrome for Testing 155). ⋯ › "에이전트 브라우저"나 입력창 아래 "브라우저"에서 설치. 앱 데이터 폴더(`agent-browser/`)에만 설치하고, npm SHA-512와 실행 파일 SHA-256(고정값)을 확인한다. |
| 창 하나, 프로필 하나 | 앱 데이터 폴더의 프로필 하나를 모든 실행에 쓴다(0700). 한 번 로그인하면 앱을 껐다 켜도 유지. 한 번에 한 세션만 창을 쓴다(다른 세션이 쓰는 중이면 거절, 쉬는 세션의 창은 닫고 넘김). 30분 쓰지 않으면 창을 닫는다(로그인은 프로필에 남음). |
| "브라우저" 알약 | 입력창 왼쪽 컨텍스트 고리 다음. 세션마다 켜고 끄며 기본은 꺼짐(첫 요청 전에도 켤 수 있음). 펼치면: 켜기, 창 상태("이 세션이 쓰는 중 · 제목" / 다른 세션 / 로그인 창), "창 보기"(niri로 앞으로), "멈춤"·"다시 쓰게 하기", 로그인, 권한별 뜻. 창을 쓰는 동안 알약에 사이트와 점(명령 중 깜빡임, 움직임 줄이기면 멈춤). |
| 로그인하기 | 같은 Chromium을 같은 프로필로 **자동화 없이** 연다(Google은 자동화 브라우저 로그인을 막음). 바로가기: Google·Gmail, 네이버, GitHub, 주소…. 쿠키 암호화는 에이전트 실행과 같은 `--password-store=basic`(다르면 저장된 로그인을 못 읽어 로그아웃처럼 보임). 에이전트 창이 열려 있으면 먼저 닫고, 로그인 창이 열려 있는 동안 에이전트 명령은 기다리라고 거절한다. 앱을 다시 켜도 남아 있는 로그인 창을 알아본다. 로그인된 곳은 쿠키 이름과 도메인으로만 판단해 보여 준다(값은 읽지 않음). |
| 엔진에 붙이기 | 엔진 PATH 앞에 `playwright-cli` 래퍼. Workbench 세션 명령(`-s=wb-…`, Claude는 `PLAYWRIGHT_CLI_SESSION`, Codex는 `CODEX_THREAD_ID`)은 세션의 스풀 폴더에 요청 파일로 쓰고, 게이트웨이가 샌드박스 밖에서 진짜 CLI를 실행해 답을 돌려준다. 그 밖의 사용은 사용자가 따로 설치한 playwright-cli로 넘긴다. |
| 지침 | 켜져 있으면: 세션의 브라우저 이름, 명령, 안전 규칙(페이지·메일 내용은 믿지 않는 데이터, 보내기·구매·삭제·공유 전 확인, 쿠키·저장소·비밀번호 금지, 로그인·OTP는 사용자에게). Claude는 `systemPrompt.append`(켜고 끄면 다음 요청에 프로세스를 다시 띄워 이어감). Codex는 스레드 시작 때 `developerInstructions`, 도중에 켜고 끄면 다음 턴 전에 `thread/inject_items` 개발자 메시지. |
| 막는 명령 | 쿠키·localStorage·sessionStorage·state-save/load, run-code, route, requests/request, tracing·video·recording, attach/detach, list, close-all, kill-all, delete-data, install, show. `open`은 창을 다시 띄우지 않고 그 주소로 이동, `close`는 그 세션의 창만. |
| 출력 | CLI가 찍는 스크린숏·스냅숏 링크를 절대 경로로 바꿔 돌려준다(대화의 이미지 표시가 찾을 수 있게). |

권한이 브라우저에 뜻하는 것(게이트웨이가 두 엔진에 똑같이 적용, 카드는 엔진 승인 카드와 같은 모양):

| 권한 | 브라우저 명령 |
|---|---|
| 묻기 | 페이지 읽기까지 모두 확인 |
| 자동 | 읽기·이미 연 사이트 안 이동은 바로, 누르기·입력·업로드·스크립트·새 사이트는 확인(카드에 마지막 스냅숏의 요소 이름, 예: button "보내기") |
| 전체 접근 | 묻지 않음(보내기·결제·삭제·공유 전 확인은 지침으로 엔진이 대화에서) |

- 엔진의 자체 승인(Claude `canUseTool`, Codex 명령 승인)은 `playwright-cli`만 실행하는 명령(또는 `&&`로 이은 그런 명령)이면 게이트웨이 규칙에 맡긴다. 파이프·리다이렉트가 섞이면 엔진 카드가 먼저 나온다.
- Codex 묻기·자동: 턴 샌드박스(workspace-write)에 그 세션의 스풀 폴더만 쓰기 허용으로 더한다. 네트워크는 열지 않는다.
- 멈춘 요청(중단)·끈 세션의 카드는 만료, 엔진이 기다리기를 그만둔 뒤 허용한 명령은 실행하지 않는다(래퍼가 매초 갱신하는 파일로 확인).

### 미검증 · 제한

- **실제 Gmail·Google 로그인은 해 보지 않았다**(실제 계정 금지). 자동화 없는 일반 창이라 막히지 않을 것으로 보지만, Chrome for Testing 판에서 Google이 로그인을 받아 주는지는 사람이 확인해야 한다.
- 쿠키는 `--password-store=basic`(Playwright 기본)이라 사실상 평문과 같다. 보호는 프로필 폴더 권한(0700)뿐이다. 키링(gnome-libsecret)으로 바꾸려면 두 실행 모두 같은 값을 써야 하고, 키링이 잠기면 로그인이 사라진 것처럼 보인다.
- 창은 한 번에 하나다. 두 세션이 동시에 브라우저를 쓰지 못한다.
- "창 보기"는 niri에서만 창을 앞으로 가져온다. 다른 데스크톱에서는 안내만 한다. niri 창 목록의 pid로 창을 찾는 부분만 실측 값과 맞춰 봤고, 실제로 앞으로 가져오는 동작은 사용 중인 화면을 빼앗지 않으려고 자동으로 확인하지 않았다.
- 앱을 다시 켤 때 남아 있는 창 처리(로그인 창 이어받기, 지난 실행의 에이전트 창 닫기)는 구현만 했고 자동 검사가 없다.
- 래퍼는 지침을 따르는 엔진을 위한 안전장치다. 전체 접근의 엔진은 래퍼를 거치지 않고 CLI를 직접 부를 수 있다(Codex 묻기·자동의 샌드박스 안에서는 소켓이 막혀 게이트웨이만 길이다).
- 지침이 바뀐 뒤(`&&` 허용, 명령 하나씩) 실제 엔진으로 다시 돌리지 않았다. 실제 엔진에서 세션 도중 켜기(Codex 주입·Claude 재시작)는 가짜 엔진과 가짜 Responses API로만 확인했다.
- 실제 앱 창(Tauri·WebKitGTK)에서 알약을 눌러 보지 않았다(Chromium 검사만). Windows·macOS 미지원(설치기가 Linux x64 Chromium만 고정).
- 데몬 기록은 Playwright 기본 위치(`~/.cache/ms-playwright/daemon/`)와 `$TMPDIR/pw-…/cli/` 소켓을 쓴다. 창을 띄울 때마다 `~/.cache/ms-playwright/b/`에 약 1KB 기록이 남는다(데이터 폴더 밖, 지우지 않음).

## 문서에 그림 넣기 (2026-10-28)

**사용자 요청**: Obsidian "CMDS Eagle"처럼 R2 키를 한 번 넣어 두면 마크다운에 붙여 넣은 그림이 R2에 올라가 링크로 들어간다. 워드·PPT·엑셀은 다른 앱에서 붙여 넣거나 끌어 놓은 그림이 문서 안에 들어간다.

### 구현됨
- **마크다운**: 붙여넣기·끌어 놓기 → 그 자리에 "그림 넣는 중…" 표시 → `![이름](주소)`가 한 문단으로 들어간다.
  - 표시는 글이 아니라 편집기 위젯이다. 그 사이 자동 저장돼도 판에 남지 않는다.
  - R2를 설정했으면 게이트웨이가 S3 API로 올린다(SigV4를 `node:crypto`로 직접 서명, SDK 없음). 키는 `<키 앞부분><내용 해시 16자>.<확장자>`, `Cache-Control: immutable`. 링크는 공개 주소.
  - 설정이 없거나 올리지 못하면 작업 폴더 `assets/<내용 해시>.<확장자>`에 저장하고 문서 기준 상대 경로로 넣는다. 올리지 못한 이유는 알림으로 보인다.
  - 같은 그림은 한 번만 저장된다(내용 해시). 그림인지는 바이트로 판단한다(PNG·JPG·GIF·WebP·AVIF·BMP·SVG).
  - 글과 그림이 함께 복사된 경우(워드·표·웹 페이지 글)는 글을 붙인다. 브라우저의 "이미지 복사"(그림 + `<img>`만 있는 HTML + 주소 글)는 그림이다.
  - 미리보기: 상대 경로 그림은 앱 토큰으로 받아 보여 준다. 작업 폴더 밖, `.workbench` 아래, 그림이 아닌 파일, 밖을 가리키는 링크는 거절한다.
- **R2 설정**: ⋯ › "그림 올리기 · Cloudflare R2…" 시트.
  - 칸: 계정 ID(대시보드의 S3 API 주소를 붙여도 되고, 그 주소의 버킷도 채움), 액세스 키 ID, 비밀 액세스 키, 버킷, 공개 주소(r2.dev나 연결한 도메인; S3 API 주소는 거절), 키 앞부분(선택).
  - 게이트웨이 데이터 폴더 `image-upload.json`(0600, 통째로 쓰기)에만 있다. 화면에는 비밀 키를 돌려주지 않고 액세스 키는 앞뒤 4자만 보인다. 비워 둔 키 칸은 저장된 값을 유지한다. 로그에 남기지 않는다.
  - "연결 확인": 작은 파일을 키로 올리고, 공개 주소에서 같은 바이트를 읽고, 지운다. 실패하면 이유(키·서명·버킷·권한·시계·공개 접근)를 한국어로 보인다. 저장 전 값으로도 확인한다.
- **워드·PPT·엑셀(앱 안 편집기)**: 붙여넣기·끌어 놓기한 그림이 파일 안에 들어간다(`word/media`, `ppt/media`, `xl/media`). R2는 쓰지 않는다.
  - 워드·엑셀은 이음 편집기의 원래 경로다. PPT 붙여넣기는 새로 붙였다: 페이지가 붙여넣기의 그림·글을 편집기 작업자의 클립보드에 넘긴 뒤 편집기의 붙여넣기를 부른다(Electron 클립보드처럼).
  - PPT 안에서 복사하면 시스템 클립보드에 표시를 남긴다. 다음 붙여넣기가 앱 안 복사인지 다른 앱 것인지 그것으로 가린다.
  - 편집기가 받지 않는 형식(WebP·AVIF·BMP·SVG)은 PNG로 바꿔 넘긴다.
  - 고친 것: 저장 직후 편집기가 다시 열리던 경쟁(게이트웨이의 새 판 알림이 편집기의 "저장됨"보다 먼저 오던 것). 편집기가 저장 시작을 먼저 알린다(`office:saving`).
- **설치 앱(WebKitGTK)의 스크린숏 붙여넣기**: WebKitGTK는 붙여넣기 이벤트에 클립보드의 글과 복사한 파일만 주고 그림 데이터는 주지 않는다. `navigator.clipboard.read()`는 거절(NotAllowedError)한다(둘 다 실측).
  - 그래서 사용자의 붙여넣기가 페이지에 아무것도 보여 주지 않으면, 게이트웨이가 그때만 데스크톱 클립보드의 그림을 읽는다(Wayland `wl-paste`, X11 `xclip`, 그림 형식만).
  - 마크다운은 앱 토큰으로, 편집기는 Workbench 창을 거쳐 받는다(편집기에 포커스가 있을 때만; 편집기 출처에는 새 권한 없음).
- **한글(HWPX)**: 앱 안 편집기가 없다(HOP로 엶). 글 보기에 그림을 붙이면 "그림은 HOP에서 넣어 주세요"라고 알린다. 설정 시트에도 형식마다 안내한다.

### 카드 목록 · 읽기 전용 노트 · 노트 붙이기
- 볼트 폴더를 누르면 가운데(분할 아님)에 카드 목록: 제목(`title` 또는 파일 이름), 앞머리 뒤 두 줄 발췌, 태그 알약(NN 태그 색), 날짜(`date created` 또는 수정 시각), 첫 그림 썸네일, 단계(`DIKM_단계:`), "세션 N". 고정 먼저, 날짜 묶음(오늘·어제·지난 7일·30일·월), "하위 폴더 포함".
- 앱 폴더·작업도 오른쪽 클릭 "카드로 보기": 폴더 = 작업 카드, 작업 = 세션·페이지 카드.
- 카드를 누르면 노트를 읽기 전용 마크다운으로 연다: 속성(키 글자 그대로), `![[그림]]`·`[[링크]]`를 볼트 안에서 찾아 그림·링크로, "Obsidian에서 열기"(`obsidian://open?path=`, 데스크톱은 opener).
- 노트 카드를 입력창으로 끌면(포인터 끌기, 웹뷰의 HTML 끌어 놓기는 쓰지 않음) 읽기 전용 참고 자료로 붙고, 그 요청은 새 세션을 연다(설계: "노트를 붙인 새 세션"). 노트 화면의 입력창은 그 노트가 처음부터 붙어 있다.
  - 게이트웨이는 노트를 그때 내용 그대로 작업 폴더 `.workbench/notes/`에 읽기 전용(0444) 사본으로 두고, 엔진에 사본과 원본 경로, "볼트에 쓰지 말 것"을 알린다. 요청에는 노트 칩이 보이고 마크다운 내보내기에도 남는다. 노트마다 받은 세션을 기억한다("세션 N").
  - 보낼 예정(끝나면 보내기)·끼어들기에도 노트가 같이 간다(`SendMessageRequest.notes`, `QueuedMessage.notes`).
- 검사: 단위(`frontmatter.test.ts` 5, `pkm.test.ts` 4, `pkm.test.tsx` 5 — 앞머리 키 글자·날짜·태그·발췌·첫 그림, 카드 순서, 링크·그림 해석, 두 엔진에 사본 전달, 볼트 바이트 그대로), `pkm-check.ts` 카드 단계(가짜 엔진이 받은 사본 이름을 되말하고 검사가 사본 바이트·권한을 확인).
- 한계: 카드는 목록마다 최대 500장(최근 순). 첫 그림은 노트 앞 48KB 안에서 찾는다. 노트 보기는 4MB까지.

### 페이지 2단계
- **하위 페이지**: 마크다운 페이지 줄의 `+`(또는 메뉴 "하위 페이지") → `A.md` 옆 `A/` 폴더에 새 페이지. 트리에서 그 페이지 아래에 들여 보인다. `A.md`는 옮기지 않아 판·세션 참조가 그대로다.
- **템플릿**: 작업 메뉴 "템플릿으로 새 페이지…", 페이지 메뉴 "템플릿으로 하위 페이지…". 출처 셋: 앱(데이터 폴더 `templates/`), 작업(`.workbench/templates/`), 볼트(`90. Settings/91. Templates/`, 읽기만).
  - 작업 폴더에 복사하며 `title`·`date created`(볼트처럼 `2026-10-28T22:15:35+09:00`)만 채운다. 나머지 앞머리는 키 글자(따옴표·끝 콜론)·빈 값·뒤 공백·순서·줄 끝(CRLF)까지 그대로, 본문도 그대로.
  - 고르는 칸(키 아래 선택지 목록, 그리고 `DIKM_단계:`는 목록이 없어도 다섯 단계)은 선택 화면에서 묻고 기본은 빈칸. 템플릿에 있는 선택지만 받는다.
  - Templater `<% %>`는 실행하지 않고 글자로 남긴다(선택 화면에 안내).
- **끌어 놓아 만들기**: 사이드바에서 세션 줄을 작업 줄에 놓으면 그 작업의 `세션 기록/`에 "세션 기록 페이지"(마크다운 내보내기와 같은 규칙, 같은 작업이면 그 내보내기를 갱신).
- **페이지로 만들기**: 답 아래(마우스를 올리면 보임) "페이지로 만들기" → 그 답(고른 부분이 있으면 그 부분)이 작업 폴더의 새 페이지가 된다(`source: workbench://session/<id>#<메시지>`).
- 새로 만든 페이지는 그 작업의 문서 목록을 펼치고 바로 열린다.
- 검사: 단위(`pages.test.ts` 4: 바이트 보존·CRLF·선택 칸·따옴표, `pkm.test.ts` 2: 세 출처, 볼트 템플릿은 그대로, 하위 페이지·세션 기록·메시지 페이지), `pkm-check.ts` 페이지 단계(두 엔진).
- 한계: 고르는 칸은 모두 여러 개 고르기다. 하위 페이지를 끌어서 다른 페이지 아래로 옮기기는 아직 없다(파일 이동이 필요해 보류).

### 보기와 규칙 (AI 0회)
- **보기**(사이드바 "보기", 가상 폴더): 저장한 질의를 누르면 가운데에 카드. 문법은 NN 그대로 `#태그`(하위 태그 포함), `."DIKM_단계:"="🔵 I"`, `."키"`(값 있음), `."키"=""`(값 없음), `@today` `@yesterday` `@thisweek` `@thismonth` `@last7d`에 `engine:codex` `status:running|idle|error|approval|unseen` `kind:note|page|session|work`를 더했다. `-`는 제외, 나머지 낱말은 제목·발췌에서 찾는다. 읽지 못한 조건은 빼고 보이며 알린다.
  - 대상: 볼트 노트(숨김 폴더 제외), 작업의 페이지(앞머리), 세션, 작업. 뜻이 없는 조건(노트의 엔진 등)은 맞지 않고, 그 부정은 맞는다.
  - 묶기: 날짜(기본)·DIKM_단계:·엔진·상태·종류 또는 앞머리 키. 값이 없으면 "값 없음" 칸에 두고 추정하지 않는다. DIKM 단계는 D·I·K·M·보류 순서.
  - 처음에는 "이번 주 노트"(`kind:note @last7d`, 단계별)와 "진행 중인 세션"을 둔다. 보기 대화상자에서 맞는 개수를 바로 보여 준다. 사이드바 개수는 세션이 바뀌면 다시 센다.
- **규칙**("보기" ⋯ › 자동 정리 규칙): 순서 있는 "조건 → 배치", 처음 맞는 하나만. 조건 = 작업 폴더 경로(그 폴더 안, 경로 단위)·엔진·문서 형식, 배치 = 앱 폴더 경로(없으면 만듦)·태그(`Work.tags`)·고정.
  - 저장한 뒤 새로 생긴, 분류 안 된 작업만 스스로 배치한다(엔진이나 첫 문서가 생길 때 한 번). 손으로 다시 옮긴 작업은 되돌리지 않는다. 시작 화면에서 폴더를 고른 작업은 건드리지 않는다.
  - 기존 작업은 "미리보기"(무엇이 어디로) → 고른 것만 "적용". 분류 안 된 작업이 처음부터 체크된다.
  - 배치된 작업 줄에 번개 표시(“규칙 「…」으로 여기 있음”).
  - 기본 묶음 "디스크 위치대로": 작업 폴더가 들어 있는 폴더 이름으로 앱 폴더를 정한다(앱이 만든 폴더·홈 바로 아래는 제외). 버튼 하나로 넣고, **기본으로 켜 두지는 않았다**(기존 작업 공간을 말없이 바꾸지 않기 위해).
- 검사: 단위(`pkm-views.test.ts` 5: 문법, 종류별 뜻, 값 없음·단계 순서, 보기 저장·개수, 규칙 첫 일치·디스크·자동 배치 한 번·미리보기/적용), `pkm-check.ts` 보기·규칙 단계(두 엔진, 단계별 묶음, `engine:` 보기, 새 작업 자동 배치와 줄 표시, 미리보기→적용).
- 한계: 3층 "AI 제안"(누를 때만 규칙을 제안받기)은 아직 없다. 보기·규칙 편집은 대화상자 하나뿐이다(끌어서 순서 바꾸기 없음, 위·아래 버튼).

### 맥락 카드와 볼트 쓰기 막기 (오케스트레이션과 잇기)
- **작업에 노트 고정**: 노트 카드 오른쪽 클릭 "작업에 고정" → 작업. 작업 카드 목록 맨 위에 보이고, 입력창 아래 볼트 표시에 "고정 노트 N".

## 이 요청 전으로 — 갈래 (2026-10-28)

## 볼트 노트·문서의 옵시디언식 마크다운 (2026-10-29)

사용자가 볼트를 붙여 보니 그림이 안 보이고 `[!NOTE]`가 제대로 그려지지 않았다. 사용자 볼트(노트 1,269개)를 읽기만 하여 실제로 쓰인 문법을 셌다: 웹 그림 1,844곳(R2·S3 등), 콜아웃 3,183곳(quote·note·summary·warning…), HTML 808곳(`<img width>`·`<details>`·`<div>`), `![[노트]]` 넣기 48곳, `==강조==` 68곳.

### 원인과 고친 것

- **웹 그림이 안 보임**: 볼트 노트의 그림을 모두 게이트웨이 토큰을 붙인 fetch로 받으려 해서, R2 같은 다른 출처는 CORS에 막혔다(토큰을 바깥으로 보내려는 것 자체도 문제). 이제 웹 그림은 `<img>`로 바로 그리고(`referrerPolicy=no-referrer`), 토큰을 붙이는 fetch는 게이트웨이 경로(`/api/…`)만 한다. 카드 썸네일도 첫 그림이 웹에 있으면 그 그림을 쓴다(`PkmCard.thumb.url`).
- **콜아웃**: `> [!NOTE] 제목`을 굵은 글자로만 바꾸던 것을 Obsidian처럼 상자로 그린다(종류별 색·아이콘, 제목 없으면 종류 이름, `+`/`-` 접기, 중첩, 사용자 정의 종류는 노트 색으로 이름 유지, 별칭 summary→abstract 등).
- **HTML**: 글자 그대로 보이던 것을 `rehype-raw`로 그리고 `rehype-sanitize`로 거른다(GitHub 규칙 + `mark`·`u` 등; `script`·`style`·`iframe`·이벤트 속성·`javascript:` 링크·`style` 속성은 지움).
- **그 밖의 Obsidian 문법**: `==강조==`, 본문 `#태그`(Notebook Navigator 색), 줄 끝 `^블록id` 숨김, `![[그림|300]]`·`![설명|300](url)` 크기, `<img src="상대 경로">`, `![[노트]]`·`![[노트#제목]]`·`![[노트#^id]]`는 그 노트(또는 그 부분)를 제자리에 보여 주고 이름을 누르면 연다(두 단계까지, `.md`가 아니면 Obsidian으로).
- 같은 렌더러(`apps/web/src/markdown/obsidian.tsx`)를 볼트 노트, 작업 문서의 미리보기·나란히, 읽기 모드가 함께 쓴다. 대화(답)는 그대로 둔다.
