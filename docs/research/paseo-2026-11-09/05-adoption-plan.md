# Paseo 참고 기능을 사용 가능한 단위로 도입한다

이 문서는 pstack Investigation의 도입 권고다. 자동 실행·예약 루프·PR·merge를 시작하는 실행 프로그램이 아니다. 구현을 시작할 때 각 변경의 실제 범위를 확정하고, 한 목적당 하나의 검증 가능한 변경으로 나눈다.

## 첫 사용 결과를 먼저 정한다

첫 중간 설치본의 목표는 **같은 대화에서 답변·이미지·문서 결과를 읽고 열며, 다른 AI 작업을 확인하는 경험**이다. 모바일 연결이 전부 끝날 때까지 채팅 개선을 미루지 않는다.

기존 HIG W2의 메인 대화·탐색과 이 계획의 P01~P03은 하나의 화면 작업으로 조정한다. 동일한 Transcript나 작업 현황 컴포넌트를 두 번 개편하지 않는다. Aside의 페이지 작업은 P03의 작업 ID·부모 보고 계약을 공유한다.

P01과 P03의 서버 모델 조사는 독립적으로 가능하다. P02는 P01의 렌더 계약을 사용한다. P04는 창의 수명에서 작업 수명을 떼는 변경이므로 P03의 상태 계약과 함께 맞춘다. P05~P07은 그 위에 실제 의존성이 있다. 원격 PR은 요청된 실행 단계에서만 준비하고, 단지 위 표가 있다는 이유로 생성하지 않는다.

P04에서는 일반 채팅의 독립 실행을 먼저 실증하고 문서 AI를 이어 검증한다. 문서는 UI·iframe 의존 실행기, 미저장 입력, writer 인계를 먼저 확인하고 작업 권한을 분리한다. 일반 채팅만 성공한 상태를 “모든 작업이 백그라운드에서 지속됨”으로 표시하지 않는다. P05는 한 호스트에 여러 클라이언트를 연결한 뒤 두 호스트로 확장하며, 같은 네트워크 연결 성공과 외부망에서의 완제품 연결을 따로 기록한다.

## 모바일 구현 경로를 작은 실험으로 고른다

1. 기존 웹 UI의 최소 모바일 화면으로 한 호스트를 데스크톱과 함께 읽고, 승인 하나를 처리하고, 이미지 하나를 보내는 흐름을 검증한다. 통과하면 두 호스트를 구분하는 흐름을 추가한다.
2. 같은 흐름을 Paseo 공식 SDK 또는 프로토콜 호환 어댑터로 구현할 수 있는지 비교한다. 공식 모바일 클라이언트 재사용은 RPC·schema·history·권한·파일·버전 계약을 포함한 이 비교가 통과해야 채택한다.
3. 둘 중 제품의 문서·권한·기록 계약을 더 적게 손상시키는 경로로 좁힌다. 별도 세션 DB를 영구 병행하는 경로는 비용을 명시한다.
4. 웹/PWA에서 가능한 범위와 native push·파일 선택·공유·백그라운드 복귀가 필요한 범위를 구분한다. iOS·Android에서 확인하기 전 완전한 네이티브 사용성이라고 발표하지 않는다.

실험 산출물은 짧은 화면 녹화, 명령·응답 ID, 두 호스트의 결과, 연결 끊김 후 복구 기록이다. 이 실험은 이번 조사에서 수행하지 않았다.

## 기존 검증을 적절한 범위로 사용한다

루트 `npm run typecheck`와 `npm test`가 있다. 먼저 변경 소유 영역의 테스트를 돌리고 필요한 통합 검증을 이어간다. `office-sessions.test.ts`, `attachments.test.ts`와 `scripts/urgent-parallel-check.ts`, `scripts/urgent-usability-check.ts`, `scripts/app-e2e/document-agents-real-run.ts`, `scripts/ieum-roundtrip-check.ts`, `scripts/app-e2e/fast-find-run.ts`는 현재 저장소의 관련 진입점이다. 실행 전에 각 스크립트의 현재 인자·환경·검증 범위를 읽는다.

새 기능은 실제 데스크톱 설치본과 실제 모바일에서 증명한다. provider 시험 서버의 성공과 실제 Codex·Claude 로그인 세션의 성공을 구분한다. 필요한 무거운 빌드·기기 실행은 Achmage 자원 예약 절차를 적용한다. 이번 조사에서는 이 검증을 실행하지 않았다.

## 세 계획을 함께 마무리한다

브라우저는 기존 C 기준, HIG는 H 기준, 이번 기능은 PA 기준을 각각 유지한다. 공통 작업·파일·알림 계약과 화면 구현은 공유한다. 중복 항목은 한 번 구현하고 각 요구 시나리오에서 확인한다.

현재 조사·계획의 완료는 출처가 있는 기능 목록, 현행 차이, 통합 대안, 우선순위와 검증 조건이 문서로 존재하는 것이다. 제품 완료는 P01~P07의 해당 PA 조건이 실제로 충족된 때다. 이후의 새 비교 앱이나 선택 기능은 별도 목록에 둔다.
