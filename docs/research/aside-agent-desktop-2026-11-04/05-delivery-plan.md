# 구현 순서와 완료 기준

이 계획은 [도입 설계](04-workbench-design.md)를 구현할 때 적용한다. **현재는 조사·설계까지 완료했으며 제품 기능 구현이나 신규 릴리즈를 시작한 상태는 아니다.** 버전 번호를 완료 조건으로 삼지 않는다.

계획의 연구 근거: [정확한 완료 결과 revision 2807fc5a0c54…](07-provenance.md#이번-연구).

## 단계별 작업

| 단계 | 작업과 주요 변경점 | 단계의 산출물·종료 조건 | 의존 |
|---|---|---|---|
| P0. 렌더러 실증 | 별도 실증 경로에서 OS WebView 생성, 프로필, DOM 제어, 팝업·파일, hide/show, 분할·IME 확인 | OS별 실행 증거와 capability 표; 채택할 렌더러 결정 | 없음 |
| P1. 일반 웹 탭 | Browser View, pageId, 주소창·이동, 새 탭 메뉴, 탭/분할/복원, 프로필·다운로드 | AI 없이도 수작업 가능한 웹 탭 | P0 |
| P2. 탭 AI와 작업 수명 | 독립 자식 세션, host 소유 작업, 페이지 제어, 사용자 인계, 부모 이벤트 | 두 탭에 작업을 맡기면서 메인 대화 사용 가능 | P1 |
| P3. 기존 기능 연결 | LP/공유 웹 실행기 선택, 결과물 등록, Ctrl+K, 완료 알림, 이음오피스 연계 | 핵심 사용성 C01~C18 통과 및 해당 OS 설치본 검증 | P2 |
| P4. 외부 앱 조작 | agent-desktop 버전 고정·capability·JSON 어댑터, 대상 앱 조정·결과 확인 | 지원한다고 표시한 OS/앱에서 X01~X03 통과 | P0 이후 별도 진행 가능 |

P0에서 **URL 표시 → 같은 페이지를 AI가 읽고 조작 → 사용자가 개입 → 탭을 숨겼다가 다시 열기**를 한 번에 실증한다. 단순 빌드 성공만 확인한 뒤 P1~P3을 크게 구현하지 않는다.

P0의 첫 후보는 Windows WebView2다. macOS/Linux는 자체 드라이버의 기능을 따로 검증한다. 검증 실패 시 동일한 구현을 추측으로 반복하지 않고, 실패 원인·새 가설·대체 렌더러의 비용을 기록한 뒤 비교한다. 플랫폼 차이를 숨긴 “전 OS 완료” 표시는 하지 않는다.

## 구현 단위 제안

실제 파일 이름은 기존 코드 구조에 맞춰 정한다. 아래는 작업 경계이며, 이 이름의 파일을 이번 조사에서 만들지는 않았다.

| 단위 | 책임 | 재사용 지점 |
|---|---|---|
| `BrowserPageRegistry` | pageId·profileId·navigationRevision·대상 WebView 매핑 | 기존 registry/scope 검사 패턴 |
| `BrowserTab` / `BrowserToolbar` | 주소, 이동, 상태, 오른쪽 AI, 분할 크기 | tabs/panes, 기존 생성 메뉴 |
| `BrowserTaskCoordinator` | task 수명·제어 소유권·인계·중지 | office-sessions의 실행/부모 보고 패턴 |
| `BrowserExecutor` | LP와 공유 페이지에 공통 관찰/행동/결과 계약 | browse-lightpanda, 기존 호환 브라우저 |
| `BrowserProfileStore` | 로그인 상태·사용자 선택 프로필·삭제 범위 | 기존 브라우저 설정과 로컬 저장 정책 |
| `TaskResultBridge` | 출처·다운로드·artifact·검색·알림·부모 카드 | 기존 transcript/artifact/검색/알림 |
| `DesktopExecutor` | agent-desktop 호출·버전·capability·결과 해석 | 공통 도구 이벤트와 작업 보고 |

P2를 위해 기존 문서·브라우저 도구 전체를 먼저 새 추상화로 옮기는 대규모 개편은 전제하지 않는다. 필요한 공통 계약만 추출하고 기존 API를 유지하는 작은 연결부터 만든다.

## 핵심 사용성 완료 기준

각 항목의 `미실행`은 **설계된 검증을 아직 실행하지 않았다는 뜻**이다. 기존 0.3.3 기능이 모두 결함이라는 뜻은 아니다.

| ID | 시나리오 | 통과 조건 | 현재 |
|---|---|---|---|
| C01 | 프로젝트에서 `+`와 우클릭 사용 | 새 세션·지원 문서·폴더·웹 탭이 보이고 AI 없이 생성 가능 | 미실행 |
| C02 | 웹을 일반 브라우저처럼 사용 | 주소 입력, 뒤로/앞으로, 새로고침·중지, 링크·새 탭이 올바른 페이지에 적용 | 미실행 |
| C03 | 분할·탭 이동·동일 URL 두 개 | pageId를 혼동하지 않고 한글 입력·크기·포커스가 유지 | 미실행 |
| C04 | 로그인 후 이 페이지의 AI 요청 | 사람과 AI가 동일 프로필의 **같은 살아 있는 페이지**에서 작업 | 미실행 |
| C05 | 사이드 AI 실행 후 다른 탭 이동 | 작업이 계속되고, 돌아오면 같은 대화·진행·결과가 보임 | 미실행 |
| C06 | 웹 2개와 문서 1개에 작업, 메인에도 요청 | 독립 세션으로 실행; 탭 전환으로 쓰기 권한 오류/취소가 발생하지 않음 | 미실행 |
| C07 | 부모 세션에서 자식 진행 확인 | 부모 입력을 막지 않고 진행 카드와 완료 맥락이 전달; 중복 실행 없음 | 미실행 |
| C08 | AI 작업 중 사람이 개입하고 재개 | 진행 중 행동 경계에서 인계, 사람 입력을 덮지 않음; 재관찰 후 계속 | 미실행 |
| C09 | 같은 페이지에 두 작업의 변경 요청 | 변경 작업을 조정하고 다른 페이지의 작업은 진행 가능 | 미실행 |
| C10 | 팝업·다운로드·사이트 권한 발생 | 대상 탭/프로필을 보존하고 다운로드가 올바른 프로젝트에 등록 | 미실행 |
| C11 | 실행 중 탭 닫기·명시적 중지 | 숨김과 중지를 구별; 중지는 자식 실행까지 끝내며 종료 이벤트 중복 없음 | 미실행 |
| C12 | 앱 종료·재시작 | 대화·탭 기록 복원; 살아 있지 않은 DOM 작업은 중단 상태로 정확히 표시 | 미실행 |
| C13 | 공개 자료 조사를 메인에서 요청 | LP 경로로 수집하고 출처·결과를 반환; 불필요하게 화면을 열지 않음 | 미실행 |
| C14 | LP 결과를 사람이 웹 탭에서 확인 | 새 렌더링 페이지임을 구별; 기존 로그인·폼이 자동 복제됐다고 표시하지 않음 | 미실행 |
| C15 | Ctrl+K에 원문 프롬프트 일부 입력 | 사이드/메인 요청 원문 모두 검색되고 해당 대화로 이동 | 미실행 |
| C16 | 다른 탭에서 작업 완료·입력 필요 | 정책에 따른 알림 1회, 클릭 시 해당 작업/탭으로 이동 | 미실행 |
| C17 | 결과 파일을 편집기→이음오피스에서 저장 | 돌아와 최신 내용을 읽고 같은 프로젝트의 다른 세션도 결과를 찾음 | 미실행 |
| C18 | 기존 프로젝트·문서·볼트·worktree 흐름 | 개요 진입·문서 집중 모드·볼트 이동 유지; 다른 worktree 결과를 동일 파일로 혼동하지 않음 | 미실행 |

검증은 로컬 재현 사이트로 페이지 식별·로그인 상태·폼·지연 작업을 반복 가능하게 확인하고, 대표 실제 사이트와 실제 설치본에서 수동 흐름을 확인하는 조합으로 한다. 계정 로그인을 자동으로 만들어 검증했다고 대체하지 않는다. 실제 AI를 쓰기 전 mock 실행으로 탭 수명·중복·취소를 확인하고, 마지막에 실제 두 독립 세션의 병행 흐름을 확인한다.

## 외부 앱 확장 기준

| ID | 시나리오 | 통과 조건 | 현재 |
|---|---|---|---|
| X01 | 지원 OS에서 지정 앱 관찰·한 가지 수정·저장 | 정확한 앱/창을 선택하고 저장 결과를 별도로 확인 | 미실행 |
| X02 | stale ref·부분 snapshot·불확실한 입력 결과 | fresh observation과 안전한 재시도로 처리; 중복 저장/전송 없음 | 미실행 |
| X03 | 사용자 조작·다른 작업과 경합 | 포커스·포인터 정책과 대상 앱 소유권을 지키고 미지원 기능을 정확히 표시 | 미실행 |

현재 niri Linux는 X01~X03의 별도 검증 대상이다. GNOME용 키 입력 경로가 있다는 이유로 통과 처리하지 않는다. 외부 앱 조작까지 제공할 때는 P4를 별도의 완료 항목으로 표시한다.

## 릴리즈 판단과 범위 고정

- **핵심 웹 사용성 완료:** P0에서 명시한 지원 플랫폼에서 C01~C18을 통과하고, 그 플랫폼의 실제 설치본으로 같은 흐름을 확인했을 때다.
- **외부 앱 자동화 완료:** 지원한다고 명시한 OS/앱에서 X01~X03까지 통과했을 때다.
- **이번 조사 완료:** Orca Lightpanda 실행 증거, Aside 메뉴/흐름 조사, agent-desktop 코드 분석, 기존 코드 대응표, 위 완료 기준을 문서로 갖춘 상태다.
- 테스트 중 발견한 결함은 이 기준을 깨뜨리는지 먼저 분류한다. 기준에 직접 해당하는 결함은 고치고, 새 기능 제안은 별도 목록으로 남긴다.
- 암호 관리자 전체·확장 스토어·브라우저 동기화·클라우드 실행을 나중에 발견했다는 이유로 핵심 완료 조건에 계속 추가하지 않는다. 전체 기능 동등성이 필요하면 별도 목표로 확장한다.

새 구현의 일정과 설치 크기는 P0에서 렌더러와 지원 범위가 결정된 뒤 산정한다. 그 전의 연구 결과를 “곧 릴리즈 가능”이나 “이미 모두 동작함”으로 표현하지 않는다.
