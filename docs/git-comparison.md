# 기준·커밋 비교

작업공간 메뉴의 **Git 변경 검토 → 기준·커밋 비교**에서 다음 세 가지를 선택한다.

- **작업 변경 전체**: 기준 커밋부터 현재 디스크 파일까지 비교한다. 워크트리는 기록된 시작 커밋, 일반 폴더는 HEAD가 기본이다. 기준 이후 커밋한 변경, 현재 스테이징·작업 변경과 미추적 파일을 함께 검토한다. 첫 커밋 전에도 사용할 수 있다.
- **브랜치·기준 비교**: 브랜치·태그·커밋을 입력한다. **공통 조상**은 대상 브랜치에서 만든 변경, **두 끝점**은 입력한 두 커밋의 차이다. 공통 조상이 없거나 여러 개면 임의 선택하지 않고 두 끝점 비교를 안내한다.
- **한 커밋의 변경**: 선택한 커밋과 부모를 비교한다. 첫 커밋은 빈 기준을 사용한다. 병합 커밋은 부모 번호를 바꿀 수 있다. 얕은 복제에서 부모 객체를 읽을 수 없으면 오류를 표시하며 첫 커밋으로 취급하지 않는다.

입력 후 **비교 불러오기**를 누르면 실제 기준·대상 커밋을 고정한다. 이름이 같은 브랜치가 이동해도 열어 둔 과거 비교는 유지한다. **비교 새로고침** 때 다시 이름을 확인한다. 화면 위 요약은 현재 입력 중인 폼과 별도로 실제 채택한 기준을 표시한다. 줄 번호, 줄바꿈, F7/Shift+F7 이동, 이름 변경과 이미지의 이전·이후/겹쳐 보기를 제공한다. 폼과 줄바꿈 설정은 작업공간별 앱 데이터에 저장하며 포트가 바뀌어도 복원한다. 저장 완료 표시를 제공하고, 느린 저장 응답이 최신 설정을 덮지 않게 요청 순서를 유지한다. 여러 창의 표시 설정은 마지막으로 저장한 값을 쓴다.

이 탭은 읽기 전용이다. 현재 인덱스 변경은 **스테이징·커밋** 탭에서 처리한다. 디스크의 최종 결과가 기준과 같아도 중간 스테이징 변경이 있는 파일은 목록에 남겨 둔다. 충돌 파일은 기존 3방향 검토로 안내한다.

## 정확성과 제한

- 호스트는 검증한 실제 OID와 파일 목록을 제한된 비교 세션에 보관한다. 파일 요청에는 세션 ID·판·목록의 경로만 받으며 호출자가 보내는 임의 OID나 patch를 사용하지 않는다. 다른 작업공간의 세션과 바뀐 저장소 정체성을 거절한다.
- 작업 파일 비교는 상태 판과 파일 지문을 다시 검사한다. 과거 커밋 비교는 현재 HEAD 이동과 독립적이다. 세션은 30분, 최대 32개/총 50,000개 파일이며 만료·재시작 후에는 다시 불러온다. 한 비교의 파일 한도는 20,000개다.
- Git 명령은 저장소 객체·인덱스·작업 파일을 쓰지 않는다. 대체 객체, 외부 diff/textconv와 자동 객체 fetch를 사용하지 않는다. 조회 중 네트워크 프로토콜도 허용하지 않는다. 실제 저장소의 검사 훅·서명·원격 쓰기 정책에는 영향을 주지 않는다.
- Git 경로는 NUL 구분을 보존한다. UTF-8로 정확히 표현할 수 없는 경로는 대체 문자로 다른 파일을 선택하지 않고 거절한다. 링크는 링크의 내용만 읽으며 상위 폴더가 링크로 바뀐 경로를 통해 읽지 않는다.
- 미추적 파일과 첫 커밋 전의 파일은 기준 blob과 실제 작업 바이트를 제한된 텍스트 계산으로 비교한다. 인덱스에서 삭제하고 같은 경로를 다시 만든 파일도 실제 양쪽 내용을 표시한다. 이 경로는 Git clean 필터를 실행하지 않는다.
- patch는 512 KiB/6,000행까지만 표시한다. 이미지·미추적 원문은 8 MiB까지 읽는다. 비 UTF-8 내용, 큰 파일, 링크·서브모듈·중첩 저장소를 일반 편집 가능한 텍스트로 가장하지 않는다. 이 단계에는 행 주석의 영속 저장·에이전트 전송이나 개별 행 스테이징이 포함되지 않는다.

API: 메인 gateway 인증으로 `POST /api/workspaces/:id/scm/compare`에 `{mode, baseRef?, headRef?, mergeBase?, parent?}`, `POST /api/workspaces/:id/scm/compare-diff`에 `{id, revision, path}`를 보낸다. Office 문서용 제한 권한에는 이 API가 없다.
