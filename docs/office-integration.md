## PDF 사본·주석 처리·영구 가림

원본 PDF의 주석 유지·평탄화·제거 선택창을 리본의 ‘다른 이름으로 저장’과 Ctrl/⌘⇧S에 연결했다. 현재 미저장 편집을 복사하며, 편집 없는 유지 사본은 원본과 바이트 단위로 같다. 일반 사본은 원본 탭에 미저장 편집과 보류한 가림 표시를 유지하고, 새 사본을 같은 대화·작업공간의 문서 목록에 등록한다. 주석 제거 사본은 링크와 입력 폼을 남긴다. 원본 복구본에는 제거·평탄화 전 내용이 남으므로 사본과 원본 초안이 섞이지 않는다.

호스트의 `copy`/`redact-copy`는 원본 엔진으로 바이트만 만든다. 최종 파일 쓰기는 기존 준비된 출력 요청·대상 변경 확인·백업·출처 계약을 사용한다. 일반 저장과 복구는 계속 주석 제거·가림·임의 출력 경로를 거절하며, 사본에 담지 못한 편집이 있으면 성공으로 등록하지 않는다. 선택·처리 중에는 자동 저장과 원본 변경을 막고, 취소·오류 뒤 원래 편집으로 돌아간다.

영구 가림은 원본의 별도 확인과 다른 편집 먼저 저장 조건을 거친다. 실제 PDFium 제거를 적용한 **새 artifact**에서 열어 이전 원본의 실행 취소·복구 데이터를 전달하지 않는다. Workbench는 이전 판을 보관하므로 반복 가림도 새 사본으로 만든다. 첫 가림 이후 같은 파일을 덮어쓰는 Electron 원본과의 차이를 확인 문구에 반영했다. 원본 파일 자체는 보존한다.

### 저장 뒤 되돌림과 응답 스트림

Sheets에서 원본 도구의 변경 저널은 갱신됐지만 React의 변경 개수 알림이 아직 오지 않은 사이, 저장 확인이 기존 판을 반환하는 경쟁 상태를 실제 앱에서 발견했다. 저장 요청은 이제 원본 close-save 처리기가 현재 저널과 입력 중인 셀을 직접 확인한다. 복사한 변경 개수가 0이라는 이유로 저장을 생략하지 않는다.

Markdown·HTML·XMind·EPUB·HWPX·PPTX·XLSX의 대표 수정은 원본 Undo → 저장(r3) → Redo → 저장(r4)을 확인했다. Word는 원본 AI 패널의 ‘이전 상태로’ → 저장, 그 복원을 원본 Undo로 취소 → 재저장을 검사했다. 일반 Undo 버튼과 AI 전체 차례 복원은 같은 기능으로 취급하지 않는다. 이 8종의 16개 검사는 실제 파일 내용을 읽어 판정한다.

PDF의 저장 후 이력 소실도 수정했다. 원본 편집 스냅샷에 바탕 PDF의 판 참조를 붙여, 다른 판으로 되돌릴 때 PDF와 미저장 편집을 함께 복원한다. 저장은 현재 Workbench 판을 기준으로 새 판을 쓰므로 과거 상태가 현재 판 번호를 되돌리거나 외부 변경을 우회하지 않는다. 저장된 PDF 바이트를 이력마다 복사하지 않는다. PDF.js 검증이 끝난 뒤 화면을 바꾸고, 불러오기 실패는 현재 파일·화면·이력 위치를 유지한다. 복원 중에는 상위 문서에도 미저장 상태를 알리고 저장/닫기는 복원 완료를 기다린다.

XMind의 내보내기·출력·링크 열기·문서 만들기, EPUB의 책 전체 번역/결과 보관·외부 링크·이름 변경 동기화와 기존 설정 이행도 남았다. 공통 Drive·검색·출력과 doory 전체 메뉴의 동등성을 계속 확인한다.
