# Git 검토 의견과 대화 전달

Git 변경 검토의 행 번호에서 `+`를 누르거나 행에 초점을 두고 `C`를 누른다. 이전·이후 원문에 의견을 남기고, 표시된 연속 범위를 최대 100행까지 지정할 수 있다. `Ctrl/Cmd+Enter`로 저장하고 `Esc`로 편집을 취소한다. 바이너리 등 행 지정이 불가능한 비교에는 파일 의견을 남긴다.

하단 검토 의견에서 수정·해결·다시 검토·삭제와 원문 확인을 제공한다. 미해결 의견을 선택하고 **같은 작업공간의 활성 대화**에 한 묶음으로 보낸다. 새 Codex/Claude 대화를 만든 뒤 대상으로 선택할 수도 있다. 실행 중인 대화에는 기존 대기 목록으로 전달한다. 모델 응답은 의견을 자동으로 해결 처리하지 않는다.

## 보존과 위치 확인

- 서버가 diff를 읽을 때 비교 기준·경로·원문을 스냅샷으로 보관한다. 저장 요청은 스냅샷 ID와 범위만 지정하며, 호출자가 보낸 코드 발췌를 신뢰하지 않는다. 저장 전 외부 파일이 바뀌어도 실제로 검토한 원문이 기록된다.
- 저장한 의견에는 저장소 식별값·최초 경로·이름 변경 이전 경로, local/combined/branch/commit 기준, OID·diff 판, 원래 행·발췌·앞뒤 문맥·원문 바이트 해시가 남는다. 텍스트 발췌는 화면과 같은 줄바꿈 정규화를 사용하며 BOM을 보존한다. 원본 파일을 수정하지 않는다.
- 비교를 다시 불러오면 현재 **열어 둔 파일**의 전체 제한 내 원문에서 발췌와 문맥을 찾는다. 파일 해시가 같으면 원래 위치를 유지한다. 고유한 위치는 이동 표시하고, 반복·변경·사라짐·다른 비교 기준은 확인이 필요한 상태로 남긴다. 같은 경로에 새 저장소를 만들어도 과거 의견을 새 코드에 붙이지 않는다. 저장한 최초 앵커는 바꾸지 않는다. Git이 확인한 이름 변경을 한 단계 연결하며 모든 과거 rename을 추정하지 않는다.
- 읽기 캐시는 30분·32개·추정 32 MiB 이내로 제한한다. 일반 UTF-8 파일은 각 2 MiB·5만 행 이내, 완전한 단일 파일 patch일 때 행을 지정한다. 바이너리·잘린 patch·링크·서브모듈·필터로 원문과 달라진 행은 파일 의견으로 안내한다. 발췌와 문맥은 64 KiB 이내다.
- 저장한 의견은 캐시와 독립적인 앱 SQLite 메타데이터에 있으며 새 포트·재시작·보관 후에도 읽을 수 있다. 생성 요청 중복을 제거하고, 수정·해결·삭제는 의견 버전별 CAS를 사용한다. 다른 창의 변경을 발견하면 입력을 보존하고 최신 의견을 확인한 뒤 명시적으로 채택한다.
- 의견 본문은 16 KiB, 작업공간 보관 기록은 1만 개다. 삭제는 목록에서 숨기는 기록으로 보존하며 이전 전달 묶음을 고치지 않는다. 저장하지 않은 편집 입력은 현재 창의 초안이며 앱 종료까지 보존되는 기록으로 간주하지 않는다.

## 전달 상태

전달 전에 대상 대화·의견 ID/버전·본문/원문을 담은 불변 묶음을 저장한다. 한 묶음은 최대 50개·256 KiB다. 같은 요청 ID의 재전송은 해당 기록만 반환한다. 전송 도중 앱을 닫으면 결과 확인 필요로 보존하고, 뒤늦게 돌아온 엔진 응답이 닫힌 저장소를 쓰지 않게 한다. 저장/전달의 응답을 잃은 UI도 같은 요청을 확인하며 임의의 새 요청으로 바꾸지 않는다.

| 표시 | 의미 |
|---|---|
| 전달 중 | 현재 호스트 실행에서 전송을 진행 중 |
| 대기 목록에 등록 | 선택한 대화의 대기 목록에 같은 본문이 있음 |
| 대화에 접수 | 선택한 대화에서 요청 접수를 확인함. 실제 수정·완료의 증거는 아님 |
| 전달 실패 | 요청별 엔진 시작/대기 전달 오류, 또는 접수 전 거절 |
| 전달 확인 필요 | 재시작 중 전송 결과가 불명확하거나 대기 요청이 사라짐. 자동 재전송 없음 |
| 대기 요청 변경됨 | 대기 목록에서 본문이 달라져 원래 묶음과 같다고 표시할 수 없음 |

전달 중 의견을 수정해도 이전 묶음에는 당시 버전만 남는다. 최신 버전이 전송됐다고 표시하지 않는다. 미해결 의견은 새 묶음으로 다시 선택할 수 있다. 대기 목록에서 변경하거나 취소한 요청은 기존 대화 UI로 확인한다. 전달 기록은 최근 20개를 표시하며 저장된 이전 기록은 제거하지 않는다.

## 검증과 남은 범위

실제 Git 파일·인덱스를 사용하는 호스트 검사, 응답 유실·다른 창 수정의 UI 검사와 Linux 실제 앱 검사를 수행한다. 회귀 79/79, 종료/세션 관련 27/27, 실제 Linux 구간/의견/비교 연속 42/42와 화면 확인을 통과했다. 정확한 연구 판: `research:rr-52b02575f1eebe2c61a3e4e43a6ca74f:fe0104ec6b7112c8ceb37c7189edae80bae767be85304d46f259e4c668a321f5`. 실제 모델이 수정을 정확히 수행한다는 보장은 별개이며, native 검사는 격리된 대체 엔진으로 전달 흐름을 확인한다.

PR/CI, 한 구간 내 개별 행 staging, 임의 원문 재앵커, 장기 rename 체인, Windows/macOS 설치본과 전체 릴리스는 후속이다. 원본 Orca의 모든 기능을 완료했다는 의미가 아니다.
