# Git 워크트리 작업공간

작업공간 선택기의 **Git 워크트리 관리**에서 같은 저장소의 기존 체크아웃을 연결하거나 기준 ref·새 브랜치·이름을 지정해 만든다. 원래 프로젝트의 cwd, 기존 파일, 세션 ID와 배치는 유지한다.

## 연결과 생성

- Git의 실제 목록과 common directory를 확인한다. 사라진 경로, 잠긴 항목, detached HEAD와 이미 연결한 공간을 구분한다. 조회는 Git index를 변경하지 않으며 줄바꿈·탭이 포함된 경로도 그대로 처리한다.
- 외부 체크아웃의 연결은 소유권을 부여하지 않는다. 연결된 폴더를 이 앱의 삭제 버튼으로 제거할 수 없다.
- 로컬/remote-tracking 브랜치, 태그 또는 commit ref에서 만든다. 선택 당시 확인한 SHA가 바뀌거나 브랜치 이름이 충돌하면 실패 기록을 남긴다. 이 단계는 원격 fetch를 수행하지 않는다.
- 생성 요청 ID와 단계를 DB에 기록한다. 같은 요청은 재사용하고 다른 내용의 ID 재사용은 거절한다. 창을 닫아도 진행하며 취소는 이 작업이 소유한 Git 실행에만 전달한다.
- 취소/실패 시 이미 생긴 checkout과 브랜치를 자동 삭제하지 않는다. 확인 가능한 결과는 작업공간에 연결한다. 앱 재시작 때 미완료 작업은 중단됨으로 표시하고 자동 재실행하지 않는다.
- 부모 작업공간은 표시용 계층이다. 같은 저장소에 속하는지 확인하며 실행 cwd나 파일 소유권을 바꾸지 않는다.

## 제거와 기록 보존

실제 경로를 보여 주고 확인한 뒤 제거한다. 실행 중인 세션·생성 작업, 편집 권한/미저장 문서가 있으면 거절한다. 같은 물리 폴더를 다른 프로젝트가 연결한 경우도 확인하며, 제거 중에는 새 세션·문서 편집·중복 제거의 진입을 막는다.

Git이 실제 폴더를 제거한 뒤 연결된 로컬 작업공간과 세션을 보관한다. 원래 프로젝트 cwd와 세션 기록은 보존한다. 미병합 커밋이 있는 브랜치는 유지한다. 폴더 제거 실패를 성공으로 처리하지 않으며, 폴더 제거 뒤 브랜치 정리만 실패한 경우에는 제거 사실을 기록하고 오류를 전달한다.

## 검증과 다음 범위

실제 임시 Git 저장소의 수명주기·문서 권한·작업공간 회귀 27/27, 전체 타입 검사와 host/Tauri 빌드가 통과했다. 실제 Linux Tauri 14/14는 발견/연결, 외부 삭제 금지, 브랜치 충돌, 선택한 태그에서 생성, 두 엔진 세션, 새 포트 재시작, 실제 삭제와 다른 프로젝트 연결 보관, 원본 파일 보존을 포함한다.

실제 [터미널](terminals.md)과 [환경 준비](workspace-preparation.md)를 연결했으며 같은 물리 폴더의 실행·준비 작업도 제거 검사에 포함한다. 보관 명령이 있으면 성공 또는 명시적 건너뛰기를 확인한다. SCM/PR/CI, 남은 환경 준비 동등성, Windows/macOS와 전체 릴리스 검증은 후속 범위다.
