# 원격 Git 동기화

**Git 변경 검토 → 원격 동기화**에서 실제 원격 주소와 대상 브랜치를 확인한다. 이 화면을 여는 것만으로 네트워크 전송하지 않는다. 받기 기본값은 현재 브랜치의 upstream이며, 보내기는 `branch.<name>.pushRemote`, `remote.pushDefault`, upstream 순서로 선택한다. 별도 보내기 원격에는 현재 로컬 브랜치 이름을 사용한다. 대상은 사용자가 바꿀 수 있다.

**브랜치 가져오기**는 선택한 원격의 첫 fetch URL에서 branch ref를 `refs/remotes/<remote>/`로 가져온다. 태그·사용자 지정 fetch mapping·prune·재귀 submodule·자동 maintenance·`FETCH_HEAD` 변경은 이 버튼의 범위에 넣지 않는다. 작업 파일과 인덱스는 유지한다.

**받기**는 단순 전진, 병합, 리베이스 중 선택한 방법으로 실행한다. 대상 브랜치를 작업별 임시 ref로 가져오고 정확한 커밋을 고정한다. 전송 후 로컬 파일·HEAD·인덱스를 다시 검사해 바뀌었으면 통합하지 않는다. 추적 파일의 기존 변경이나 열린 문서 편집 권한이 있으면 먼저 정리해야 한다. 자동 stash나 다른 로컬 브랜치의 rebase updateRefs는 사용하지 않는다. 충돌이면 실패 출력과 실제 merge/rebase 상태를 남긴다.

**보내기**는 검토 당시 HEAD의 커밋 ID만 선택한 원격 브랜치에 보낸다. 그동안 새 로컬 커밋이 생겨도 섞지 않는다. 여러 push URL이 있으면 모두 화면에 표시하고 순서대로 전송하며, 앞선 전송만 성공했다면 그 결과도 보존한다. 자동 rollback·재시도·force 전환은 없다. 선택적으로 성공 후 upstream을 설정한다. 보내기 URL과 가져오기 URL이 다르면 가져오기 쪽 추적 ref를 임의로 갱신하지 않는다.

기록을 재작성한 경우 **원격 커밋 확인**으로 각 push URL의 실제 HEAD를 읽는다. 사용자가 표시된 대상을 확인하고 선택한 경우에만 `--force-with-lease=refs/heads/<branch>:<확인한 OID>`를 보낸다. 뒤에서 fetch가 실행되어 추적 ref가 바뀌어도 확인한 OID는 바뀌지 않는다. 확인은 10분간 유효하며 재시작하면 사라진다.

## 실행·인증·실패 기록

기존 Git 자격 증명/SSH agent를 사용하며 앱 DB에 비밀번호를 받지 않는다. 대화형 인증이 필요한 경우 **이 작업공간 터미널 열기**에서 기존 Git 인증을 마친 뒤 새 작업으로 진행한다. 실제 hosted provider 및 다른 OS의 인증 UX는 별도 검증 대상이다.

Git URL rewrite를 반영한 주소를 표시하되 URL 사용자 정보·쿼리는 가린다. 원격 설정 판과 로컬 검토 판을 실행 전 재검사한다. 원격별 upload-pack/receive-pack, HTTP proxy/auth-method, server-option을 유지한다. pre-push와 서버 훅은 그대로 실행한다. 각 URL로 명시적으로 보내므로 pre-push의 첫 번째 인자는 그 URL이며, 원격 이름을 고정 가정하는 사용자 훅은 이를 처리해야 한다.

원격 출력은 완성된 행을 모아 URL 자격 증명을 가린 뒤 저장한다. 중단은 현재 전송을 정지하고 이미 완료한 대상의 결과를 남긴다. 원격 확인도 전체 30초 제한과 앱 종료 시 소유한 실행 종료를 적용한다. 기존 프로세스나 저장된 PID를 인수하지 않는다.
