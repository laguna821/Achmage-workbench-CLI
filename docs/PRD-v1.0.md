# Achmage Workbench PRD v1.0
**Claude Code 구현 인계용 · 2026-10-16 · Markdown 초안**

## 1. 제품 목표와 첫 출시 범위

**Achmage Workbench는 Claude Code와 Codex, 문서 편집, 기존 Achmage 지식 체계를 하나의 단순한 작업 화면으로 연결하는 개인용 데스크톱 앱이다.**

사용자는 대화하다가 같은 화면에서 문서를 열고 수정하고, 수정된 판을 AI에 이어주거나 다른 세션에 검토를 요청한다. 프로젝트·세션·파일·기기를 오가면서 맥락을 다시 설명하거나 파일을 옮기는 수작업을 줄이는 것이 목적이다.

핵심 성공 조건은 다음 흐름이 끊기지 않는 것이다.

> 대화 → 결과 열기 → 직접 수정 → 저장된 수정본을 AI가 이어받기 → 다른 세션에 검토 요청 → 같은 작업에서 결과 확인.

**편집기를 채팅 안에 넣는 것만으로는 완료가 아니다. AI가 사용한 문서 버전과 사용자가 보는 문서 버전이 연결되어야 한다.** :codex-annotation{index="1"}

### 확정된 방향

| 항목 | 결정 |
|---|---|
| 첫 출시 | **Windows·Linux PC 작업실부터 완성** |
| 앱 형태 | **처음부터 Tauri 2 설치형** |
| 기본 화면 | Codex처럼 단순한 단일 대화 화면 |
| 화면 전환 | 대화·문서·작업 목록·진행 상세가 같은 중앙 영역을 교체 |
| 기본 AI | Claude Code, Codex의 실제 세션 |
| 코드 기반 | 별도의 얇은 Achmage Workbench. 기존 Achmage·HOP/RHWP·PDFCraft를 재사용 |
| 모바일 | 후속 단계. PC 상태·문서·미리보기 모델을 재사용하도록 설계 |
| 기본 운영 | 개인용·로컬 중심. SaaS 계정 서버나 자체 결제 시스템 없음 |

### v1 필수 범위

- Windows·Linux 설치, 실행, 업데이트 시 설정 보존.
- Claude Code·Codex 로그인, 세션 생성·재개·중단·승인.
- 한 작업 안에서 두 엔진의 세션 탭 전환.
- 프로젝트와 작업, 세션의 중첩 폴더 정리.
- Markdown·HWPX 편집, PDF 열람 및 제한된 편집, HTML 실제 미리보기.
- 직접 수정한 문서를 정확한 버전으로 AI에 전달.
- 다른 세션에 문서와 요청을 보내고 현재 작업에서 답변 확인.
- 기존 Achmage의 작업·지식·근거 참조.
- 연결 중단 및 앱 재시작 후 상태 복구.
- 전체 프로세스를 포함한 메모리·설치 용량 측정.

### 후속 범위

- iPhone 접속·페어링, 자동 문서 미리보기, 위치를 지정한 수정 요청.
- 연구실 PC와 노트북 사이의 실행 호스트 선택과 작업 재개.
- Kanban 개요, Hermes·OpenRig·Herdr 연동.
- 여러 사람이 동시에 편집하는 기능.
- 임의의 공식 앱 세션이나 웹 채팅 전체를 가져오는 기능.

이번 결정은 이전 기술설계의 **“웹 먼저, Tauri 나중” 및 “모바일 검증 우선” 순서를 대체**한다. 브라우저에서 동작하는 것만으로 PC 버전을 완료 처리하지 않는다.

## 2. UX 원칙과 PC 시안

아래 이미지는 기존에 만든 **설계 시안**이다. 실제 구현 화면이나 기능 검증 결과가 아니다. 구현은 이미지의 화면 구성과 아래 명시된 동작을 함께 따른다.

### 2.1 기본 작업 화면

![단일 대화 중심 PC 시안](<../assets/ui/01-focus.png>)

**항상 보이는 요소는 작업 선택, 현재 작업, 짧은 상태, 대화, 입력창으로 제한한다.**

- 왼쪽 사이드바와 분할 화면을 기본으로 열지 않는다.
- 작업 선택기를 열면 폴더·검색·최근 작업을 확인한다.
- 같은 작업에 세션이 둘 이상이면 제목 아래에 작은 세션 탭을 표시한다.
- 탭은 `강의 작성 · Claude`, `인용 검토 · Codex`처럼 목적과 엔진으로 구분한다.
- 현재 단계와 실행 호스트를 한 줄로 표시한다.
- 상세 로그·도구 호출·참조 근거·토큰 정보는 펼쳤을 때 보여준다.
- 엔진 변경은 새 세션 생성 또는 기존 세션 전환이다. 서로 다른 엔진의 기억이 자동으로 같아졌다고 표시하지 않는다.
- 시안의 상태 문구는 실제 실행 단계에 맞춰 갱신한다.

입력창은 하나만 둔다. 일반 메시지 전송과 세션 간 전달이 혼동되지 않도록 시안의 대상 선택 버튼은 **‘다른 세션에’**로 변경한다.

### 2.2 다른 세션에 요청 보내기

![세션 간 요청 전달 시안](<../assets/ui/02-send-to-session.png>)

사용 흐름:

1. 입력창에서 ‘다른 세션에’를 선택한다.
2. 세션 이름·엔진·실행 위치로 대상을 찾는다.
3. 현재 문서 또는 선택한 근거를 첨부한다.
4. 요청을 보내면 현재 대화에 진행 카드가 생긴다.
5. 답변이 도착하면 같은 카드에서 읽거나 해당 세션을 연다.

기본 첨부 범위는 **요청문과 사용자가 선택한 문서의 확정 버전**이다. 전체 대화나 모든 저장소를 자동 첨부하지 않는다.

재연결해도 같은 요청을 중복 실행하지 않는다. 에이전트끼리 계속 재요청하는 순환은 기본 제공하지 않는다. 시안에 등장하는 Hermes는 후속 연동 대상이다.

### 2.3 대화 안에서 문서 열기

![중앙 영역 문서 편집 시안](<../assets/ui/03-document.png>)

파일 카드를 누르면 문서가 중앙 영역을 채운다.

- ‘대화로’ 버튼으로 기존 대화 위치에 돌아간다.
- 저장 상태와 AI가 읽은 버전을 구분한다.
- 문단·텍스트·페이지 영역을 선택하면 입력창이 그 선택 범위를 대상으로 한다.
- AI 제안은 미리보기·적용·취소로 처리한다.
- 편집 도중 다른 세션의 검토가 끝나면 작은 상태 알림으로 표시한다.
- HOP의 별도 AI 패널을 그대로 중복 탑재하지 않고 Workbench의 세션·입력창에 연결한다.
- 전체 리본이나 모든 도구를 상시 노출하지 않는다. 선택 대상에 필요한 도구만 나타낸다.

### 2.4 작업과 세션의 폴더 정리

![중첩 폴더 작업 선택 시안](<../assets/ui/04-work-folder.png>)

폴더 구조는 사용자가 직접 정한다.

```text
강의
  2026-2
    7주차 강의 자료
      강의 작성 · Claude
      인용 검토 · Codex
연구
  프로젝트 A
도구 개발
  Workbench
```

- 폴더 생성·이동·이름 변경·접기·검색을 제공한다.
- 폴더 이동은 기본적으로 앱 안의 분류 변경이다. 실제 파일 경로나 Git 저장소를 자동 이동하지 않는다.
- 기존 Achmage 작업 ID와 실제 파일 위치는 유지한다.
- 최근 작업과 폴더 보기를 v1에 제공한다.
- 보드 보기는 후속 단계이며 v1에서는 미완성 버튼을 노출하지 않는다.

### 2.5 진행 확인과 복구

![작업 단계와 재개 시안](<../assets/ui/05-resume-step.png>)

작업 진행 상세는 필요한 순간에만 중앙 영역에서 연다.

- 완료된 단계, 현재 단계, 대기 이유, 다음 행동을 보여준다.
- 실패한 단계부터 다시 시도하며 완료된 결과는 보존한다.
- v1은 같은 호스트에서의 재연결·재개를 제공한다.
- 이미지의 ‘노트북에서 재개’는 후속 단계다. 다른 컴퓨터에서 기존 프로세스가 그대로 이동하는 것으로 구현하거나 설명하지 않는다.

### Workflow Engineering 적용

| 원칙 | 제품 동작 |
|---|---|
| Step Awareness | 현재 단계·대기 이유·다음 행동을 짧게 표시한다. |
| Change-Aware Design | 문서 수정·엔진 변경·연결 중단 후 완료된 결과를 보존한다. |
| Human-Centered Decomposition | 사용자는 목적과 판단을 맡고, 저장·버전 연결·전달·미리보기 갱신은 앱이 처리한다. |
| Org-Level Diffusion | 반복 작업은 입력·역할·완료 조건·복구 방법을 가진 버전 있는 작업 템플릿으로 확장한다. |

## 3. 기능과 기술 계약

### 3.1 기술 구성

**Orca 전체를 포크하지 않고, 기존 자산을 연결하는 별도 앱을 만든다.** Orca는 구조화된 대화와 세션 처리의 참고 대상으로 사용한다. 코드를 가져올 때는 의존성과 라이선스를 확인하고 출처를 남긴다.

| 계층 | 선택 | 역할 |
|---|---|---|
| 데스크톱 셸 | Tauri 2 / Rust | 창·트레이·파일 열기·설치 패키지 |
| UI | React / TypeScript / Vite | 단일 작업 화면, 세션·문서 전환 |
| 로컬 게이트웨이 | Node.js 24 / TypeScript | 엔진 어댑터, 실행 상태, 이벤트, 문서 작업 조정 |
| Codex 연결 | 공식 app-server | 인증, 스레드·턴, 승인, 스트리밍 |
| Claude 연결 | 공식 Agent SDK 및 CLI | 공식 로그인, 세션 실행·재개 |
| Achmage 연결 | 기존 Python 런타임의 지원 인터페이스 | 작업·지식·연구 근거 참조 |
| 한글 편집 | 사용자 HOP/RHWP 포크 | 기존 Rust/WASM·편집 기능 재사용 |
| Markdown | CodeMirror 6 | 원문을 보존하는 편집 |
| PDF | PDF.js + 사용자 PDFCraft 포크 | 열람·선택, 검증된 편집 명령 |
| HTML | 격리된 미리보기 | 실제 HTML 렌더링 |
| 로컬 상태 | SQLite | UI 메타데이터·이벤트·요청 중복 방지·캐시 |

UI와 게이트웨이 사이는 HTTP 명령과 재연결 가능한 SSE 이벤트를 사용한다. 각 AI 엔진의 내부 전송 방식은 어댑터가 감춘다.

Windows는 **NSIS 설치 프로그램**, Linux는 **AppImage**를 첫 배포 형식으로 한다. Linux WebKitGTK 및 문서 엔진 의존성을 실제 대상 환경에서 확인한다.

### 3.2 로그인과 세션

별도의 Workbench 온라인 계정을 만들지 않는다.

- Codex는 공식 app-server가 지원하는 ChatGPT 로그인 흐름을 사용한다.
- Claude는 공식 CLI·SDK의 지원 로그인 흐름을 사용한다.
- 공식 앱의 비공개 인증 파일을 복사하거나 자체적으로 OAuth 토큰을 추출하지 않는다.
- 비밀정보는 각 호스트의 공식 인증 저장소 또는 OS 보안 저장소에 둔다.
- 구독 사용과 API 사용을 명확히 구분한다. API 과금 방식으로 조용히 전환하지 않는다.
- 잔여량은 공식 인터페이스가 제공하는 값만 표시한다. 확인 불가능하면 ‘확인 불가’로 표시한다.
- 사용량 때문에 엔진을 바꾸는 결정은 사용자가 한다. 자동 전환은 v1에 넣지 않는다.

최소 세션 인터페이스는 생성·재개·전송·중단·승인 응답·기능 조회다. 엔진마다 다른 승인·재개 기능을 억지로 같은 기능인 것처럼 표현하지 않는다.

세션 식별에는 `workId`, `provider`, `hostId`, `nativeSessionId`를 함께 사용한다.

### 3.3 문서와 AI가 같은 판을 보는 규칙

모든 편집 가능한 문서에 `artifactId`와 `revision`을 부여한다.

**AI에 요청을 보낼 때:**

1. 편집기의 미저장 변경을 확정한다.
2. 저장된 문서 버전과 선택 위치를 기록한다.
3. 해당 버전의 내용 또는 접근 가능한 작업 사본을 AI에 전달한다.
4. AI 응답에 기준 버전을 연결한다.
5. 적용 시 현재 버전과 비교한다.

AI 실행 중 사용자가 수정하면 기존 실행이 새 내용을 자동으로 읽었다고 간주하지 않는다. 이전 버전 기준 제안은 자동 적용하지 않고 차이를 확인하거나 최신 버전으로 다시 요청한다.

- 검토 세션은 고정된 버전을 읽는다.
- 같은 문서에 대한 활성 쓰기는 한 주체만 수행한다.
- AI의 파일 수정은 관리되는 작업 사본에서 수행하고 적용 시 검증한다.
- 파일 감시만으로 덮어쓰기 충돌을 해결했다고 간주하지 않는다.
- 미리보기에도 원본 버전을 연결한다. 늦게 도착한 이전 미리보기가 최신 화면을 덮지 않는다.
- 적용 취소는 새 버전을 만드는 방식으로 남기며 사용자의 후속 편집을 지우지 않는다.

### 3.4 포맷별 v1 범위

| 포맷 | v1 제공 범위 | 제한 |
|---|---|---|
| Markdown | 원문 편집·미리보기·선택 영역 AI 수정 | YAML 키·값 형태, 링크, 기존 본문을 불필요하게 재작성하지 않음 |
| HWPX | 기존 HOP 편집 기능 연결, 저장, 선택 문단 AI 제안 | AI 제안은 우선 균일 서식의 단일 본문 문단 범위로 제한 |
| HWP | 기존 검증된 경로로 읽기 | 최종 편집 산출물은 HWPX |
| PDF | 열람, 텍스트·영역 선택, 페이지 회전·삭제 후 새 파일 저장 | PDFCraft에서 실제 명령·저장 결과를 확인한 기능만 공개 |
| HTML | 실제 렌더링, 확대, 화면 폭 전환, 수정 요청 | 생성 이미지로 실제 렌더링을 대체하지 않음 |

HWPX의 첫 AI 편집 계약은 기존 HOP 계약에 맞춰 **4,000 Unicode scalar 이하의 단일 균일 서식 문단**으로 시작한다. 혼합 서식·필드·개체·새 문단 생성 등 지원하지 않는 선택은 이유를 표시한다. 편집기 자체의 기능과 AI 자동 수정 범위를 구분한다.

HTML 미리보기에는 앱의 파일 접근·인증 권한을 주지 않는다. 한글 입력기의 조합 중 Enter가 메시지를 전송하거나 문서를 확정하지 않도록 처리한다.

### 3.5 Achmage 지식 연결

Workbench는 기존 Achmage를 대체하는 새 지식 저장소를 만들지 않는다.

- **Human Vault:** 원문과 사용자의 판단.
- **LLM Wiki:** 연결된 지식과 재개 맥락.
- **Achmage OS:** 승인된 방법·스킬.
- **Research:** 근거·실험·실패와 정확한 리비전.
- **Git 저장소:** 실제 구현 코드.

작업별로 연결된 자료와 이번 요청에서 실제 사용한 자료를 구분한다. 참조 근거는 기본적으로 접어두고 필요할 때 펼친다.

GUI의 폴더 이동·파일 열기·저장·세션 대상 선택은 결정적 코드로 처리한다. 이를 위해 매번 LLM을 호출하지 않는다. MCP 호출 자체를 일률적인 유료 호출로 계산하지 않으며, 내부에서 모델을 호출한 경우를 별도로 기록한다.

원본 Vault의 태그·YAML·링크·본문은 색인이나 화면 표시의 부작용으로 변경하지 않는다. Achmage 내부 DB를 직접 수정하지 않는다.

### 3.6 실행 수명과 설정

- 창 닫기는 기본적으로 트레이로 이동하며 진행 중 작업을 유지한다.
- 완전 종료 시 실행 중 작업이 있다면 중단 여부를 명시적으로 처리한다.
- 앱 강제 종료 후 살아남은 프로세스가 있다고 가정하지 않는다. 확인된 상태에서 재개한다.
- 탭을 닫는 것과 작업을 중단하는 것을 구분한다.
- 폴더·즐겨찾기·글꼴·화면 밀도·본문 폭·단축키·기본 엔진을 사용자 설정으로 보존한다.
- SQLite와 인증정보는 로컬에 보관한다. Dropbox에는 공유가 허용된 문서와 결과만 둔다.

## 4. 구현 순서와 합격 기준

### 단계 A — 설치형 기반과 실제 엔진 연결

- 관리되는 새 작업 공간에 Workbench 저장소를 만든다.
- 기존 Achmage·HOP·PDFCraft 저장소를 이동하거나 덮어쓰지 않는다.
- 재사용할 코드의 버전과 라이선스를 고정한다.
- Windows·Linux Tauri 패키지에서 UI·게이트웨이 연결을 확인한다.
- Claude·Codex 각각 로그인 → 대화 → 승인 → 중단 → 재개를 실제로 검증한다.
- 동일 작업에서 두 엔진의 탭을 번갈아 사용한다.

**합격:** 두 OS 설치 앱에서 두 엔진의 실제 세션이 작동한다. 모의 응답이나 브라우저 전용 실행은 대체 증거가 아니다.

### 단계 B — 문서 편집에서 검토까지

- 네 포맷의 파일 카드를 대화에 표시한다.
- 같은 중앙 영역에서 열고 대화로 돌아온다.
- Markdown·HWPX 직접 편집과 AI 제안을 연결한다.
- PDF 제한 편집과 HTML 실제 미리보기를 연결한다.
- 문서 버전을 다른 세션에 전달하고 현재 작업에서 결과를 받는다.

**대표 합격 시나리오:**

> Claude가 강의 초안을 만든다 → 사용자가 HWPX 문단을 직접 수정한다 → Codex에 현재 버전의 검토를 요청한다 → 사용자가 다시 수정한다 → Codex의 이전 버전 제안은 자동 적용되지 않는다 → 최신 버전을 기준으로 검토를 이어간다.

### 단계 C — 일상 사용 완성

- 중첩 폴더·검색·최근 작업을 구현한다.
- Achmage 참조와 근거 표시를 연결한다.
- 재연결·중복 요청 방지·앱 재시작 복구를 검증한다.
- 한글 입력·키보드 이동·스크롤 복귀·저장 상태를 다듬는다.
- 설정을 보존하는 업그레이드 경로를 검증한다.
- 설치 용량과 전체 메모리를 보고한다.

### 필수 테스트

| 상황 | 기대 결과 |
|---|---|
| 한글 조합 중 Enter | 메시지 오발송 및 편집 확정 없음 |
| 수정 직후 AI 요청 | 확정된 최신 버전을 읽음 |
| AI 실행 중 직접 수정 | 오래된 제안의 자동 덮어쓰기 없음 |
| 저장 실패 | 저장 완료로 표시하지 않고 편집 내용을 보존 |
| 외부 파일 변경 | 충돌을 표시하고 원본과 사용자 변경을 보존 |
| 네트워크·이벤트 연결 재개 | 동일 요청과 답변이 중복되지 않음 |
| Claude에서 Codex로 전환 | 필요한 문서·요청 범위를 명시적으로 전달 |
| 앱 재시작 | 작업·폴더·문서·확인된 세션 상태 복구 |
| HTML에서 앱 권한 접근 시도 | 호스트 파일·인증정보에 접근 불가 |
| 지원하지 않는 HWPX 선택 | 제한을 표시하고 원문 유지 |
| Linux 설치 및 렌더링 | 실제 Linux에서 한글·WASM·파일 열기 검증 |

### 성능 목표

다음 수치는 **측정 결과가 아니라 설계 목표**다.

- 기본 UI 전송량: 문서 엔진·글꼴을 제외한 gzip 기준 2MB 이하.
- 유휴 UI+게이트웨이: 모든 WebView 하위 프로세스를 포함해 300MB 이하 목표.
- 문서 엔진은 해당 문서를 열 때 지연 로드한다.
- 무거운 렌더링은 기본 동시 실행 1개.
- 기본 실행 동시성은 작성 1개·검토 1개.
- 미리보기 캐시는 기본 500MB이며 원본·미저장 내용을 삭제하지 않는다.

UI, 게이트웨이, CLI, Achmage, 문서 엔진의 사용량과 **전체 합계**를 모두 보고한다. Tauri라는 이유만으로 경량이라고 결론내리지 않는다. 설치 파일도 런타임·CLI·문서 엔진·글꼴·선택 도구를 나눠 실제 용량을 기록한다.

목표를 넘으면 원인과 조정을 보고한다. 경량화를 이유로 사용자가 고른 설치형 앱을 브라우저 앱으로 조용히 바꾸지 않는다.

## 5. 모바일 확장과 Claude Code 인계 지침

### 모바일 후속 설계

PC v1의 문서·작업·이벤트 계약을 재사용하는 반응형 웹 클라이언트를 만든다.

- 첫 연결은 **Tailscale 사설 연결 + Workbench 기기 승인**을 기본으로 한다.
- Hermes는 모바일 연결의 필수 구성 요소로 사용하지 않는다.
- iPhone에 Claude·Codex 자격증명을 복사하지 않는다.
- 승인된 기기에서만 연구실 호스트의 작업을 열고 제어한다.
- 미리보기는 원본에서 실제 렌더링하며 원본 버전을 함께 표시한다.
- PDF는 페이지 열람·영역 선택, HTML은 실제 화면, HWPX는 읽기용 렌더링과 문단 선택을 우선 제공한다.
- 모바일의 긴 문서 정밀 편집보다 **열람 → 위치 선택 → 수정 요청 → 변경 확인**을 먼저 완성한다.
- 다른 기기에서의 재개는 저장된 문서·근거·작업 상태를 전달한 새로운 실행으로 처리한다.

목표는 Dropbox로 파일을 옮기거나 별도 앱을 설치하고 스크린샷을 다시 요청하는 왕복을 없애는 것이다.

### 인계 자료

이 PRD와 함께 다음 자료를 전달한다.

- 위 PC 시안 5장과 이미지 manifest. 휴대 가능한 패키지에서는 `assets/ui/`에 복사하고 상대 경로로 연결한다.
- [통합기술설계 v5](<./design/통합기술설계-v5.md>).
- 정확한 기술 조사 기준: **R007**, `research:rr-c4b5961b9256ae582e257e97ef4c3ef6:4be68deef8338e7d3c0184ee4785b2fc87b5fc612d912065fa287954eaffd430`.

충돌 시 **이번 PRD의 PC 우선·Tauri 설치형 우선 결정**을 적용한다. 이전의 다중 패널 중심 설계는 UI 기준으로 사용하지 않는다.

### Claude Code가 지켜야 할 구현 원칙

1. 현재 환경의 `AGENTS.md`와 Achmage 작업 문맥을 확인하고 기존 자산을 읽는다.
2. 새 Workbench를 관리되는 별도 작업 공간에서 구현한다.
3. UI 목업 완성보다 **실제 세션 → 문서 수정 → 정확한 버전 전달 → 검토 결과 복귀**를 먼저 관통한다.
4. 공식 인증 흐름과 지원 프로토콜을 사용한다. 엔진이나 인증을 임의로 재구현하지 않는다.
5. HOP·PDFCraft의 README 기능 목록을 검증 완료로 간주하지 않는다. 실제 사용한 기능을 테스트한다.
6. 각 단계에서 구현됨·실제 검증됨·미검증을 구분해 기록한다.
7. Linux 환경을 확보하지 못했다면 Windows 결과로 Linux 완료를 선언하지 않는다.
8. 사용자의 비공개 글꼴·인증정보·라이브 DB를 배포 패키지에 넣지 않는다.
9. 구현 중 추가되는 기능은 단일 작업 화면과 하나의 입력창 원칙을 유지한다.
10. 최종 인계에는 설치 파일, 실행 방법, 검증 결과, 메모리·용량 측정, 남은 제한을 포함한다.

**v1 완료 정의:** 사용자가 Windows 또는 Linux 설치 앱에서 Claude와 Codex를 오가며 문서를 직접 고치고 검토받는 실제 작업을 끝낼 수 있고, 그 과정에서 파일을 다시 첨부하거나 수정 내용을 다시 설명할 필요가 없어야 한다.
